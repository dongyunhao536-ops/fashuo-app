本契约约束 `ask-pc`、`coach-pc`、`cuoti-fupan`、`daibei-pc`、`lunshu-pc`、`yingyu-pc`。业务真相仍落原账本；本状态机只回答“本轮用了哪个 Skill、关键步骤是否真实执行、在哪里被阻断、启动耗时多少”。

## 一、启动与唯一 Run

- 每个稳定业务单元只建立一个 `SR-...`。**系统替用户选下一步**（规划、派题、跨科排序）时由 `skill-context` 或 `english-growth start` 建 Run 并记录 `context_loaded`；**用户已给出题目、对象、章节、篇目或作答**时，直接用 `skill-run start` 建轻量 Run，随后只执行该路径真正需要的证据、题面和写回步骤。不得为了取得 `context_loaded` 而读取与当前目标无关的全账本。自背进度**当天**的顺手抽查不建 Run（2026-08-25 云拍板，见第三节）；只有**跨日**冷复检才另建 `kind=recall` 的稳定单元，那不属于重复建 Run。<!-- [gpt] 2026-08-21；[claude] 2026-08-25 当日抽查改无 Run -->
- 同一会话内重跑快照必须传原 `--run <SR-ID>`；`cuoti` 的答后重规划还要传真实 `--signal`。不得为同一会话反复新建 Run 来掩盖漏步。
- 中断恢复、Guard 续跑或用户下一轮作答会产生新 turn。此时必须由宿主把当前 prompt 的 `expectedRunId` 明确绑定到原 Run，执行层才允许跨 turn 续写；仅 session 相同不足以复用，既避免恢复死锁，也禁止拿任意旧 Run 冒名补签。<!-- [gpt] 2026-08-13 -->
- `--no-track` 只供测试和人工诊断；正常 Skill 运行禁用。Run 遥测只保存步骤名、时间、短证据引用和草稿 hash，不保存题干、答案、密钥或教材原文。

## 二、自动回执不可口头补签

以下步骤只能由对应脚本成功回执写入，`skill-run step/checkpoint/end` 均拒绝手工声明：

- `context_loaded`、`replanned`：`skill-context` / `english-growth start`。前者只属于需要个性化选择或规划的阶段，不是直接答题、指定对象复检、指定章节带背、指定主观题/英语篇目的通用许可证；<!-- [gpt] 2026-08-13 -->
- `progress_recorded`：仅由 `coach.mjs log --run` 在 `daibei-pc kind=progress|progress-only`、同科同章、`activity=背诵` 且 `raw` 保留真实的 `[背诵方式=自背|带背]`、共享账本同步成功后自动落证；点名章节实际带背使用 `--activity 带背`，自背汇报使用 `--activity 自背`，两者均规范为同一背诵活动。`--auto-run daibei-progress` 仍仅用于自背汇报。进度回执不等于用户通过抽查，也不得签成 `result_recorded`。<!-- [gpt] 2026-08-28：修复真实带背被自背专用校验误拒，不改变活动分类。 -->
- `materials_checked`：默认由 `cuoti.mjs material|material-batch --run <SR-ID>` 自动回执；包括 `ask-pc` 在内均不得手工签。**仅 `daibei-pc` 的现役母版非选择题**可由 `question-integrity.mjs --template-entry <完整条目键> --run <SR-ID>` 在同一调用中替代：加载器必须验证母版状态、`《考试分析》+页码+行号` 锚点、A0 与 Run 科目，并把模板 hash 绑定到回执；缺任一项即拒绝、退回本节一次 `material-batch`。普通材料回执仍按独立信源轴带真实命中数（`q:N|kaoshi:N|jiangyi:N|xinde:N|yixiao:N|zhenti:N`），是 `ask-pc/preflight_checked` 的唯一推导来源；母版回执不得用于 ask 判权。<!-- [gpt] 2026-08-12｜[claude] 2026-08-25 补命中数｜[gpt] 2026-08-26 带背母版快路径 -->
- `preflight_checked`：只能由 `ask.mjs preflight --run <SR-ID> --category <科目/章节/题型>` 自动落证。证据各项一律从上条回执推导，执行者只能提供第 1 项归类与第 6 项法律更新；**判权只认《考试分析》／讲义／真题三条互相独立的轴**，≥2 轴实锤才判"正常作答"，仅一轴挂"依据偏单一"，零轴直接拒签，除非显式 `--discussion-only` 承认这是讨论性回答。考试分析零命中而讲义有命中时自动挂口径警告。**不得再用 `--done preflight_checked` 补签**，CLI 会拒绝。<!-- [claude] 2026-08-25：原先它只是白名单里的字符串，无脚本产出也无校验，实测中被在未读定义的情况下自签。 -->
- `question_integrity_pass`：法硕复检题及主观题自拟题用 `question-integrity.mjs ... --run <SR-ID>`，BLOCK 记录 fail，只有同一草稿复跑 PASS 才能覆盖；英语阅读使用真题网页，不把整篇题面和答案传给该 Gate，改由手工核对的 `source_checked + reading_page_verified` 证明净卷、素排和无前置导读；
- `reference_answer_checked/grading_bound`：`lunshu-pc` 只能由 `reference-answer.mjs --run <SR-ID>` 真实加载参考答案后，以同一 `referenceHash` 自动落证；加载器未完整扫描、来源不可用或同一 Run 试图换 hash 时直接拒绝。英语写作的用户指定标答仍按原手工证据路径，不与本自动绑定混用；
- `judgment_output_verified`：错题判分只能由 `judgment-result.mjs check --run <SR-ID>` 对结构化结果校验后落证；回执绑定证据卡 hash、T#、判定结果与 diagnosis。`cuoti.mjs review --run` 在进入 outbox 前逐项核对，pending 的确定性病根表述、卡片与写回漂移均直接 BLOCK。<!-- [gpt] 2026-08-13 -->
- `result_recorded/writeback_verified` 只能由接入 Run 的业务 CLI 在真实写回成功后自动落证，模型和 `skill-run step/end --done` 均不得手工补签；当前已接 `cuoti.mjs review --run`、`ask.mjs verify --run`、主观题/英语统一尝试 `coach.mjs log --run`。带背刻意拆开：`daibei-ledger.mjs evidence --run` 只签本地 `result_recorded`，`cuoti.mjs sync --run --operation` 查到同一 `ingest_operation=applied` 才签 `writeback_verified`。英语阅读必须先由 `english-growth.mjs grade-reading` 真实读本地答案键，再由 `verify-ledger` 核本场台账；主观题必须由 `subjective-profile.mjs verify` 唯一核本场记录。尚无专用业务回执的路径保持 BLOCK，不能用口头“已经记录”冒充闭环。<!-- [gpt] 2026-08-12 -->
- `cuoti.mjs record-batch --run <SR-ID>` 是新错题 intake 的唯一批量写回桥：它在同一 outbox 批次生成一条进度和 N 条错题、同步成功后自动签 `result_recorded/writeback_verified`；operation ID 稳定，重跑不得制造重复流水。<!-- [gpt] 2026-08-13 -->
- 新错题入口直接用 `skill-run.mjs start --skill cuoti-fupan --kind intake` 建立轻量 Run；普通 cuoti 快照只用于系统替用户选择老题或跨科重规划。历史任务回放可用 `verify-batch` 核验已存在的唯一批次并签回执，但不得重复落账。<!-- [gpt] 2026-08-13 -->

## 三、阶段硬闸

`execution.phases` 或 `skill-run status` 是本 Skill 当前可用阶段及必做步骤的机器事实源。阶段区分“需要上下文选任务”和“目标已知直接执行”；禁止绕过证据步骤，也禁止把 plan 的上下文要求复制到所有路径。<!-- [gpt] 2026-08-13 -->

- 准备展示题目：运行 `skill-run checkpoint --phase question`；使用命题 Gate 的题目必须同时传其返回的 `--hash <QUESTION_DRAFT_SHA256>`，确保放行的仍是同一展示草稿；可把 `target_frozen/source_checked/...` 等手工核验用 `--done` 一次提交，但只要含手工步骤就必须带 `--ref <可核对短引用>`。缺任一步、缺 ref 或 hash 不同均以退出码 2 阻断，题目不得展示。英语真题网页不走文本 Gate，因其 question 阶段不要求 hash。<!-- [gpt] 2026-08-12 -->
- 完整答案、规划、判分或写回收口：运行 `skill-run end --phase <answer|plan|grading|result> --done ... --ref <可核对短引用>`。缺步骤或缺引用时退出码为 2，先补真实动作再重跑。<!-- [gpt] 2026-08-12 -->
- `daibei-pc/progress` 只要求 `target_frozen + progress_recorded + writeback_verified + response_verified`，禁止 `context_loaded`；`kind=recall` 禁止按 plan 降级收口。普通 progress 结束后**抽查照做但不再建 Run**（见下条）；`post_progress_probe_missing` 这条 Stop 闸已于 2026-08-25 整条删除。用户明确“不抽查”时仍用 `kind=progress-only`。<!-- [gpt] 2026-08-21；[claude] 2026-08-25 删除抽查 Run 要求 -->
- **`kind=recall` 必须在 start 就定出写回路线，定不出直接阻断**（`DAIBEI_RESULT_ROUTE_REQUIRED`）。路线由 `--target` 的语法决定，两套语法互不重叠：KP-ID（`LS-0012`）→ `knowledge`，唯一带背挂账条目 ID（`L12`/`X15`/`S6`/`M1`）→ `ledger`。**给章节名一类自由文本只能换成真实 ID，补 `--result-route` 救不回来**——它校验目标类型、不放宽目标要求，声明与目标类型不符同样阻断（`DAIBEI_ROUTE_TARGET_MISMATCH`）。`--result-route` 的用处是目标里同时含两类 ID 时指定走哪条，以及显式复核推断结果。**现役 `kind=recall` 只接受可写回 ID，没有例外**；当日拿稳定文本设问抽查的场景直接走状态机之外的 stateless probe（下一条），不再用 `recall-sameday` 兜。**这是类型校验不是命名启发式**——只看"像不像 KP-ID"会误伤合法的挂账复检，又挡不住拿假 KP 串走错路线。事故依据：2026-08-25 一个 recall Run 的 target 冻成章节级，跑完材料、Gate、出题、判分才在写回炸掉，整条链返工；闸装在末端等于没装。<!-- [claude] 2026-08-25 -->
- **进度当天的顺手抽查是无 Run 的 stateless probe（2026-08-25 云拍板）**：不建 Run、不 checkpoint、不 end、不写四个账本中的任何一个。一个不产生学习事实的动作没有需要审计的对象，为它维持一整套空账本 Run 生命周期不划算。**但内容正确性闸不砍**——`question-integrity` 只查题干泄题、不核验答案键对错（2026-08-25《法经》第三篇《网法》被写成《囚法》即由此漏出），所以答案来源可靠时跑一次无 `--run` 的 `question-integrity`（第一题 1 次调用），来源不可靠时先 `material`／`material-batch` 再跑 Gate（第一题 2 次调用）。跨日冷复检、专项复检仍走 `kind=recall` + `--phase result`，照常落账。
- ⚠️ `kind=recall-sameday` 与 `phase=probe` **已降为 legacy**：仅供历史 Run 回放兼容，新流程不得调用。作为防御性兜底，这类 Run 上的 `knowledge.mjs attempt` 与 `daibei-ledger.mjs evidence` 两条写回路仍会被 `DAIBEI_SAMEDAY_PROBE_NO_WRITEBACK` 拒绝，`probe` 与 `recall-sameday` 的双向锁也保留。
- 题目已经安全展示、正在等用户作答时，Run 保持 `waiting_user`，不必伪造 completed。用户明确中止记 `--outcome aborted`；路由到另一个 Skill 必须 `--outcome handoff --to <目标Skill> --reason <可核对原因>`，随后立即启动目标 Run。同一会话存在未收口 Run 时禁止另建；监控把“已 handoff 但目标 Run 未启动”列为断链。<!-- [gpt] 2026-08-12 -->
- `waiting_user` 按最后一条 Run 事件计时；连续 30 分钟没有新事件时，由系统回收器跨宿主写入 `aborted/system` 终态。该终态只关闭 Run 生命周期，**不得记用户 fail、不得替用户确认错因、不得补写或改写学习事实**。用户 30 分钟后回来要继续当前题目时，新建 Run 重新冻结当前对象。回收器在下一次 Skill 启动、Run 状态/监控检查或显式 `skill-run reap` 时执行；它不放宽普通业务步骤的 session/turn 身份闸。<!-- [gpt] 2026-08-26 -->
- 新错题讲解等待用户认领错因时使用 `cuoti-fupan/intake_question` 检查点。它只证明批次已写回、材料已核与当前事件已冻结，不是复检题，不要求命题 Gate；全部新错讲完后以 `cuoti-fupan/intake` 正常完成，不得记成 `aborted`。<!-- [gpt] 2026-08-13 -->
- 旧错复检 partial/fail 且病根 pending 时使用 `cuoti-fupan/diagnosis_question`，并传判题卡 hash。用户认领后由 `classify --run` 写 `diagnosis_recorded`，重新生成 confirmed/rejected 卡，才允许 result 收口；不得把 pending 卡改写成确定性诊断。<!-- [gpt] 2026-08-13 -->
- 宿主把每条 assistant commentary 视作一次 Stop 审计边界；短于 60 秒的新错题 intake 工具链不得在启动、写回和材料批检之间插入阶段性 commentary，否则未收口 Run 会被保护性中止。<!-- [gpt] 2026-08-13 实跑修正 -->

## 四、手工步骤必须有可核对对象

- `target_frozen/priority_checked`：证据引用写原排期 ID、T#/事件号、带背条目 ID 或选题编号。
- `source_checked/answer_key_checked` 以及英语写作的 `reference_answer_checked`：写文件/题号/采分表短引用，不复制答案正文；lunshu 的参考答案不属于手工步骤，见第二节加载器回执。
- `question_integrity_pass` 只证明展示题面没有偷塞答案；ask/coach/cuoti 在运行 Gate 前必须已由材料命令自动落 `materials_checked`，daibei 还可在同一 Gate 调用中用上条现役母版加载器自动落证；lunshu 必须已有同 hash 的 `reference_answer_checked + grading_bound`，英语作文仍手工留 `reference_answer_checked`。普通 Gate 不能替代知识证据；带背母版快路径之所以可合并，是因为加载器先验证并绑定了考试分析母版而不是口头声明。<!-- [gpt] 2026-08-24；[gpt] 2026-08-26 -->
- `rubric_applied/response_verified`：只在真实完成采分表逐块比对或末尾一致性复核后签；不得开场预签。<!-- [claude] 2026-08-25：preflight_checked 已移出本节，改由脚本自动落证，见第二节。 -->
- `result_recorded/writeback_verified`：只有原业务 CLI/台账写入及必要同步成功后签；等待用户作答的题目阶段不能提前签。

## 五、监控与回放

- Codex 宿主守卫位于 `.codex/hooks.json`：`UserPromptSubmit` 只对明确触发词注入本轮 Skill 约束，`Stop` 将同一 `session_id/turn_id` 与 Run 对账；无 Run 或未收口时最多自动续跑一次，第二次仍失败只告警并落账，避免死循环。路由日志只存 prompt hash/长度，不存原文。新建或修改 hook 后必须在新任务里用 `/hooks` 审阅并信任，否则监控会显示“宿主覆盖未观测”。<!-- [gpt] 2026-08-12 -->
- `node scripts/skill-run.mjs check --days 2` 查看运行完成率、过期未收口、Gate 阻断和启动 p50/p95。
- `node scripts/skill-run.mjs reap --idle-minutes 30` 可单独触发超时等待回收；`start/status/check` 已自动执行同一回收逻辑。<!-- [gpt] 2026-08-26 -->
- `learning-flow-monitor` 同时消费 Run 与宿主 hook 日志；无 Run 不再被解释为“Skill 一切正常”，并能区分守卫未启用、慢启动、Gate 保护性阻断与真正漏收口。<!-- [gpt] 2026-08-12 -->
- `npm run skill:replay` 固化回放近期四类事故：文字瑕疵机械判错、宏观 P0 锁科、题面泄答案、T# 前缀/P0 对象串账。修 Skill 或状态机后必须跑。
