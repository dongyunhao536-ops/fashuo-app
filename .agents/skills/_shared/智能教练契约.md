# 智能教练数据契约

智能教练层只从既有事实源**派生决策视图**，不新建可变的“掌握状态真相”。入口：

```powershell
node --env-file=.env.local scripts/coach-engine.mjs snapshot
node --env-file=.env.local scripts/coach-engine.mjs dispatch --limit 3        # 预览
node --env-file=.env.local scripts/coach-engine.mjs dispatch --limit 3 --write # 写唯一排期账
```

快照写入 `.local/coach-engine-snapshot.json`，也内嵌于 `.local/assessment-snapshot.json` 的 `coachEngine`。两者都是可重算缓存，不是新的学习事实源。

## 主题/带背七阶段状态机

`发现 → 确认 → 强化 → 短期通过 → 冷却观察 → 稳定 → 长期保持`

- 发现：主题尚未确认分类；确认：已分类但尚无合格冷检。
- 强化：最近一次冷检 `partial/fail`，或旧通过后又出现新的 open 事件。
- 短期通过：刚出现一次合格迁移通过；冷却观察：已有合格迁移，等待下一间隔复检。
- **错题主题稳定门槛（[gpt] 2026-08-10）**：最近失败后至少两个不同北京日的 `clean + cold + application + L3+` 通过，跨度不少于 7 天、至少两个结构化验证轴且至少一次 L4 陌生/综合案例；长期保持还需第三个合格日期并进入低频轮换。自由文本 angle 改写不等于换轴，旧裸 pass 最多兼容 monitoring。
- 同日订正、提示后通过、原题复现、规则复述、teach-back 和作废题都不升级。任何新失败或复发都允许降级。
- 数据库的事件状态、主题 mastery 状态和带背挂账状态仍按各自契约写；七阶段状态是跨轴派生视图，不直接回写这些字段。

## 知识点多维状态机 v3（[gpt] 2026-08-10）

- 独立于上面的主题生命周期，知识点阶段为 `未接触 → 已接触（理解待证）→ 理解 → 能复述 → 能应用 → 稳定`；由四维表现证据 `exposure/understanding/recall/application` 每次重算，不设可手改 mastery 真相。快照必须同时保留历史 `demonstratedStage` 与截至参考日的当前 `stage`，不得把半年前会过直接写成今天会。
- 提示后通过不升级，作废题不计，新的 partial/fail 会使对应维度回退。稳定要求最近失败后兼具 recall/application 两维干净冷检、至少两个日期且跨度不少于 7 天。
- `examReadiness` 与稳定分轴：只有当前仍稳定，且最近失败后至少两个日期出现 `application + clean + cold + L4` 陌生/综合题通过、其中至少一次在 `timed/full_mock` 环境并记录时长，才标考试就绪。稳定但缺考场证据只能写“稳定、尚未考试就绪”。<!-- [gpt] 2026-08-10 -->
- `sprintLane` 是临考期对重要/高风险知识点的独立调度标记，不是第七个掌握阶段；稳定知识点也可能进入冲刺，未稳定知识点也不会因“冲刺”被伪装成熟练。
- Anki 只参与目录别名、教材来源、覆盖线索和重要度排序；`exact/section` 均为材料关系，`masteryImpact=none`。

## 遗忘与风险

- 每一维都从最近一次有效 `clean pass` 派生 `fresh / due / decayed`、下次复检日与当前阶段；提示通过不建立衰减基线，未来日期证据不提前生效，历史证据不删除。
- 有“clean pass → 后来 partial/fail”的个人样本时，按实际间隔中位数估计半衰期；反复跨日冷通过可提供成功间隔下界。没有个人样本时使用各维默认半衰期并标低置信，单次冷通过只建立基线，不虚增长期稳定性。
- `retentionIndex`、`riskScore / dropRisk / readinessIndex` 都是 0–100 **调度分**，用于队列排序，不是遗忘概率、能力百分比或卷面分。
- **风险分去饱和（2026-08-07）**：候选分数先做科内归一化（同科内按相对位置拉开、科内第一最高），再叠“新错加权 +8（最近 3 天有新 open 事件）”与“积压限流 −6（该科候选 >6 个）”；今日队列每科最多 `ceil(limit/2)` 件、保证跨科。`rawScore` 保留在快照供审计。
- 背诵输出 `topDropRisk` 前 20 项；不能再只按“最久未碰”机械抽题。最终选择仍需结合当天章节、周报 P0/P1 与用户状态。
- 科目风险结合量化 v3、学习新鲜度、复发主题和高风险背诵点。风险排序本身永远不是概率；完整同口径成套模考 `N<3` 时 `canProjectScore=false`，`N=3~5` 只准趋势分数区间，`N≥6` 才准目标达成概率，仍禁止直接输出上岸率。<!-- [gpt] 2026-08-10 -->

## 知识图谱与考试失分前瞻

- `knowledge_relation` 保存 `prerequisite / supports / contrast`。只有来源为 manual/curated/textbook、带证据锚且状态为 confirmed 的 prerequisite 会参与阻塞；pending/model/catalog 候选只供审核。数据库和 CLI 都拒绝自环与 confirmed 前置环。<!-- [gpt] 2026-08-10 -->
- 前置关系还记录目标所需阶段（理解/复述/应用/稳定）。目标到期但前置不足时，派单先重定向到最深链上的根前置，并保留 `prerequisiteFor/path` 供审计；图谱只改顺序，不改知识状态。
- `examForecast.lossRiskIndex` 用当前衰减、近 28 天结构化复检供给、考点重要度、已确认前置缺口与活跃栽点，对**已激活知识点**做考试日失分压力排序；它不是丢分概率。未激活的高重要度目录点单列为 `coverageBlindSpots`，只叫观测盲区，不判不会。
- 预测采用三级硬闸：`N<3` 为 `structural-only`，不给卷面分；`N=3~5` 为 `trend-band`，只给经验趋势区间；`N≥6` 才为 `probability-eligible`，用 `ols-normal-v1` 给“该科卷面分达到目标线”的百分比、概率区间与低/中/高信心。所有等级都用科目真实满分作上限，不用目标分截断趋势。<!-- [gpt] 2026-08-10 -->
- 百分比必须自动写入 `.local/概率预测台账.md`，同一“目标事件 + 模型 + 模考证据日期集合”幂等。目标日后写 outcome 0/1 与实际分，回测 Brier、偏差、可靠性分桶；已对账 `N<10` 只收集，10~29 仅初步观察，`N≥30` 才允许审查模型偏差。普通判断台账的 hit rate 不得替代概率校准。<!-- [gpt] 2026-08-10 -->

## 目标执行控制器（[gpt] 2026-08-10）

- 控制器不另存可手改状态，只从 `.local/复盘排期.md` 中带完整 `plan_id/plan_week/plan_source/weight` 的验收单元重算周 P0 严格兑现率；完成日期晚于该周周日不算该周完成。
- `normal`：每日最多新增 3 件，允许 P2；`constrained`：连续两周 P0 `<60%` 或当前至少两个 P0 逾期，冻结 P2、P1 每周最多 1 件、每日最多新增 2 件；`rescue`：连续三周 P0 `<60%` 或里程碑红灯，只新增 P0、每日最多 1 件；`recovery`：一次低周后连续两周 `≥80%` 且无 P0 逾期，继续冻结 P2观察。
- 自动降级降的是并发和次优先级，不是 P0 验收标准；已到期维护义务继续占位。战略目标、目标分和轮次死线只能在评估/里程碑中明确复核后改变。

## 自动派单

<!-- [gpt] 2026-08-10：自动派单补齐执行 skill 与检验维度，日报不再猜路由。 -->
- 自动派单只处理**已被真实证据或确认映射激活的知识对象**（既有错题主题、带背挂账、答疑卡点和知识证据），不从全目录凭空创造新章节目标、不改周报优先级。
- 每次最多 3 件、P0 最多 1 件、优先跨科；候选与分数透明保存在快照。
- `dispatch` 默认只预览；只有 `--write` 才写 `.local/复盘排期.md` 的结构化区。每条自动排期都携带 `route + dimension`，写入前后用同一解析器校验：
  - `ask-pc / understanding`：先讲清规则、理由与边界；
  - `daibei-pc / recall`：闭卷复述骨架和限定条件；
  - `cuoti-fupan / application`：换事实做涵摄或错题冷复检。
- 知识阶段决定下一跳：`unseen/exposed → ask-pc`，`understanding → daibei-pc`，`recall → cuoti-fupan`；进入 application 后，根据稳定性证据缺的是 recall 还是 application 定向补，不把“都学过”当稳定。
- **错题下一探针（[gpt] 2026-08-10）**：主题状态同时携带 `nextProbe`，错题候选携带同一份 `reviewProbe`，明确变式、迁移等级、验证轴、最早冷却日和命题 guardrails。处方只使用 confirmed 栽点；自动到期日取遗忘模型到期日与探针最早日中较晚者，未到冷却日不得提前连考。它是确定性证据缺口处方，不是现成题目、掌握概率或风险预测。
- 画像只在两个范围影响任务：已确认的知识点级画像可定向该点；科目级画像只有跨至少 2 点、累计至少 3 次 confirmed 失败后才可影响其他知识点。pending 或单次个案只能设计验证题，不能改写全科派单。
- 同一知识对象已有未完成结构化排期时幂等跳过；完成仍用 `schedule.mjs done` 回写。日报只消费排期，不把派单视为已学习或已掌握。
- 派单还必须服从 `controller.policy`：`constrained/recovery` 不新增 P2，`rescue` 只新增 P0；但不得删除既有 P0、降低验收标准或把已到期维护任务静默丢掉。<!-- [gpt] 2026-08-10 -->
- **复检结果一致性回写（2026-08-07；[gpt] 2026-08-10 修订）**：错题复检用 `cuoti.mjs review ... --schedule <排期id>`；答疑理解检验用 `ask.mjs verify ... --schedule <排期id>`；两者都只在远端证据同步成功后回写本地排期，其中答疑卡点仅在 `clean pass` 后变成 `clarified`。带背复检先用 `daibei-ledger.mjs evidence` 留真实表现；若同时联动排期与撤池/重挂，则用 `schedule.mjs done ... --recite ... --event ... --evidence "..." --outcome pass|partial|fail --cold ... --prompt ... [--pattern ... --diagnosis ...]` 一次写入证据、状态与排期。命令先预校验两个事实源，进程内任一写入失败即恢复两份原文。跨 Supabase/本地文件或两个文件系统的操作不得宣称数据库级原子事务；出现中断时按命令提示修复，不得把半完成状态当作完成。

## 错因画像与教练校准

- **[gpt] 2026-08-10**：错因画像由错题关系、知识点表现证据和稳定知识点 ID 动态重算，不另存一个可人工修改的“个人画像真相”。待认领栽点只叫候选；单个确认失败只叫个案；跨至少 2 个知识点、累计 3 次确认失败才称习惯性。
- 栽点退役只认失败后的两个不同北京日定向干净冷检，跨度至少 7 天；同场订正、提示后通过或污染题干均不能凑退役证据。
- `judgment-ledger.mjs calibration` 按科目报告栽点预测兑现率。每科 N<5 只继续积累样本；N≥5 后只调整教练诊断置信和候选宽度，不自动改变学生掌握状态，也不在题干中泄露预测。
- 画像中的样本分布、预测兑现率及所有风险分都是派生审计信息，不是掌握概率、卷面分或上岸率。
- 同一种“栽点模式 → route/dimension”仍保留为粗策略层；具体效果比较必须下钻到受控 `protocol@version`，不能把同一 skill 内的不同教法混成一种。风险变化只是伴随信号，不能宣称因果治愈。<!-- [gpt] -->

## 干预响应闭环（[gpt] 2026-08-10）

- 自动派出的定向病根任务必须在同一条结构化排期中固化 `subject/kp/pattern/pattern_scope/intervention/episode/protocol/protocol_version/window/baseline_risk/expect`；它们记录“当时为什么派、具体怎么教”，不能事后按结果改写。`intervention` 是粗策略键，`protocol` 才是可比较教法。<!-- [gpt] -->
- 首条 `window=immediate` 结案时写真实 `episode_start`。执行 skill 必须连同 `outcome=pass|partial|fail|void`、`cold=true|false`、`prompt=clean|cued|invalid` 回写；只打完成勾、自由文本“会了”或提示后通过均不能进入效果样本。
- immediate 干净通过后，排期只生成一条最早 D3；D3 干净冷通过才生成 D14，D14 通过才生成 D30。延迟窗口不得提前结案，且除作废题外必须 `cold=true + prompt=clean`。任一窗口 partial/fail 立即停止旧 episode，不继续机械铺后续窗口。
- 带背条目在 immediate 通过后可撤池；后续 D3/D14/D30 通过用 `schedule.mjs done ... --event observe` 只追加证据、不反复迁移状态，失败才按原契约 `rehang`。
- `interventionResponse.items` 保留“栽点 × route × dimension”粗策略审计；`interventionResponse.protocols` 按“科目 × 栽点 × protocol@version”以 episode 为单位比较。N<3 或未跨至少 2 个知识点只标 `collecting`；长期窗口样本足够后才可标 `supported/mixed/needs-redesign`。
- `supported` 必须由 D14/D30 的跨点结果支持：至少 3 个可评估 episode、覆盖至少 2 个知识点，长期 clean cold pass 率不低于 67%，且至少 2 个知识点通过。即时或 D3 高响应只能继续 collecting，不能提前晋级。
- 选策先让兼容协议各留个人样本；出现长期 supported 后默认 80% 利用、20% 确认性探索，防止旧优势永久固化。`needs-redesign` 在有安全替代时不再重复，但它只表示当前协议响应低，不等于病根被证伪或学生学不会。
- 所有协议响应仍是单人观察性证据，不替代知识点稳定或栽点退役门槛；`baseline_risk → 当前风险` 的变化不得宣称由本次干预造成。
