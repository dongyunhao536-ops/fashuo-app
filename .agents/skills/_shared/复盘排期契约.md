# 复盘排期数据契约

- 唯一事实源仍是 `.local/复盘排期.md`；结构化行与旧历史散文在同一文件，不另建第二本账。
<!-- [gpt] 2026-08-10：结构化排期增加 owner route 与知识检验 dimension。 -->
- 新排期必须运行：`node scripts/schedule.mjs add --date YYYY-MM-DD --priority P0|P1|P2 --type <类型> --task "<可判定验收>" [--route <skill> --dimension <维度> --ref <题号/主题/处方>] [--plan <稳定计划ID> --week <周一YYYY-MM-DD> --source weekly|assessment|milestone|coach --weight 1-5 --goal <目标ID>]`。`route/dimension` 必须成对出现；自动派单必须写，人工宏观排期可暂缺。<!-- [gpt] 2026-08-10 -->
- 周报、月度评估、里程碑和教练正式处方的每个可验收单元必须完整写 `plan/week/source/weight`；四字段缺一即结构错误，`date` 必须落在 `week` 的周一至周日。重跑报告必须复用稳定 `--id` 与 `--plan`，不能随机生成重复承诺。`goal` 可选，只作目标追踪，不改变优先级。<!-- [gpt] 2026-08-10 -->
- 一条排期就是一个可独立判定的验收单元；普通原子项 `weight=1`。复杂事项优先拆成多条，只有确实不可拆且验收价值明显更高时才用 2~5，禁止为触发或逃避控制器而调权重。<!-- [gpt] 2026-08-10 -->
<!-- [gpt] 2026-08-10：历史 canonical 行只能通过受校验命令补路由，禁止凭任务文字批量猜测。 -->
- 旧结构化行需要补齐执行归属时，运行 `node scripts/schedule.mjs route <ID> --route <skill> --dimension exposure|understanding|recall|application`。只在 owner 与检验维度可唯一核验时回填；混合推进、行政收尾等含糊项继续保持 `unrouted`。该命令只改调度元数据并保留 `ref/completed/result`，不会生成掌握证据。
- 当前知识任务的固定对应为 `ask-pc/understanding`、`daibei-pc/recall`、`cuoti-fupan/application`。它们只决定执行入口和本次取证维度，不等于掌握状态。
- 完成后必须运行：`node scripts/schedule.mjs done <ID> --result "<结果与证据>"`。若条目验收终态要求“通过”，未过就保留未完成；若条目明确要求“完成一次冷检”，可把本次 `partial/fail` 作为该次检验结果结案，但知识状态保持未过并由引擎继续派下一次，禁止把“检验已做”写成“知识已掌握”。
- [gpt] 带背排期需要同步撤池/重挂时，用 `done <ID> --recite <条目ID> --event withdraw|rehang|observe --evidence "<教材/题目锚点>" --outcome pass|partial|fail --cold true|false --prompt clean|cued [--pattern <code> --diagnosis pending|confirmed]`；命令会在同一进程事务里写 `recite-evidence-v2`、必要的迁移状态和排期结案。`withdraw` 只接受干净冷检 pass，`rehang` 只接受 partial/fail；协议化 D3/D14/D30 通过用 `observe`，只追加证据不反复撤池。
- 读取行动队列运行：`node scripts/schedule.mjs summary [--today YYYY-MM-DD]`；写回后运行 `check`。
- 预测复检可先运行 `node --env-file=.env.local scripts/coach-engine.mjs dispatch --limit 3` 预览；确认后加 `--write`。它只把既有错题/带背复检义务写入本文件，并按知识对象幂等去重。
- `coach-engine` 每次从本文件重算控制器，不另写模式账：连续两周 P0 严格兑现率 `<60%` 进入 `constrained`，连续三周低于 60% 或里程碑红灯进入 `rescue`，一次低周后连续两周 `≥80%` 且无 P0 逾期进入 `recovery`。降级只冻结/限流 P1/P2 与每日新增数，保留 P0 验收标准和已到期维护义务。<!-- [gpt] 2026-08-10 -->
<!-- [gpt] 2026-08-10：定向病根排期新增事前基线与事后结构化响应字段。 -->
- 定向病根的自动排期会附带 `subject/kp/pattern/pattern_scope/intervention/episode/protocol/protocol_version/window/baseline_risk/expect`；结案后的 `outcome/cold/prompt` 必须来自真实检验。旧条目继续兼容粗策略观察，但缺少 episode/protocol 的历史行不参与具体教法比较。<!-- [gpt] -->
- 这些字段共同构成干预审计链，禁止事后按结果改写事前病根或风险基线；风险前后变化只能称伴随变化，不能称因果效果。
- 协议化 immediate 通过后由同一结案函数串行生成 D3→D14→D30；后一个窗口只在前一个窗口干净通过后出现。延迟窗口是“最早可检日”，不得提前，除 void 外只能按无提示冷检结案；失败/半对停止本 episode，等待教练改协议。
- 旧散文里的“验收”只作历史证据候选。由于后文可能另有回写，日报、周报、评估不得把它直接算作当前逾期；需要继续执行的旧项先迁成结构化行。
- 一条结构化行只写一个可验收终态；中间动作不单开假任务。任务文字中的 `|` 会转成 `／`，ID 全局唯一。自动行以 `route/dimension` 指定 owner，以 `episode/protocol/window` 指定纵向干预；日报按结构化字段转手，不再从中文 type 猜 skill。
