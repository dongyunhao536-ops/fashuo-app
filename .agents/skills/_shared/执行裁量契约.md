# 执行裁量契约

<!-- [gpt] 2026-08-12：把跨 skill 的裁量层级、文字瑕疵与动态重规划收成单一事实源。 -->

本契约约束 `coach-pc` 与 `cuoti-fupan` 的会话决策。业务细则没有明确写成“硬门槛”时，不得覆盖这里的裁量顺序。

## 一、决策层级

1. 用户本轮真实意图与会话目标。
2. 事实真实性、证据门槛、数据完整性和不可伪造状态。
3. 周 P0/P1、到期排期与风险排序。
4. 默认题量、默认科目、推荐顺序和表达格式。

高层可改写低层。周报中的宏观 P0 是必须兼顾的优先项，不是锁科指令；但已经落入唯一排期且今日到期或逾期的具体 P0，是不能被同科其他动作冲抵的验收单。用户明确说暂缓/改期时可暂停该硬闸，但原排期保持 open 并明确记为未完成，未经真实目标证据不得结案。默认题量是起点，不是停手条件。用户说“继续”“量太少”“换一科”时，先重新判断目标与边际收益，不能机械复读旧计划。<!-- [gpt] 2026-08-12 -->

## 二、命题完整性前置 Gate

<!-- [gpt] 2026-08-12：把答案污染从“事后注意”改成所有复检题展示前的硬闸门。 -->

任何执行 Skill 生成复检题时，先把**题干、附加要求、提示语、题型、教练侧答案键、用户原错答案**组成完整草稿，再运行启动快照 `questionIntegrity.command`（等价于 `node scripts/question-integrity.mjs check ...`）。只有输出 `QUESTION_INTEGRITY_PASS` 的同一份草稿可以展示；改过一个字也要重新运行。`coach-pc` 直出或转交 `cuoti-fupan`、`ask-pc`、`daibei-pc` 都不能绕过。

- 选择题必须显式以 `【单选题】` 或 `【多选题】` 开头；所有题均须向 Gate 提供只在教练侧使用的 `--answer`（选择题为答案键，非选择题为参考答案）。有原错答案时同时提供 `--original-answer`。
- Gate 阻断直接或间接暴露正确项、错误项、正确项数量、答案结构、原错答案以及决定答案的显著标记。`“选正确项，并指出③④错在哪里”` 属于点名错误项，必须 BLOCK。普通 `“请选择，并简述判断依据”` 应放行。
- clean 复检的 `--hints` 必须为空。需要提示时退出 clean 复检流程，先教学，之后另出一份重新过 Gate 的无提示题。
- BLOCK 后只能重写并复跑；`--rewrite` 产物只是候选，不是通行证。BLOCK 草稿不展示、不落判断预测、不进入用户作答与有效题量。
- Gate 是展示前硬校验，不能用下节“文字瑕疵不影响答案”绕过；下节只处理已经展示后才发现的一般错字与歧义。

若展示后才发现污染：立即停止判分；已有判断预测用 `judgment-ledger.mjs resolve <id> void`；只写 `review <T#> void --variant invalid --invalid-prompt ... --note "题面污染；responsibility=teacher"` 审计。不得写 `fail`、`add`、`recheck-fail` 或用户病根；该记录不计有效题量、不改用户错误、不推进冷却、不关闭原排期。重写后重新过 Gate，再让用户作答。

## 三、文字瑕疵的实质性判断

题面或作答有错别字、漏字、口语化表达时，只问四件事：是否改变正确答案、核心争点、关键推理链，或已经妨碍理解。

- 四项均否：只做一句澄清；不判错、不扣分、不作废、不因此重复出题。
- 任一为是：说明它改变了哪个判断变量，修正后重答；坏题面记 `void`，不得形成掌握证据。
- 边界不清：优先按用户最合理的完整意思理解，再用依据核验；不要以文字洁癖代替法理判断。

## 四、会话目标函数

每次动作优先最大化“真实闭环收益”，不是机械完成同一科题数。候选动作按以下信息综合比较：

- 先冻结今日到期或逾期、带稳定对象 ID 的具体 P0 验收单；同科其他动作、普通候选高分和“本周已有动作”均不能冲抵。缺稳定对象时 BLOCK 并修数据链，不猜测；未来 P0 不提前冻结。<!-- [gpt] 2026-08-12 -->

- 事件是否已达销账门槛，或再通过一次即可销账；
- 是否到期、逾期、复发或属于周 P0；
- 下一探针今天是否已过冷却日；
- 当前科是否已经完成本场最小有效动作；
- 同科连续训练的边际收益是否已下降；
- 用户当前精力与明确加量/切换指令。

出题前先看事件级 proof。当天新错和未到冷却日项目只能讲解、归类或排期，不为凑量连考。

## 五、动态重规划

出现以下任一信号，当前选题计划立即失效，必须重跑跨科候选池后再决定下一题：

- `pass`、`partial`、`fail`、`absorbed` 或 `new-error`；
- 用户说“继续”“量太少”“换科”或表达相同意思；
- 同科已连续做 2 题；
- 当科本场最小有效动作已经完成；
- 新发现可立即销账或一次通过即可销账的其他科项目。

重跑命令：

```powershell
node --env-file=.env.local scripts/skill-context.mjs cuoti [聚焦科目] --current-subject <当前科目> --subject-streak <连续题数> --signal <continue|too-little|switch|pass|partial|fail|absorbed|new-error> [--focus-minimum-met]
```

`[聚焦科目]` 只是开场偏好；跨科候选池始终保留。完成最小动作后加 `--focus-minimum-met`，当前科会降权而非永久退出。

## 六、状态边界

- “事件销账”与“主题 stable”永远分开陈述。
- 同场第二角度可以在事件级门槛允许时形成补充证据；它不能伪装成跨日冷检，也不能单独证明主题 stable。
- 记录、判分与销账必须使用真实发生的证据；裁量只改变下一步怎么选，不降低证据门槛。

## 七、最小输出

每题判完只需交代：结论、关键依据、是否形成有效证据、事件能否销账、下一步为何留在本题或切到别科。不要把内部规则全文念给用户。
