# 学习系统共享事实层

这份契约回答一个问题：同一件学习事实应该写到哪里、上游报告该怎样解释。所有 PC Skill 共用，不在各自规则里复制第二套口径。

## 事实轴

| 一次真实做错 | `study_error` | 长期弱项主题、背诵卡壳 |

## 错题的两条状态轴

- 事件状态：`open / absorbed / dismissed`。`absorbed` 只表示这一次错题达到销账门槛；`dismissed` 表示确认不应作为错题。
- 主题状态：`open / monitoring / stable / archived`。同一主题可关联多次事件，一次事件也可有一个 primary 和多个 related 主题。
- 任何报告必须分别写“本期销账多少事件”和“多少主题获得冷复检、进入 monitoring/stable”。禁止把销账事件数表述成解决弱项数。
- 主题至少在两个不同北京日通过，且期间没有更新的 `partial/fail`，才进入 `stable`；任何新 `partial/fail` 立即回 `open`。
- 病根只有用户认领后才写 `diagnosis_status=confirmed`；教练推断保持 `pending`。`unclassified` 不是“粗心”，只是尚未认领。
- `dismissed` 不进待归类池、不进训练优先级，但保留审计。英语错题由 `yingyu-pc` 复检，不交给法硕错题 Skill。

## 知识点证据与关系状态轴 v3（[gpt] 2026-08-10）

- 稳定知识点 ID 来自现有目录；`demonstratedStage` 保留历史最高可证明阶段，`stage` 表示截至参考日仍可依赖的当前阶段。两者都由证据重算，不再读取 `kp_state` 的旧 L1/L2/L3/mastered 字段。
- 证据分 `exposure / understanding / recall / application` 四维。干净通过才推进；提示后通过不推进，作废题不计，后续 partial/fail 可降级。
- “稳定”须在最近失败之后同时具有 recall 与 application 的干净冷检通过，至少两个不同北京日、跨度不少于 7 天。“冲刺”只是一条考前调度通道，不覆盖阶段。
- **稳定不等于考试就绪**：考试就绪还须最近失败后至少两个不同日期的 `application + clean + cold + L4` 陌生/综合题通过，且至少一次来自 `timed/full_mock` 并记录时长。L1 原题、L2 复述、L3 反事实可推进一般能力证据，但不能单独证明考场迁移。<!-- [gpt] 2026-08-10 -->
- 历史通过不会因时间经过被删除；系统只把相应维度从 `fresh → due → decayed` 派生降级。`retentionIndex` 是复检调度指数，不是记忆概率；没有个人间隔样本时必须标低置信默认值。
- `knowledge_relation` 只保存经审核关系。只有有锚点的 `confirmed prerequisite` 会阻塞后续点并改变学习顺序；pending、model/catalog 候选、supports/contrast 均不阻塞，也绝不改变掌握阶段。前置图禁止自环与循环依赖。
- Anki 的标题、章节、星级/P1、真题频次和 `note_id` 只用于材料别名、来源、重要度与覆盖参考。`exact` 也不是掌握证据，`section` 更不能当精确知识点命中。
- 栽点画像与知识阶段都由表现证据重算；`pending` 诊断不能写成稳定个人特征。科目级习惯至少要跨 2 个知识点、累计 3 次 confirmed 失败；退役须失败后两个不同日期的定向干净冷检通过且跨度至少 7 天。

## 写入纪律

<!-- [gpt] 2026-08-10：答疑与知识证据正式接线，禁止先销疑后补证据。 -->
- 做题、复盘、考核中真实答错：默认当场按“事件 + 主题”结构入账，用户可当场否决。纯概念提问或随口讨论：只有用户明确要求才记。
- 新事件先查是否命中已有 T#主题或属于旧账复发；复发用 `--recur-of`，不要靠长文本相似度猜。
- 所有运行态写操作先入可靠 outbox，随后立即同步；成功前不说“已入库”。每个操作由 `ingest_operation` 持久记录 `operation_id + payload_sha256 + handler_version + result/error`，相同 ID 改 payload 必须硬失败，成功重放不得重复写业务事实。大批量迁移先 `--stage`，再 `sync --dry`，确认后正式同步。<!-- [gpt] 2026-08-10：持久摄取审计 -->
- 每次真实作答、复检或考核都应写一条 `learning_attempt`；英语/主观题首稿由带显式 attempt 元数据的 `coach.mjs log` 同源生成，错题/答疑/带背复检由既有写入链自动派生，通用入口为 `knowledge.mjs attempt`。非 `manual` 必须有稳定 `source_id`；客观/主观作答必须同时有稳定题号与 `score/max_score`。历史 `accuracy`、散文批语和当前台账状态一律不回填。<!-- [gpt] 2026-08-10 -->
- 学习记录日期取用户汇报当时的北京日；不追问实际发生在零点前还是零点后，不擅自回填历史日期。
- 答疑卡点带稳定 `kp_id` 时，同时写 confirmed 对象映射和 `understanding=partial|fail` 缺口证据；真正打通只能走 `ask.mjs verify`。固定顺序是“映射 → understanding 证据 → clean pass 才 clarified”，提示后通过、无效题面和同步失败都不能销疑。
- 带背每次真实检验用 `daibei-ledger.mjs evidence` 或排期联动结案写 `dimension/result/cold/prompt/failurePattern/diagnosis`；两者都以 `recite-evidence-v2.operationId` 暂存同号 `learning_attempt(role=recheck)`，随后必须 `cuoti.mjs sync`。已确认 `recite_ledger → kp_id` 映射再实时派生知识点证据；不得为同一次作答手写第二条 evidence/attempt。<!-- [gpt] 2026-08-10 -->
- 知识点阶段只从有效知识表现证据重算（DB `knowledge_evidence` + 经 confirmed 映射实时派生的带背证据）；`route/dimension` 说明“交给谁、检验哪一维”，`protocol/episode/window` 说明“本次采用哪种教法、在何时观察”，都不是新的掌握事实。<!-- [gpt] -->
- 错题或知识表现若来自限时/成套模考，必须同时写 `variant_kind/transfer_level/assessment_context/duration_seconds`；`timed/full_mock` 缺时长即为坏证据。旧证据保留兼容，但不能被补猜成 L4 或限时证据。<!-- [gpt] 2026-08-10 -->
- 新增知识关系必须记录两端 `kp_id`、关系类型、所需阶段、来源与证据锚；模型只能提交 pending 候选，不能自行确认。confirmed 前置写入前必须查环。<!-- [gpt] -->
- <!-- [gpt] 2026-08-10：对象映射覆盖审计。 -->用 `knowledge.mjs mapping-audit` 分轴检查错题主题、错题事件、答疑卡点和带背条目的唯一主点；`suggest-*` 只读候选不自动确认，`backfill-direct --apply` 也只能迁移来源表已经存在的合法稳定 `kp_id`。强文本匹配不是事实。

## 上游读取纪律

- 教练、日报、周报、评估优先读 `error_book_v2` 的主题聚合；需要还原当时误答时再读 `study_error.knowledge/raw_input`。
- 带背存量、最久未碰和已撤池统一读 `node scripts/daibei-ledger.mjs summary`；不要解析超长标题或手数 `###`。当前存量不是本周新挂/撤账流量。
- 带背本期新挂/撤池/重挂/移交统一读 `daibei-ledger.mjs flow --from ... --to ...`；只认同一 Markdown 内的 append-only 迁移流水，不能从当前状态倒推历史。
- 带背表现与栽点模式统一读同一账本的 `recite-evidence-v2`；旧自然语言复检只作兼容回退。报告必须区分 pending 候选、confirmed 个案、跨点习惯与 retired，不得从一次漏项写出“经常漏项”。
- 复盘排期的行动队列只认 `schedule.mjs` 写入的结构化行；自动排期的 `route/dimension` 与 `protocol/episode/window` 原样交给下游 skill。周报、评估、里程碑的每个可验收单元还必须带完整 `plan_id/plan_week/plan_source/weight`，否则控制器不把它算进 P0/P1/P2 兑现率。下游必须按任务中的协议执行并结构化结案，旧散文保留作历史证据，不再让报告猜“后来是否已完成”或该交给谁。<!-- [gpt] -->
- 月度/阶段评估先运行 `node --env-file=.env.local scripts/assessment.mjs`，量化 v3、数据库事实轴与本地台账同一次快照；不得另抄公式或手数台账。
- 教练、错题、带背、日报、周报和评估需要决定“接下来复检谁”时，运行 `coach-engine.mjs snapshot` 读同日派生视图；先补未满足的 confirmed 根前置，再处理被阻塞目标。风险分、衰减指数和失分压力只排序，不冒充概率、卷面分或事实状态。
- 失分前瞻只给已被证据激活的知识点排序；目录中未激活的高重要度点只能称“观测盲区”，不能称不会。预测分三档：完整同口径成套模考 `N<3` 只报结构风险，`N=3~5` 只报分数趋势区间，`N≥6` 才可报带概率区间、信心、模型版本和证据日期的目标达成概率。每个新证据版本自动落 `.local/概率预测台账.md`，结果发生后用 0/1 对账和 Brier 分数校准；禁止把 `lossRiskIndex` 换算成概率。<!-- [gpt] 2026-08-10 -->
- 学习控制器只从带计划归属的排期重算：连续两周 P0 严格兑现率 `<60%` 进入 `constrained`（冻结 P2、P1 每周最多 1 件）；连续三周低于 60% 或里程碑红灯进入 `rescue`（只新增 P0）；一次低周后连续两周 `≥80%` 且无 P0 逾期才进入 `recovery`。模式只降负载，不降低既定 P0 验收标准，也不擅改战略目标。<!-- [gpt] 2026-08-10 -->
- 答疑卡点只读 `ask_point_v2.active=true`；TTL 过期不是掌握。报告只能称“新增卡点/打通卡点”，不能把 `ask_summary` 行数叫答疑次数。
- <!-- [gpt] 2026-08-10：个人知识上下文是可重算读模型，不新增事实轴。 -->答疑的个人关联统一读 `knowledge.mjs context <KP-ID...>`：先独立完成教材裁判，再用近 30 个北京日的 confirmed 关系与真实表现调整讲解。两次只称疑似、跨至少 2 个 KP 的 3 次 confirmed 失败才称反复；pending 具体病根不得写成用户特征。共享 `supports` 父点的纯结构两跳不召回旁系旧错；上下文为空不制造关联，查询失败不推成“没有历史”，输出本身绝不回写任何账。
- 报“活跃主题”＝仍有关联 `open` 事件；报“待冷检主题”＝事件已销账但主题仍为 `open/monitoring`；两者不能合并成一个数字。
- 数据查询报错时中止，不用 `null ?? []` 输出一份全零报告。工具查不到只能写“未查到”，不能推成“没有发生”。
- 量化 v3 是趋势仪表，不是卷面分；主题层用于解释复发和闭环，不直接擅改 v3 公式或跨版本比较指数。

## 跨功能流向

`ask-pc / coach-pc / daibei-pc` 暴露真实问题 → 分流到正确事实轴 → `cuoti-fupan` 负责题目级复检与事件销账 → `coach.mjs ledger` 汇总主题账 → `ribao-pc` 盯日执行 → `weekly-pc` 盯周标准与冷检证据 → `pinggu-pc` 做全周期目标反推。
