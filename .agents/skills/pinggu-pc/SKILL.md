# PC 备考评估（升级版 · 火力全开 · 全周期体检）

采集前先读 `../_shared/学习事实层.md`、`../_shared/智能教练契约.md`、`../_shared/报告展示契约.md` 与本目录 `数据契约.md`。评估必须把错题事件闭环率与长期主题掌握率分成两条指标，避免把销账速度误判成能力稳定。<!-- [gpt] 2026-08-10 -->

给云（在职·五战·目标北大 375+）做的**阶段性全面体检**：现在站在哪、离目标多远、照当前斜率外推能不能到、最大的窟窿在哪、接下来怎么办。区别于 weekly-pc 的周切面——这里看**全周期**，且必须**目标反推**（从 375+ 倒着算回来），不是顺着流水账夸进度。

## 数据采集（先跑齐再下笔，零编造）
0. **单一事实快照**：`node --env-file=.env.local scripts/assessment.mjs`。先读 `.local/assessment-snapshot.json`；所有数字以这次同日快照为准，任一必需源失败就停，不拼一份半新半旧报告。七阶段状态、知识点 `examReadiness`、带背掉落风险、科目风险排序、预测分层、概率回测与学习控制器读其中 `coachEngine/probabilityForecasts`；这是派生决策视图，不另算一套。<!-- [gpt] 2026-08-10 -->
1. **全账本**：`node --env-file=.env.local scripts/coach.mjs ledger`（距考天数/轮次/进度/错题/长期记忆/对话）。
2. **量化 v3（与 APP 今日页同一算法）**：直接读快照 `quantV3`。APP 与 PC 共用 `src/lib/quant-v3.mjs`；禁止再用 `npx tsx` 临时跑另一份或另编分。算法解释见 `src/lib/dashboard.ts` 头注释。
   - ⛔ **口径断点：v3.0 与 v3.1 的分不可比（2026-07-31 立·与关口体检同一道闸）**。**7-09（指数 12）、7-13（指数 10）两份评估、以及 7-13 定的「7-31 指数应上 20」里程碑，全是 v3.0 口径**；7-26 v3.1 改了两处（深度分母 已覆盖章→总章、闭环从加分项改乘法折扣），同一份账本在 v3.1 下会低一大截。**开篇审计历史里程碑时，只许比"轮次进度、章数、出账/撤账数、处方执行率"这些实数，不许拿指数直接减、也不许拿今天的 v3.1 分去对 v3.0 定下的指数线判达标与否**——否则会得出"学了一个月反倒掉分"的假结论。真要纵向比指数，就用 v3.1 重算那天的分再比，或明写"该线因口径变更作废"。
   - 📌 **报指数必带三条已知失真**（清单原文在 `src/lib/dashboard.ts` 头注「已知失真清单」）：①**章级粒度双向偏**——触到一章即记满，章内再深耕对广度＝0（法制史的百分比是偏高不是偏低）；②**综合指数两侧不同尺**——英语 1 篇 ≈ 综合 +4，一整晚啃已覆盖章 ≈ +0.06，**指数对英语过敏、对已覆盖章加深近乎失明**，英语破零那几天的指数跳升别读成整体水平上台阶；③**诚实税 ≈ 综合 3 分**——登记未销账错题在 absorbed>0 时确实掉分，公式故意不改。**别让他拿指数当唯一方向盘。**
3. **投入与吸收趋势**：`node --env-file=.env.local scripts/weekly.mjs data --week <周一>` 逐周跑近 3~4 周（每跑一次读走 `.local/weekly-data.json` 再跑下一周）——看学习动作数、复盘数、吸收数是升是降。
4. **错题本全量**：先 `node --env-file=.env.local scripts/cuoti.mjs topics`（活跃主题、待冷检主题、monitoring/stable、同主题累计事件），再 `cuoti.mjs list` 还原 open 事件和原始栽点。报告分别给事件轴与主题轴，不能只报一组“错题数”。
5. **带背挂账台账（量化 v3 闭环维不含它，评估必须单独盯）**：运行 `node scripts/daibei-ledger.mjs summary` → 报当前 active/可复检/Anki/移交、科目分布、最老未碰与已撤池候选；按需读对应 ID 正文。当前状态不能倒推出本期流量；只有本期日期迁移证据足够时才报本期新挂/撤账数。
   **答疑卡点轴**：`coach.mjs ledger` 已读 `ask_point_v2` 有效 open；另用 `node --env-file=.env.local scripts/ask.mjs list --all --json` 审计 clarified/dismissed/superseded/expired。只报新增卡点与打通数，不把卡点行数写成答疑次数，也不把 expired 当掌握。
6. **日报执行与控制器**：读快照 `dailyExecution` 和 `coachEngine.controller`。严格完成率只认 ✅，⚠️ 单列；据 `gaps` 与最新日块审计断链，不手数 Markdown。constrained/rescue 只说明系统已降负载，不可用来粉饰 P0 未兑现。<!-- [gpt] 2026-08-10 -->
7. **主观题**：读快照 `subjective` 的练笔量、首稿/重写水位、挂病灶与最近练笔。案例或论述任一类型少于 3 道时，只报样本风险，禁止把小样本硬乘成 180 分卷面。
8. **复盘排期**：读快照 `reviewSchedule`；行动队列只认结构化行。处方用 `schedule.mjs add` 写回，完成用 `done`，旧散文不直接算逾期。
9. **基准**：`config/coach.json`（**「目标分」＝目标反推的唯一事实源**、轮次表/死线/红线：9月底模拟 320——**分数看「模拟分记录」字段**、同弱项 3 次转专题、「里程碑.已完成」里上一关口的结论）+ `docs/方法论/00_总纲`（阶段应达标什么）。⚠️ 周时长红线 2026-07-17 云拍板**不记录不监控**（"时长不好记"）——**别再把"无时长数据"当数据盲区点名**，投入趋势用学习动作数/打卡数代理。

## 评估展示框架（结论→差距→变化→风险→处方→证据）
1. `## 先看结论`：绿=按线走 / 黄=偏航可救 / 红=再不动就来不及；同屏给 controller、最关键目标缺口和预测层级，最多 3 个决定性数字。<!-- [gpt] 2026-08-10 -->
2. `## 目标差距`：用一张紧凑表列“科目 / 当前可靠证据 / 目标或底线 / 缺口 / 下一动作”。没有完整模考时“当前估分”写不可校准，不用四维冒充分数。英语与主观题仍必须单列，但只保留会改变目标判断的数字；完整四维移到证据附录。<!-- [gpt] 2026-08-10 -->
3. `## 趋势变化`：相对上一份只写最多 3 个改善、3 个恶化；进度审计与病根追踪合并到这里，不重放全量现状。当前轮次应到 vs 实到、启动晚/从不复盘/重复犯老错仍必须有真实证据。<!-- [gpt] 2026-08-10 -->
4. `## 主要风险`：最多 3 条，每条固定写“触发 → 后果 → 最小动作”；首次模考、单科底线或错题复发只有真正进入前三才进首屏，其余进附录。<!-- [gpt] 2026-08-10 -->
5. `## 行动处方`：3~5 件，P0≤2；每件用 `[P0]/[P1]/[P2] + 日期/时段 + 数字验收 + 理由`，并落排期。<!-- [gpt] 2026-08-10 -->
6. `## 证据附录`：综合指数、各科四维、错题事件轴/主题轴、投入趋势、英语、主观题、日报执行、数据异常与来源。附录用表格/短句，不重复前五节结论。<!-- [gpt] 2026-08-10 -->

### 目标反推口径（扣 `config/coach.json`「目标分」，2026-07-31 定档后不许再自编拆法）
   - **378 ＝ 政治 65 + 英语 75 + 专业基础 115（刑 62 / 民 53）+ 综合 123（法理 50 / 宪法 40 / 法制史 33）**。逐科给「目标分 vs 照当前水位估分 vs 缺口」，别只给总分。**民法 53/75 是刻意压低的、不是失误**（打法＝追覆盖与客观题不追精通）；**宪法 40/50、法制史 33/40 反按 80%+ 要求**（纯记忆型、全盘性价比最高）；**刑法 62/75 ＝ 守成不加码**。
   - **单科硬底线优先于总分**：专业基础 ≥90、综合 ≥90（北大四年没变过）、政英各 ≥55。**先判这四条过没过，再谈 375**——7-22 体检估基础卷仅 65-70，离 90 差 20-25 分。
   - **主观题占比校准（新增·必做）**：两卷主观题合计 180 分＝60%，其中基础卷 30 分案例（定性错一步整题崩）、综合卷 30 分论述（踩点给分）。拿采集步骤 7 的真实练笔得分水位去乘，算出"照现在的笔头，180 分能拿多少"，再看 115/123 还成不成立。**客观题四维再好看也补不上这一块。**
   - **英语 75 的硬条件**：若到 9-26 模考仍近乎零流水，目标**自动降回 72 并按 72 重排时间**——评估必须明确判定这条触发没触发（看近 14 天精刷篇数、作文语料 ✅ 数），别让 75 挂着当装饰。
   - **复试口径（2026 起改面试 + 权重 50%，1 复试分 ≈ 5 初试分）**：375 的作用是**安全垫、不是加权优势**；旧 70/30 公式已作废别再引。结论落在"资源投补短板保上线，不在强科刷边际"。
   - 对照 9 月底模拟 320 红线按当前斜率外推够不够、缺口多大。**「模拟分记录」为空就如实说"无法校准，9-26 必须模一次"**，别用四维分冒充卷面分。预测硬闸：完整同口径模考 `N<3` 只报结构风险，`N=3~5` 只报趋势区间，`N≥6` 才报科目目标达成概率及区间；不得从五科概率拼“上岸率”。百分比必须能在 `.local/概率预测台账.md` 找到模型和证据版本，并同时报告已对账 N 与 Brier。<!-- [gpt] 2026-08-10 -->
风险与处方仍以 `coachEngine.examRisk/examForecast` 的可解释排序作一个输入，再结合死线、轮次、主观题样本与 `controller` 判断；未跨预测门槛时只许说对应层级，不许输出伪卷面分/胜率。<!-- [gpt] 2026-08-10 -->

## 铁律
- **零编造**：每个数字可溯源到采集步骤；数据缺失（如无模拟分、某科零流水）如实说缺失本身，并把缺失当发现。
  ⚠️ 但 **minutes/accuracy 不算缺失**——它们是量化 v3 **故意排除**的（[[today-quant-v3-beida]]），填充率低是设计结果不是缺陷；云 7-17 已取消时长监控并点名"别再当盲区点名"，别拿它当发现报。
- **北大 375+ 严标准**：该泼冷水就泼（五战了，客气是害他），但差距必须翻译成"每周做掉多少"的可执行斜率，不许只吓唬不给路。
- **别把覆盖当掌握**：广度好看≠能力分高，四维里深度/背诵/闭环才是北大区分度——评估措辞跟着这个理念走。
- **数字不真实当场汇报**（[[report-fake-numbers]]）：读到的指标与现实对不上（覆盖/深度/闭环/能力分/综合指数），当场说清哪个数不对、真值应是多少、根因是记错还是算法有洞、怎么修。**不许拿自己都怀疑的数去下结论。**
- 时间一律按**北京时间**（本机 UTC-7、差 15 小时）：`new Date(Date.now()+8*3600e3).toISOString().slice(0,10)`，别用系统上下文里的日期（[[beijing-time-standard]]）。
- 纯法硕口径 [[fashuo-only-no-fakao]]；对话里给全文，同时存档 `.local/评估/pinggu-YYYY-MM-DD.md`。不写 APP 库（无对应表，要进 APP 展示另立项、需云点头）。
- **"上一份"＝ `.local/评估/` 里最新的一份，不论 `pinggu-*.md` 还是 `里程碑-*天-*.md`（2026-08-01 补·两条线共用一个目录）**。月度评估与关口体检**交叉审计**：开篇既要对上一份月度评估的处方，也要对最近一次关口体检的 P0（如 150 天体检的"民法抢工作日晚、法制史占周末上午"）。只认 `pinggu-*` 会整份跳过关口那几张处方——那恰恰是最要命的几张。
- **处方落地通道（2026-07-17 成文）**：行动处方必须绑进（或对齐）当周周报的 P0/P1 分档，不做孤立清单；下次评估**开篇先审计**上一份的处方执行率 + 到期里程碑逐条对账（执行率这项硬指标**拿 `.local/日报台账.md` 到天对账**，别只凭周报自述）。评估节奏：**每月 1 号定时跑一次**（`monthly-pinggu`，北京 20:00），云中途随时可加做。

## 落账（做完必做——2026-08-01 补·7-13 五张处方四张零执行，其中一张的死因就是"没落到任何地方"）
1. **P0 落排期**：处方里带日期的条目当场用 `node scripts/schedule.mjs add ... --plan <稳定ID> --week <周一> --source assessment --weight 1 [--goal ...]` 写进 `.local/复盘排期.md`；下次审计后用 `done` 回写结果，别只留在报告里。若处方跨多周，每周拆独立验收单元。<!-- [gpt] 2026-08-10 -->
2. **长期记忆**：`node --env-file=.env.local scripts/coach.mjs remember --category 评估 --fact "<月份>月度评估：<结论一句 + 最大缺口>"` → `node --env-file=.env.local scripts/cuoti.mjs sync`。（`--category` 是自由文本原样入库，帮助里那四个只是默认建议；月度一律用「评估」，别混进「里程碑」。）中文长参数走 argv 易乱码、`/` 会被 MSYS 转成路径，改用 UTF-8 临时 node 脚本直写 `.local/cuoti-pending.jsonl` 再 sync 更稳（[[gitbash-slash-mangling]]）。
3. **不写 `config/coach.json`「里程碑.已完成」**——那是关口体检（150/120/100/60/30）专用字段，月度评估往里塞会让 ledger 的关口告警失真。

## 分工
- **weekly-pc**＝周报（本周切面、写 weekly_report 给 APP 展示）；**ribao-pc**＝天粒度"该做没做"（台账回喂本 skill）；**coach-pc**＝日常策略/规划/情绪；**cuoti-fupan**＝错题出题销账；**lunshu-pc**＝主观题训练批改（台账是本 skill 的 60% 卷面数据源）；**yingyu-pc**＝英语。本 skill＝**全周期体检**，产出留 PC 存档。评估里发现的弱项要考核→转 cuoti-fupan；要落到本周安排→转 coach-pc 口径；主观题水位不行→转 lunshu-pc 排练笔。
- **与里程碑关口体检（coach-pc/milestone-checkup.md）的分工（2026-08-01 补·8-01 月度与 8-21 的 120 天关口只隔 20 天，不分清会出两份重复报告）**：**月度＝趋势 + 目标反推 + 处方审计**（看这一个月斜率往哪走、离 378 那张表还差多少）；**关口＝对表死线 + 产能算账 + 定下一段 P0**（剩余小时够不够、砍什么）。数据采集清单两边共用，**落账不同**：关口写 `config/coach.json`「里程碑.已完成」，月度不写（见上「落账」第 3 条）。
