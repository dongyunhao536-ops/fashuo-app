# 评估事实快照契约

- 先运行 `node --env-file=.env.local scripts/assessment.mjs`；固定日期审计用 `--today YYYY-MM-DD`。输出同时写 `.local/assessment-snapshot.json`。
- 快照一次采集量化 v3.1、学习流水、错题事件/主题、冷复检、答疑卡点、带背存量/迁移、日报执行、结构化排期、主观题与目标死线。任一必需数据库查询或台账结构报错时整体失败，不生成全零报告。
- `quantV3` 与 APP 今日页共用 `src/lib/quant-v3.mjs`，禁止在 Skill、报告或临时脚本里复制公式。跨 v3.0/v3.1 仍不可直接比较。
- `dailyExecution.strictExecutionRate` 只把 ✅ 算严格完成，⚠️ 单列，不把“有记录”冒充“已完成”。
- `reviewSchedule.overdue/dueToday/upcoming` 只含 `schedule.mjs` 的结构化行动项；旧散文只在 legacy 计数里显示为数据债。
- `recite.flow30d` 只认同一带背 Markdown 内 append-only 流水；0 表示 0 条可审计迁移，不代表历史上从未迁移。
- `subjective.scores` 是真实样本水位。案例或论述任一类型少于 3 道时，不得把单类小样本线性外推成整张 180 分主观卷；只报样本与风险。
- 快照是事实包，不自动给“胜算”或卷面估分。叙事判断仍由 pinggu-pc 目标反推，并逐条引用快照字段。
