# PC 日报（生态链最底层的执行账 · 每天北京 17:20）

生成前先读 `../_shared/学习事实层.md`。日报必须分别呈现错题事件、活跃主题和待冷检主题，不能把“销账事件”写成“解决弱项”。

云 2026-07-28 定：周报管一周的标准、评估管一个月的体检、里程碑管关口，中间缺了**天**这一格。Supabase 账本只记"做了什么"，永远答不出"**该做没做**"——日报补的就是这个洞，并把日粒度沉进 `.local/日报台账.md` 让上游三层能回读。

## 时机与它决定的口径（先想清楚再动笔）
- **北京 17:20 跑**（本机 UTC-7，机器时间 02:20 同日；一切按北京算 [[beijing-time-standard]]）。云在职：此刻刚下班、晚间大块时段还没开始。
- 所以 **结算写昨天、派单写今晚**：17:20 时"今天"只过了大半天且晚间主战场未开——**【昨日全天】才是完整的一天，今日切面绝不能拿来判勤惰**，写成"今天什么都没干"就是造假。
- **派单窗口＝今晚 + 明早**（到明天 17:20 之前的全部可用时段，正好接上在职双轨的"工作日晚"与"工作日早"两块）。**明天结算时两块分别去两个数据段找**：今晚件看【昨日全天流水】、明早件看【今日截至此刻】——data 输出天然分好了，别混着判。
- **时段冲突就照实说，别硬派**：某件是周报 P0 但处方把它钉在周末上午（如法制史），今晚就不该派它——写进【告警】锁死具体周几几点，并注明"今晚不派是时段不对、不是降级"。派单要尊重双轨与体检处方的时段分配，不是把 P0 无脑塞进今晚。

## 工作流程
1. `node --env-file=.env.local scripts/coach-engine.mjs dispatch --limit 3 --write` —— 先把既有错题/带背的到期复检义务幂等写入唯一排期账；它不能新立章节目标或改周报优先级。再运行 `node --env-file=.env.local scripts/daily.mjs data` 拉事实源（昨日派单 / 昨日全天流水 / 今日切面 / 近14天热力与断档链 / 错题主题+带背挂账+答疑卡点+复盘排期 / 本周周报分档 / 距考与里程碑）。
2. 按需补读（**不是每天都读，有触发才读**）：
   - `node scripts/schedule.mjs summary` —— 昨日/今日有到期验收项、或要派复盘件时读结构化行动队列；旧散文不直接算当前逾期。
   - `node scripts/daibei-ledger.mjs summary` —— `daily.mjs data` 已给结构化带背快照；要派带背/复检件时用这里的最久未碰与已撤池候选，再按需读 `.local/带背挂账.md` 对应 ID 正文。
   - `.local/日报台账.md` 近 3~5 块 —— 要判"这件事连着欠几天了"时读。
   - 数据异常、结算不了、库里数字对不上 → 立刻按 [[report-fake-numbers]] 在日报里点名，别糊过去。
3. 写日报到 `.local/日报草稿.md`（格式见下，四行摘要是硬约束）。
4. `node --env-file=.env.local scripts/daily.mjs save --file .local/日报草稿.md` —— 落 `.local/日报/YYYY-MM-DD.md` + upsert 台账块（同日重跑覆盖不追加；缺【派单】行会直接报错拦下）。
5. **定时跑时**：用 PushNotification 发一条 ≤80 字的推送＝靶心句 + 派单头两件。手动跑时不推，直接在对话里给全文。

## 输出格式（.local/日报草稿.md）
```
# 日报 YYYY-MM-DD（周X）· 距初试 N 天

> 一句话：<≤20 字的靶心结论，打头就说，别铺垫>

## 昨日结算
- **昨日结算**：<X/Y 件 + 逐件 ✅/⚠️/❌ 极简串>
（逐条展开：每件配一句流水证据或"库里无记录"；没派过单就写明是首日/断链）

## 今日切面（截至 17:20，半天）
- **今日流水**：<有什么写什么，空就写"暂无记录">

## 今晚派单
- **派单**：[P0] … ｜ [P1] … ｜ [P2] …
（逐件写清：从哪个时段抢 + **做到什么算完成**——验收标准必须可判定，明天要拿它结算）

## 告警
- **断档**：<连续零流水 N 天 / 某科跳过了它自己的窗口 / 里程碑到点 / 欠账雪球；无则写"无">

> ⚠️ **断档判定必须按【该科当前节奏】定基线，不许一刀切"某科 M 天没碰"**（2026-07-31 云逮到：日报天天报"刑法断了"，而刑法当前只有周三轻滚+周日销账两个窗口，**周一二四五零流水本来就是正常态**——这个告警在设计上注定天天响，狼来了）。
> - **先从 ledger、`config/coach.json`、本周指导和复盘排期判定这科当前归哪种节奏，禁止在 skill 写死“当前名单”**：①**在铺面** → 基线是“每周该进 N 章”，几天没碰可以报；②**守成/双窗口** → 按该科真实窗口判定，只有连续跳过约定窗口才叫断档，非窗口日零流水不报；③**未开张** → 报“从未开张 + 距红线还剩几天”，不报伪精确的断档天数。科目状态变化时以最新账本和用户明确确认为准。
> - **别把"销账没做"写成"这科断了"**——两件事：刑法的**新进度是我方主动停的**（守成 62/75、分则等第 2 轮），刑法的**错题销账没停**（open 44 类里刑法占 25，最多）。混着说会让云以为策略自相矛盾。
> - **派单必须落在该活有窗口的日子**：错题销账类动作只能派到**周三/周日**（或明写"锁 X 日、今晚不派是时段不对"）。2026-07-31 那次在**周五**派 [P0] 刑法 #72/#44 两问式训练——周三已过、周日未到，**这活当天根本没有窗口可落**，属于日报自己打自己。
```
> **🆕 断档的第二种形态：听/看了但没配题（2026-08-03 夜班实证后加）**
> 全量跑过一遍：**21 个有输入（听课/看书）的章里，只有 8 个配了同章做题——13 个章听完就过去了**（刑法 11、民法 2）。而**配上的那 8 个，输入→做题间隔中位 0 天**——所以他不是"配得慢"，是**根本没配的那部分没有任何机制在追**（`docs/方法论/00_总纲` 的"真题第一遍分章配学习进度"这条，时效满分、覆盖只有 38%）。
> - **每天结算时多查一步**：昨日流水里若有 `听课`/`看书` 且带 chapter，**查同科同章有没有 `做题` 记录**（当天或此前皆可）。没有就写进【断档】行：`听而未配：<科>-<章>`。
> - **报了就要能派**：这类缺口正好是"今晚 30 分钟能补上"的活，优先级按它所属科目在周报里的档走，**不新立标准**（守下方铁律）。
> - ⚠️ **38% 是下界不是真值**：chapter 是压缩短标签，同一章存在「第3章」「第三章」「犯罪构成」多种写法，匹配不上就漏算（[[today-quant-v3-beida]] 的同一个坑）。**所以只报"这一章我没查到配题"，别报"你从没配过题"**——查不到不等于没有。

四行 `- **派单**` `- **昨日结算**` `- **今日流水**` `- **断档**` 是脚本抽取台账块的接口，**标签和格式一字不能改**。

## 铁律
- **日报不另立标准**：派单只能派生自 ① 当周周报的 P0/P1（[[weekly-as-week-standard]]：周报＝当周宏观指导标准）② `.local/复盘排期.md` 到期验收项（含智能教练写入的既有旧账复检）③ 欠账池里最该动的一条。**不许自创新目标、不许改周报的优先级**——要改得等周一周报。分档沿用周报的 P0/P1/P2；机器风险分不能越级改宏观标准。
- **派单 ≤3 件**，P0 至多 1 件。他在职，17:20 之后现实只有一个晚间时段；派五件等于没派。
- **落笔前必做的回指自检（2026-07-28 首日即翻车后加·别跳过）**：派单写完，**逐条回到周报原句比一遍**——原句要求的量（几章 / 几条 / 哪几件）有没有被写小。**拆时段可以，减量不行**；一个晚间时段装不下的，把余下那半**写进【告警】锁死具体周几几点 + 注明"移时段不是降级"**，绝不能让它无声消失。
  - 首日实例：周报 P1-3 原句是「补第一章 **再推第三章 自然人**，本周至少 2 章新增」，日报只派了第一章、第三章整个蒸发——**由云当场逮到，不是我自查出来的**。日报把周报的量悄悄改小，是这条天/周链最该防的失效模式（比漏派更隐蔽：派单看起来是满的）。
- **零编造 + 「没记录 ≠ 没做」**：库里为空只能写"无流水记录"并顺口提一句补记，绝不写成"你没学"。但**连续多日空记录本身是发现**，要报出来（是真断档还是只是不记？两种病不同药）。
- **结算要有证据**：判 ✅/❌ 必须贴昨日流水里的具体行（科目·章节·正确率）或明说"库里查无"。不许凭印象判（[[trend-claims-need-data]]）。
- **靶心句前置、一块只准一处加粗**（[[cuoti-one-at-a-time]]）：日报是每天扫一眼的东西，重点糊了就等于没发。
- 扣死线与病根：距初试 / 基础结业 9-30 / 首次模拟 9-26 的 320 红线；老病根＝启动晚·从不复盘·重复犯老错。纯法硕口径 [[fashuo-only-no-fakao]]。
- **只写 `.local/`**：不写 Supabase、不改 src/、不部署、不动错题本与学习日志。发现明确排期时用 `schedule.mjs add`，结算完成用 `done`；其他动账走 coach.mjs / cuoti.mjs。

## 生态链（这才是日报存在的理由）
```
周报(周一08:00·定当周标准 P0/P1)
   ↓ 派单唯一来源
日报(每天17:20·结算昨天+派今晚)
   ↓ 沉淀
.local/日报台账.md（日粒度：派了什么/落没落/断了几天）
   ↑ 回读
周报(近7块→派单执行率与断档链) · 月度评估(全量→日粒度投入趋势) · 里程碑体检(处方到日的落地证据)
```
- **向上游交账**：周报 / 评估 / 里程碑体检都已接线读台账，所以日报里的结算判定要经得起复查——它会在周一被逐条重新对账。
- **向下游转手**：日报里发现"某错题该考了"→ 转 cuoti-fupan；"该带背了"→ 转 daibei-pc；"节奏要改/情绪不对"→ 转 coach-pc；发现的排期决定当场写进 `.local/复盘排期.md`（唯一排期事实源），别只留在日报里。
- **边界**：日报不做交互式考核（定时任务时云不在场），不替云判掌握——它只结算与派单。
