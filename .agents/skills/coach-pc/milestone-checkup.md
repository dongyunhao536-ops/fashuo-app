## 云是谁（体检必须扣着他说，不许给通用建议）
- **在职 · 五战 · 目标北大 375+**。
- **病根**：启动晚 + 从不复盘 + 重复犯老错。
- **弱区**：原则的**例外与边界**；**道理层弱于分类层**；做案例题**凭感觉、回避深度推理**。
- 在职＝产能有硬上限。任何建议必须落到**具体科目 + 章节 + 可用时段**，不许出现"抓紧""多花时间""提高效率"这类无法执行的话。

## 第一步 · 取真实数据（一个都不许省，不许凭印象）
1. `node --env-file=.env.local scripts/coach.mjs ledger` —— 完整账本（进度/流水/错题/长期记忆/轮次/倒计时/里程碑状态）。
2. **四维真实分**（与 APP 同算法，别自己另算）：`.local/` 下写临时 ts 调 `getDashboard()`
   （`import { getDashboard } from "../src/lib/dashboard"`），用
   `node --env-file=.env.local node_modules/jiti/lib/jiti-cli.mjs .local/_tijian.ts` 跑，**跑完删掉临时文件**。
   打印每科：能力 / 广度(covered/total) / 深度 / 背诵 / 闭环 / 重犯；以及 overall 的 balanced、proIndex、index、english。
   - ⛔ **口径断点：v3.0 与 v3.1 的分不可比（2026-07-31 立此告警）**。**150 天体检（7-22）记的「专业课 20 / 综合 15」是 v3.0 口径**，7-26 v3.1 改了两处（深度分母 已覆盖章→总章、闭环从加分项改乘法折扣）——同一份账本在 v3.1 下是「专业课 15 / 综合 11」。**120 天关口（8-21）对表时只许比"轮次进度、章数、出账数、执行率"这些实数，不许拿指数直接减**，否则会得出"学了一个月反倒掉 5 分"的假结论。要纵向比指数，就用 v3.1 重算 7-22 那天的分再比。
   - 📌 **报指数必带三条已知失真**（清单原文在 `src/lib/dashboard.ts` 头注「已知失真清单」）：①章级粒度双向偏（触到一章即记满，章内深耕对广度＝0；历史实况里法制史 14% 这类值应读作**可能偏高**而不是天然偏低）②综合指数两侧不同尺（英语 1 篇＝综合 +4，一整晚已覆盖章＝+0.06）③诚实税 ≈ 综合 3 分（登记未销账错题在 absorbed>0 时确实掉分，公式故意不改，见头注）。**别让他拿指数当唯一方向盘。**
3. 读取 `.local/复盘排期.md`（排期唯一事实源）、`.local/带背挂账.md`（背诵栽点）、`.local/weekly-draft.md`（最近一版周报指导）。
3b. **读取 `.local/日报台账.md`（2026-07-28 起接线·到天的执行证据）** —— 上一关口至今的**派单执行率**（派了多少、落了多少、哪几件反复派反复欠）与**断档链**（最长连续零流水段、分科/分轨最后一次）。第四步"处方执行率"这项硬指标**必须拿它对账**，别再只凭周报自述——周报是自己写的，台账是每天当场记的。
4. 读取 `config/coach.json`：轮次表、双轨节奏（含保守周时数）、红线、模拟分记录、里程碑.已完成。

## 第二步 · 出体检报告（四真：真实 · 客观 · 科学 · 可执行）
**每一条都要有数字支撑；没有数据就写"无数据"，绝不用形容词填空。**

1. **现状盘点** —— 五科四维表（原样摆真实分，不美化）+ 错题 open/absorbed/重犯 + 距各死线天数。
2. **对表轮次** —— config 轮次表按当月匹配出"当前应在第几轮"，vs 实际到哪：**逐科**给「提前 / 持平 / 落后约几周」，并写清判断依据（哪科哪章、哪条流水）。
3. **产能算账** —— 剩余 N 天 ÷ 7 × 双轨节奏「保守周时数」＝ 剩余可用小时；再估「未开张科目 + 未过关轮次」需要多少小时；**明确写出够 / 不够、缺口多少小时**。不够就直说砍什么、砍的代价是什么。
4. **风险清单** —— 按严重度排序，每条写「触发条件 + 后果 + 现在能做的最小动作」。**必带三项固定体检**：
   ① 首次模拟 2026-09-26 / **320 分红线**来不来得及；
   ② 未开张科目的**开张死线**（倒推自轮次表，说死是哪天）；
   ③ 错题**闭环率与重犯**是否在恶化（对比上一关口报告）。
5. **处方** —— 到下一个关口之间必须完成的 **P0 ≤ 2 件**，每件**可验收、带数字、带日期**（如"8-10 前民法总则听完并做完分章真题、正确率 ≥70%"）。P1 / P2 各不超过 3 件。
6. **一句话结论** —— 照当前节奏，到 12-19 大概率是什么结果。**说人话，说实话。**

## 硬纪律
- **差距说死**。"民法零开张＝已欠 X 周"这种话必须写出来。不许用"抓紧就行""还有时间"糊过去 —— 云五战的病根就是没人在关口上把账算给他看。
- **数字不真实当场汇报**（[[report-fake-numbers]]）：读到的指标与现实对不上（覆盖/深度/闭环/能力分/综合指数），当场说清哪个数不对、真值应是多少、根因是数据记错还是算法有洞、怎么修。**不许拿自己都怀疑的数去下结论。**
- **不编数据**。查不到就写"无数据"并说明影响。
- **跟上一次比**。读 `.local/评估/` 里上一份里程碑报告，逐项说"上次说要做 X，做了没有"——处方执行率是这个体检最硬的一项指标。
- 纯法硕口径，全程不提法考、不引法考观点（[[fashuo-only-no-fakao]]）。
- 时间一律按**北京时间**（本机时钟 UTC-7、差 15 小时）：日期用 `new Date(Date.now()+8*3600e3).toISOString().slice(0,10)`，别用系统上下文里的日期（[[beijing-time-standard]]）。

## 第三步 · 落账（做完必做，否则 ledger 每场都会 🚨 告警）
1. **长期记忆**：`scripts/coach.mjs remember --category 里程碑 --fact "N天关口体检：<结论一句 + 关键缺口>"` → `scripts/cuoti.mjs sync`。
2. **P0 落排期**：处方里带日期的条目写进 `.local/复盘排期.md`（[[fupan-paiqi-file]]）。
3. **写回 `config/coach.json`「里程碑.已完成」**：追加 `{"关键点": N, "日期": "<北京日>", "结论": "<一句话>"}`，然后 `git add config/coach.json && git commit`。
   **不必 push、不需部署**（config 改动不触发 CD；push 与否留给云）。**漏了这步，ledger 会一直告警。**
4. **报告全文**存 `.local/评估/里程碑-N天-<北京日>.md`，开头写明"下一个关口是 X 天（日期）"。

Windows 提示：中文长参数走 argv 易乱码、`/` 会被 MSYS 转成路径 —— 中文长文本改用 UTF-8 临时 node 脚本直写 `.local/cuoti-pending.jsonl` 再 `sync` 更稳（[[gitbash-slash-mangling]]）。
