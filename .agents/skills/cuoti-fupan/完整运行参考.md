# 错题复盘

目标：把真实做错事件转成可复用的长期弱项主题，用冷复检证明“不二过”。不要把长段错题描述当分类，不要把刚讲完答对当掌握。

## 工作流

1. 选一个 T#主题或同病根小窝，先读每条事件的原始栽点；画像中的“习惯性”可决定优先训练角度，“已确认个案”只作局部证据，“候选待认领”必须在本题重新验证。优先遵守 `proof.nextProbe` 的变式、验证轴与冷却日；若材料证据表明处方不适用，说明理由后重算，不可静默改轴。<!-- [gpt] 2026-08-10 -->
2. 对核心术语取教材、真题或讲义锚点：只有一个词用 `material <词> ... --run <SR-ID>`；有 2–3 个独立核心词时一次用 `material-batch ... --run <SR-ID>`，每个词仍独立输出完整证据，不合并争点、不减少覆盖，只复用一次材料加载。`--run` 是 `materials_checked` 的自动回执，绝不能漏。<!-- [gpt] 2026-08-12 -->
3. 按《命题判题规范》出递进题，一次给 1–2 道；第一题必须正中原始错因。把验证轴落实为题目中主动改变的变量，但不得把轴名、病根预测或规则结论写进题面。草稿完成后必须运行启动快照给出的 `questionIntegrity.command`：选择题显式标 `【单选题】/【多选题】`；所有题均传教练侧答案键或参考答案。只有 `QUESTION_INTEGRITY_PASS` 才能进入下一步。BLOCK 就重写、复跑，不展示。<!-- [gpt] 2026-08-12 -->
   - **Gate PASS 后、云作答前落一条预测（2026-08-07 判断台账；[gpt] 2026-08-12 前置 Gate）**：`node scripts/judgment-ledger.mjs add --type 栽点 --prediction "他会栽在 X" --subject 科目 --ref T#id --verify-date 当日 --basis "依据"`；判分时 `resolve <id> hit|miss`。判对的没人记＝分母永远不存在，所以**对错都记**；预测只在教练侧静默保存。若展示后发现题面污染，该预测改用 `resolve <id> void`，不得算教练预测 miss。
4. 云作答后，先保留原答与依据，再逐项判。答错时给 2–4 条互斥病根候选，由云认领；认领前禁止用“暴露、证明、确认”把候选写成事实。证据卡按教材/讲义/考试分析“页码（未知须明示）+行号”、法条“条号”、真题“年份+题号”完整定位。<!-- [gpt] 2026-08-13 -->
5. 新错误用带 `--topic` 的 `add` 入账；旧事件用 `classify` 补主题。主题拿不准时标 `--classification pending`；病根未认领一律 `--diagnosis pending`。用户认领/排除后，沿用同一 Run 执行 `classify ... --diagnosis confirmed|rejected --run <SR-ID>`，由业务脚本落 `diagnosis_recorded`，不能手签。<!-- [gpt] 2026-08-13 -->
6. 每个真实复检都按《数据契约》用 `review T# pass|partial|fail|void --variant ... --axis ... --angle ... --anchor ...` 留完整证据。<!-- [gpt] 2026-08-12 --> `--axis` 是受控的主动变量，`--angle` 是本题可读细节；改写 angle 不能伪造第二个轴。变式决定维度和迁移等级，禁止自由打分；同日订正、提示通过、原题复现、规则复述与 teach-back 都不能凑主题 stable。展示后发现污染，只写 `void --variant invalid --invalid-prompt --note "题面污染；responsibility=teacher"`；不得写用户 fail/病根，CLI 会保留原排期并禁止推进冷却。
7. 达到事件销账门槛后运行 `absorb #id...`；<!-- [gpt] 2026-08-10 --> CLI 与 outbox 落库前都会重验：最近失败后至少两条带原答/依据的 clean L3+ application 通过、覆盖两个结构化验证轴，且至少一条是跨会话冷检；当日新错直接拒绝。只改写 angle 不算第二轴，禁止手改 outbox 绕过。写操作自动进入可靠 outbox 并立即同步，成功前不要说已入库。误销账只用 `reopen #id --reason "..."` 行政恢复，不得用 `recheck-fail` 伪造失败或复发。
8. **[gpt] 排期必须按对象一致性结案**：单主题排期直接在真实 `review T# ... --schedule <ID>` 中留证并结案，不得另跑裸 `schedule.mjs done`。整组排期先逐 T# 执行并写入 review 证据，全部目标都完成后才可运行 `schedule.mjs done <ID> --topics <原排期完整T#集合> --evidence-refs <逐题已落库证据引用> --result "..."`；无 T# 的单一知识点精准排期使用 `--kp <原KP-ID> --evidence-refs <已落库知识证据引用>`。CLI 会拒绝少目标、多目标、`T#10/T#108` 前缀混淆、缺证据引用或无稳定 T#/KP-ID 的模糊结案。未过则原排期保持 open，再用 `schedule.mjs add` 安排下一次；会话里新定日期当场落账。`void` 不是完成项，命令只留教练审计并保持原排期 open。<!-- [gpt] 2026-08-12 -->
9. 判题先经 `judgment-result.mjs check --run <同一SR-ID>` 自动生成证据卡并落 `judgment_output_verified`，再运行 `cuoti.mjs review --run`；后者进入 outbox 前会核对两者 T#、结果和病根状态。`partial/fail + diagnosis=pending` 先以 `checkpoint --phase diagnosis_question --hash <pending卡SHA256>` 原样展示并等待，不得 `end`；认领写回后重新生成 confirmed/rejected 卡，才以新卡 hash 结束。若继续出下一题，沿用原 `--run` 触发跨科重规划。下一步可以留在本主题，也可以切科，但必须能用最新候选池说明边际收益，不能因为“刚才在法理”就继续法理。<!-- [gpt] 2026-08-13 -->

## 特殊路径

- 云说“抽查老题/复盘老错题”：运行 `recheck`，最久未碰优先。通过后 `pass #id` 维护全覆盖轮换；若有 T#，同时按真实题型写完整 `review` 证据。失败用 `recheck-fail #id` 重挂并写完整 `review T# fail --variant ... --axis ... --angle ... --anchor ...`，不得再写裸 pass/fail。
- 当日新错：只讲解、认领、`add`、排冷考；当天不重考、不销账。**[gpt] 批量错题入账后必须自动逐题讲解（2026-08-11 云定）**：确认同步后立即从原题顺序中的第 1 题开始，一次只处理 1 题，讲透并完成必要的病根认领后再进入下一题；不先问“要不要讲”，不得把“已经记录”当作会话收口。**讲解不另记 study_log 流水（2026-08-07 云定）**：错题讲解只在会话里讲透，错题本身以 `add` 入账即算记录，不再为讲解单独开一条学习日志。
- **[gpt] 错因纠正不重启（2026-08-13）**：云纠正某题错因时，直接在当前 `intake` Run 下用 `classify` 覆盖该事件关系并继续下一题；不得为一句错因纠正重跑启动快照、材料检索或新建 Run。教练之前的误解不写成用户画像；只保留云最终确认的原意。
- **复盘活动落流水（2026-08-09 云定·口径修正）**：周三轻滚、周日冷启动等整场复盘活动结束，按科目各记一条 `activity=复盘` 的 study_log（`coach.mjs log --subject X --activity 复盘 --chapter "周日错题复盘·..." --feeling "验了哪些主题、pass/fail、病根认领、排期回写"`），`log_date` 用当天北京日。复盘活动与“记录错题后的逐题讲解”是两件事：前者落流水、后者不落。
- **周三轻滚强度（2026-08-09 云定·加量；[gpt] 2026-08-10 门槛固化）**：原“20 分钟维护性·不销账”改为 **30–40 分钟·允许销账**——从本周目标窝里抽 3–5 条验证；旧事件至少先有一条跨会话冷检，再补无提示 clean 角度，累计覆盖两个结构化验证轴且都能讲出依据，才当场 `absorb`。当日新错仍不当天销。
- 复发主题：只认结构化迁移门槛；第一次合格 L3+ 通过只进入 monitoring，第二次还必须跨至少 7 天、换结构化验证轴且含一次 L4 才可能 stable。
- 主观题需要 15 分逐句批改时转 `lunshu-pc`；本 Skill 继续保存客观题式错因和表达漏点主题。

## 红线

- 所有复检题必须先过《执行裁量契约》的命题完整性 Gate；不得用自然语言自检代替脚本 PASS。
- 引用编号必须带内容摘要，如 `T#12（监护人顺位）`。
- 判题前必须取证；材料没讲就说不确定并降信心。
- 云未认领前，不把教练推断写成 confirmed。
- 知识点相似度只缩小检索范围，不是映射事实；`suggest-errors` 的全部候选都保持 pending。只有人工核对源对象、目标 KP 与材料锚点后，才可显式 `link ... --status confirmed --method manual --anchor ...`。<!-- [gpt] 2026-08-10 -->
- 不把画像样本占比、预测兑现率或任何调度分写成掌握率；低样本不得自动改训练策略。
- `pending` 栽点可以帮助设计验证题，但不得驱动下一探针；处方只采用 confirmed 栽点，缺 confirmed 时走中性验证轴。<!-- [gpt] 2026-08-10 -->
- `absorb` 只销事件，且必须通过自动证据门槛；一次通过最多让主题进入 monitoring，不能销事件。主题是否 stable 只认满足结构化迁移门槛的跨日 `error_review`，旧裸 pass 最多 monitoring。<!-- [gpt] 2026-08-10 -->
- 不改 `kp_state`、`detection_log` 或背诵台账状态。
- 全程按法硕口径，不引法考通说替代考试分析。
