## 工作流

### 0. 默认快路径：`scripts/fupan.mjs`（[claude] 2026-08-30）

旧题复检**默认走这条**；下面第 1–9 步是它内部按序执行的同一批受控命令，手工逐条敲只作回退路径。

```bash
FASHUO_SESSION_ID="$CLAUDE_CODE_SESSION_ID" FASHUO_PRODUCER_HOST=claude \
  node --env-file=.env.local scripts/fupan.mjs ask --spec .local/fupan-<题>.json
```

| 命令 | 覆盖下面哪几步 | 规格字段 |
|---|---|---|
| `ask` | 建 Run → 一次 `material-batch`（第 2 步）→ 题面 Gate（第 3 步）→ 落预测（3 的子条）→ 签 `question` | `target`（**须含 `T#…/E#…`**）、`kind`、`materialQueries`、`type`、`stem`、`answer`、`originalAnswer`、`prediction`、`basis`、`subject` |
| `judge` | 证据卡 Gate（第 9 步）→ 写回 `review`（第 6 步）；`pass` 满门槛顺带 `absorb`（第 7 步）并收口，`partial/fail` 停在 `diagnosis_question` 等认领 | `run`、`judgment`、`review`、`resolvePrediction`、`cardPath`、`thenAsk` |
| `claim` | 云认领后 `classify`（第 5 步）→ 重出终态卡 → 收口 | `run`、`event`、`cardPath`、`status`、`claimIndex`、`pattern`、`recognitionRef`、`verdict` |

- `materialQueries` 每项写 `"关键词"` 或 `{ query, refine }`，整批合成**一次** `material-batch`，与第 2 步的批量要求一致。
- `judge` 规格里给 `thenAsk`（指向下一题的 ask 规格路径），可在 `pass` 后把「判分＋出下一题」并成一次调用。
- 不带参数跑一次 `fupan.mjs` 即打印三份字段清单，不必翻本文件。

**它的定位是"提前满足契约"，不是"绕过契约"。** 前置校验只把过去要靠 BLOCK 才知道的东西在本地判掉：
`target` 缺 `E#`、答案键含题面外选项、证据锚点格式、`--context timed` 漏 `--seconds`、
`--diagnosis` 未与 `--pattern` 同给、题型枚举、终态卡未逐字保留原候选。
`skill-run` / `judgment-result` / `question-integrity` 的判闸口径一条都没动，回执原样透传。
本地校验失败打印 `FUPAN_BLOCK｜<原因>` 并以退出码 2 结束——照提示改规格重跑即可，
**不要因为撞了 BLOCK 就退回手工路径**，那正是 08-30 那场把 40 分钟烧成 4 道题的走法。

## 特殊路径

- 云说“抽查老题/复盘老错题”：运行 `recheck`，最久未碰优先。通过后 `pass #id` 维护全覆盖轮换；若有 T#，同时按真实题型写完整 `review` 证据。失败用 `recheck-fail #id` 重挂并写完整 `review T# fail --variant ... --axis ... --angle ... --anchor ...`，不得再写裸 pass/fail。
- 当日新错：只讲解、认领、`add`、排冷考；当天不重考、不销账。**[gpt] 批量错题入账后必须自动逐题讲解（2026-08-11 云定）**：确认同步后立即从原题顺序中的第 1 题开始，一次只处理 1 题，讲透并完成必要的病根认领后再进入下一题；不先问“要不要讲”，不得把“已经记录”当作会话收口。**讲解不另记 study_log 流水（2026-08-07 云定）**：错题讲解只在会话里讲透，错题本身以 `add` 入账即算记录，不再为讲解单独开一条学习日志。
- **[gpt] 错因纠正不重启（2026-08-13）**：云纠正某题错因时，直接在当前 `intake` Run 下用 `classify` 覆盖该事件关系并继续下一题；不得为一句错因纠正重跑启动快照、材料检索或新建 Run。教练之前的误解不写成用户画像；只保留云最终确认的原意。
- **复盘活动落流水（2026-08-09 云定·口径修正）**：周三轻滚、周日冷启动等整场复盘活动结束，按科目各记一条 `activity=复盘` 的 study_log（`coach.mjs log --subject X --activity 复盘 --chapter "周日错题复盘·..." --feeling "验了哪些主题、pass/fail、病根认领、排期回写"`），`log_date` 用当天北京日。复盘活动与“记录错题后的逐题讲解”是两件事：前者落流水、后者不落。
- **周三轻滚强度（2026-08-09 云定·加量；[gpt] 2026-08-10 门槛固化）**：原“20 分钟维护性·不销账”改为 **30–40 分钟·允许销账**——从本周目标窝里抽 3–5 条验证；旧事件至少先有一条跨会话冷检，再补无提示 clean 角度，累计覆盖两个结构化验证轴且都能讲出依据，才当场 `absorb`。当日新错仍不当天销。
- 复发主题：只认结构化迁移门槛；第一次合格 L3+ 通过只进入 monitoring，第二次还必须跨至少 7 天、换结构化验证轴且含一次 L4 才可能 stable。
- 主观题需要 15 分逐句批改时转 `lunshu-pc`；本 Skill 继续保存客观题式错因和表达漏点主题。

## 红线

- 所有复检题必须先过《执行裁量契约》的命题完整性 Gate；不得用自然语言自检代替脚本 PASS。
- 引用编号必须带内容摘要，如 `T#12（监护人顺位）`。
- 判题前必须取证；材料没讲就说不确定并降信心。
- 云未认领前，不把教练推断写成 confirmed。
- 知识点相似度只缩小检索范围，不是映射事实；`suggest-errors` 的全部候选都保持 pending。只有人工核对源对象、目标 KP 与材料锚点后，才可显式 `link ... --status confirmed --method manual --anchor ...`。<!-- [gpt] 2026-08-10 -->
- 不把画像样本占比、预测兑现率或任何调度分写成掌握率；低样本不得自动改训练策略。
- `pending` 栽点可以帮助设计验证题，但不得驱动下一探针；处方只采用 confirmed 栽点，缺 confirmed 时走中性验证轴。<!-- [gpt] 2026-08-10 -->
- `absorb` 只销事件，且必须通过自动证据门槛；一次通过最多让主题进入 monitoring，不能销事件。主题是否 stable 只认满足结构化迁移门槛的跨日 `error_review`，旧裸 pass 最多 monitoring。<!-- [gpt] 2026-08-10 -->
- 不改 `kp_state`、`detection_log` 或背诵台账状态。
- 全程按法硕口径，不引法考通说替代考试分析。
