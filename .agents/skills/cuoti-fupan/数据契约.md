# 错题本 v2 数据契约

## 三层事实

- `study_error`：一次真实做错事件。保留题目语境、当时误答、正确结论、栽点和证据，不拿它充当长期分类名。
- `error_topic`：长期弱项主题。标题用稳定、短、可复用的法律问题，如“监护人顺位的法定条件”。
- `error_review`：跨会话复检证据。<!-- [gpt] 2026-08-10 --> 新记录必须带变式类型、派生维度、冷检条件、题干完整性、结构化验证轴、可读角度和证据锚点；旧版裸 `pass` 只兼容为 monitoring，不能再靠“两次 pass”直接 stable。
- `study_error_topic`：事件与主题的多对多关系。每个事件最多一个 `primary`，其余为 `related`；病根与诊断状态写在这张关系表。

事件状态 `open / absorbed / dismissed` 与主题状态 `open / monitoring / stable / archived` 是两条轴：销掉一次错题事件，不等于长期主题已经稳定。

## 只读命令

```powershell
node --env-file=.env.local scripts/cuoti.mjs list [科目]
node --env-file=.env.local scripts/cuoti.mjs topics [科目]
node --env-file=.env.local scripts/cuoti.mjs profile [科目] [--limit 5] [--json]
node --env-file=.env.local scripts/cuoti.mjs proof [科目] [--topic 12] [--limit 20] [--json]
node --env-file=.env.local scripts/knowledge.mjs suggest-errors [科目] [--limit 20] [--candidates 3] [--min 65] [--json]
node --env-file=.env.local scripts/cuoti.mjs triage [科目] [n]
node --env-file=.env.local scripts/cuoti.mjs material <关键词> [特征词]
node --env-file=.env.local scripts/cuoti.mjs recheck [n]
```

- `list` 看尚未销账的错题事件，并显示关联的 `T#主题`。
- `topics` 看长期弱项、事件数、病根和掌握状态；选题与按窝复盘优先读它。
- **`profile`（[gpt] 2026-08-10）**从 `error_book_v2`、`knowledge_evidence`、`knowledge_object_link` 的 confirmed 映射和稳定知识点目录重算细粒度栽点画像，不新建“画像真相表”。`pending` 只显示为候选；单个确认失败只叫已确认个案；同一栽点跨至少 2 个知识点出现 3 次确认失败才叫习惯性。画像输出的是样本计数，不是掌握率。
- **`proof`（[gpt] 2026-08-10）**按 `error_review` 原始证据逐主题重算 `open/monitoring/stable`，展示合格迁移次数、北京日跨度、结构化验证轴、L4 覆盖、旧 pass 兼容量和库内状态偏差，并开出下一探针处方。它不写库、不生成题目，也不输出掌握概率；`mastery_status` 与重算结果冲突时不得沿用缓存口径继续宣称稳定。
- **`suggest-errors`（[gpt] 2026-08-10）**只展示仍无稳定 `kp_id` / confirmed 对象映射的细粒度错题证据，零写入。分数只是候选排序，不是正确概率；输出分为强候选待核、多候选待核、需人工核对、弱相似、明确保留未映射和目录不覆盖。所有相似度候选一律保持 pending。
- `triage` 只列没有主题关联的旧事件；历史账逐步补，不批量瞎归类。
- `material` 必须用 2–6 字连续术语；具体争点加特征词。它分开显示心得、教材、易混库、真题原卷与二次总结。

## 知识点候选与人工确认（[gpt] 2026-08-10）

`knowledge_object_link` 是“学习对象属于哪个稳定知识点”的唯一事实。主题文案相似、原题上下文命中、Anki 章节映射和模型判断都只能产出候选，不能直接确认。

固定顺序：

1. `suggest-errors [科目]` 只读预览真正未映射的证据。
2. 对每个候选运行 `knowledge.mjs show <KP-ID>`，同时回看 `T#主题` / `#错题事件` 原文与证据锚点。
3. 单一内容点明确时，由人工显式确认：

```powershell
node --env-file=.env.local scripts/knowledge.mjs link error_topic 12 XF-0100 `
  --status confirmed --method manual --confidence 100 `
  --anchor "人工核验:T#12+考试分析L120-126"
```

4. 一个主题确实跨多个知识点时，只选一个 `primary`，其余使用 `--role related`；错因画像只把该次失败归入 primary，related 只保留内容关联，不复制失败样本。拿不准就继续 pending 或保留未映射。
5. confirmed 必须带人工核验 `--anchor`，否则 CLI 拒绝写入。写操作仍先进可靠 outbox，同一“对象 + KP”按唯一键幂等更新；同步成功前不得宣称已映射。

跨科做题方法主题不是单一内容知识点，不为了画像计数硬连；英语等稳定目录未覆盖科目转对应 skill。候选找不到，代表当前证据不足或目录粒度不合适，不代表系统必须猜一个。

`validateErrorEntry()` 是所有 PC `new_error` 的唯一写回前校验器：单条暂存、批量清单生成和最终 outbox 同步都必须通过它。调用入口自动赋 `entrySource`，批量章节自动下沉到每道错题；模型不手写来源枚举。没有病根事实时持久关系规范为 `unassessed / unclassified`；`pending` 只存在于当前 Run 临时判题 artifact，不入库。若声称 `diagnosisStatus=confirmed`，代码要求具体病根代码和认领说明。错误通过 `ERROR_ENTRY_INVALID` 与字段级 code 返回，先补对应事实再重试，不准靠改写提示词绕过。同步会先预检整份 outbox，再发起第一笔远端写入，防止后段坏条目造成半批落库。<!-- [gpt] 2026-08-25 -->

历史任务性能回放禁止再次写入，改用 `verify-batch <同一清单> --run <SR-ID>` 核验该北京日、科目和章节下恰好一条匹配进度、每道题恰好一个匹配事件；核验成功后自动签 intake 写回回执。

事件销账前必须把每次验证都用 `review ... --event <事件id> --note "原答与依据"` 关联到原事件。`absorb <事件id...>` 会在 CLI 预检和 outbox 落库前各重验一次：错题日必须早于当前北京日；最近一次 `partial/fail` 后至少两条 `clean + application + L3+` 通过；至少两个不同 `probe_axis`；至少一条是跨会话冷检；每条都有 angle、教材/真题 anchor 与保留原答/依据的 note。一次通过、同轴换措辞、提示通过、无依据、当日新错一律拒绝。

误销账使用审计恢复，不制造学习证据：

```powershell
node --env-file=.env.local scripts/cuoti.mjs reopen 102 --reason "教练误把一次通过当作销账门槛"
```

`reopen` 只把既有事件从 `absorbed` 恢复为 `open`，清空本次吸收标记并记录最近恢复时间、来源和原因；不得用 `recheck-fail` 代替，因为后者表示用户真的抽查失败并会新建复发事件。

复检留证：

```powershell
node --env-file=.env.local scripts/cuoti.mjs review 12 pass `
  --variant counterfactual --event 81 `
  --axis subject_condition `
  --angle "变式案例：替换监护候选人的履职能力" `
  --anchor "考试分析L120-126" --note "能主动说出顺位与能力是两道门"
```

<!-- [gpt] 2026-08-10：变式等级是枚举派生值，不接受自由打分。 -->

| `--variant` | 自动维度/等级 | 能否作为 stable 迁移证据 |
|---|---|---|
| `original` | application / L1 | 否，原题复现 |
| `rule_recall` | recall / L2 | 否，只证明复述 |
| `counterfactual` | application / L3 | 可，须冷检 clean |
| `novel_case` / `integrated_case` | application / L4 | 可，且 stable 至少要有一次 L4 |
| `teach_back` | recall / L5 | 否，等级高也不能替代应用迁移 |
| `invalid` | application / L0 | 只和 `void --invalid-prompt` 配套；教练责任审计，不计有效题量/用户错误/掌握，不推进冷却或关闭排期 |

<!-- [gpt] 2026-08-10：axis 是受控主动变量，angle 只做可读审计。 -->

| `--axis` | 主动改变的变量 |
|---|---|
| `rule_boundary` | 例外、但书、适用范围或排除条件 |
| `subject_condition` / `object_condition` | 主体资格 / 行为对象或客体条件 |
| `time_condition` / `procedure_order` | 时间节点 / 程序或判断先后 |
| `degree_term` / `element_structure` | 程度效力词 / 要件结构 |
| `concept_boundary` / `question_layer` | 相邻概念界线 / 设问层级 |
| `fact_signal` | 题干事实信号、表述位置或干扰线索 |
| `integrated` | 陌生综合案情中的多轴联动 |
| `invalid` | 作废题内部轴；非作废复检禁用 |

非作废复检必须有 `--variant`、`--axis`、`--angle`、`--anchor`；`--axis` 说明命题时主动改变的变量，`--angle` 留本题具体细节。两个不同 angle 若属于同一 axis，仍只算一个验证轴。`--same-session` 或 `--cued` 自动记非冷检。主题进入 stable 必须满足：最近一次 `partial/fail` 之后，至少两个不同北京日的 L3+ application 干净冷检通过，跨度至少 7 天、结构化验证轴至少两个，并且至少一次 L4 陌生/综合案例。任一新失败立即回 open；提示通过、同场订正、原题复现、规则复述和 teach-back 都不能凑 stable。

## 下一探针处方（[gpt] 2026-08-10）

`proof.nextProbe` 和教练快照中的 `nextProbe/reviewProbe` 使用同一确定性规则：

- 最近有效复检仍未过：两天后起做单变量 `counterfactual / L3`，先隔离病根。
- 没有结构化迁移证据：做 L3 基线；旧裸 pass 只触发补证，不反推验证轴。
- 已有 L3 但缺 L4：首个合格日满 7 天后起做 `novel_case / L4`。
- 已有 L4 但缺第二日期、7 天跨度或第二验证轴：只补对应缺口，不重复已覆盖轴。
- 已 stable：降频到 `integrated_case / L4` 保持性复检，处方最早日为最近支持证据后 14 天。

处方只采用 confirmed 栽点映射到优先验证轴；pending 不驱动处方，缺 confirmed 时使用中性轴。`earliestDate` 是冷却下限，不是强制到期日；自动派单取“遗忘到期日”和“处方最早日”中较晚者。处方的 guardrails 约束命题，但轴名、栽点和结论不得写进题面。

**一致性回写（2026-08-07；[gpt] 2026-08-12 修订）**：自动派单的单主题复检必须带 `--schedule <排期id>`——CLI 在写远端证据前后都按原排期 ID、`route=cuoti-fupan`、`dimension=application` 与精确 T# 预检；有效复检证据落库（`error_review` + 主题状态 + 有 KP 时的 application/recall 知识证据）成功后，同一命令再结案 `.local/复盘排期.md` 对应条目。整组排期不得由第一条 review 提前结清：每个 T# 逐题留证，全部目标完成后才用 `schedule.mjs done <ID> --topics <完整T#集合> --evidence-refs <逐题已落库证据引用> --result "..."` 结案；无 T# 的单一知识点精准排期用 `--kp <原KP-ID> --evidence-refs <已落库知识证据引用>`。命令按离散目标集合核对，`T#10` 不得命中 `T#108`，少目标、多目标、缺证据引用、无稳定 T#/KP-ID 或同科替代均拒绝。`void` 只落教练责任审计并保持排期 open。`--stage` 暂存不会结案；同步或本地结案失败时先修关联，再按提示重跑同一安全入口，禁止裸 `schedule.mjs done`。本地结案失败不回滚已落库证据。带背复检按 daibei 数据契约一次给全 `--recite/--event/--outcome/--cold/--prompt/--evidence`；不得把跨远端/本地或跨文件的操作称为数据库级原子事务。

**指定 P0 硬闸（[gpt] 2026-08-12）**：`skill-context cuoti` 将今日到期或逾期、且明确路由为 `cuoti-fupan/application` 的 P0 排期冻结在 `crossSubjectReview.requiredP0`。它们按原排期 ID 与稳定 T#/事件号先验收，不能被普通候选分数、同科其他题或“本周 P0 已有动作”冲抵。未来 P0 只显示为 upcoming；周报宏观 P0 仍只是普通候选的权重。硬闸若缺稳定目标、目标未映射 open 事件或与冷却处方冲突，输出 BLOCK 并先修数据链，不静默换题。

写操作都先入 `.local/cuoti-pending.jsonl`，随后立即自动同步；网络失败只保留失败项。只有显式 `--stage` 才延后。不要手改 outbox。

## 兼容纪律

- `absorb <事件id...>` 只销事件；命令会按上述事件级硬门槛重算证据，成功同步后才能说“已销账”。`reopen <事件id...> --reason ...` 只纠正行政误销账，不写失败/复发。<!-- [gpt] 2026-08-10 -->
- `dismissed` 是云确认“不是错题”，统计闭环率时明确分母是否排除它，绝不能把 `absorbed_at` 非空直接等同销账。
- `recheck` / `pass` / `recheck-fail` 继续维护旧事件全覆盖轮换。若事件已有 T#，同时用 `review` 留主题级冷复检证据。
- `recheck-fail` 自动按复发重挂并继承主题；不再依靠长文本完全一致判断复发。
- 英语条目由 `yingyu-pc` 在新文章里验证干扰项套路，本 Skill 不复做原题、不销英语事件。
- 背诵栽点仍归带背账，不写 `study_error`；错题本只装真实做题、复盘和考核中的错误。
