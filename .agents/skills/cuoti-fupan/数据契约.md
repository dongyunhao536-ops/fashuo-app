# 错题本 v2 数据契约

## 三层事实

- `study_error`：一次真实做错事件。保留题目语境、当时误答、正确结论、栽点和证据，不拿它充当长期分类名。
- `error_topic`：长期弱项主题。标题用稳定、短、可复用的法律问题，如“监护人顺位的法定条件”。
- `error_review`：跨会话冷复检证据。同日刚讲完答对不写 `pass`；至少两个不同北京日通过，主题才自动进入 `stable`。
- `study_error_topic`：事件与主题的多对多关系。每个事件最多一个 `primary`，其余为 `related`；病根与诊断状态写在这张关系表。

事件状态 `open / absorbed / dismissed` 与主题状态 `open / monitoring / stable / archived` 是两条轴：销掉一次错题事件，不等于长期主题已经稳定。

## 只读命令

```powershell
node --env-file=.env.local scripts/cuoti.mjs list [科目]
node --env-file=.env.local scripts/cuoti.mjs topics [科目]
node --env-file=.env.local scripts/cuoti.mjs triage [科目] [n]
node --env-file=.env.local scripts/cuoti.mjs material <关键词> [特征词]
node --env-file=.env.local scripts/cuoti.mjs recheck [n]
```

- `list` 看尚未销账的错题事件，并显示关联的 `T#主题`。
- `topics` 看长期弱项、事件数、病根和掌握状态；选题与按窝复盘优先读它。
- `triage` 只列没有主题关联的旧事件；历史账逐步补，不批量瞎归类。
- `material` 必须用 2–6 字连续术语；具体争点加特征词。它分开显示心得、教材、易混库、真题原卷与二次总结。

## 写入命令

新错题优先一次写全：

```powershell
node --env-file=.env.local scripts/cuoti.mjs add 民法 "监护顺位题误选：把有能力担任监护人漏读" `
  --topic "监护人顺位的法定条件" `
  --chapter "第三章 自然人" `
  --section "第三节 监护" `
  --cause fact_misread `
  --cause-note "云认领：漏读题干中的履职能力" `
  --classification confirmed `
  --diagnosis confirmed `
  --anchor "考试分析L120-126"
```

已有旧账复发时加 `--recur-of <旧事件id>`。系统继承旧主题关联；若本次暴露了更准确的新主题，可同时给 `--topic`，旧主题降为 related 留痕。

历史补归类：

```powershell
node --env-file=.env.local scripts/cuoti.mjs classify 81 `
  --topic "监护人顺位的法定条件" `
  --chapter "第三章 自然人" `
  --cause boundary_miss `
  --diagnosis pending
```

一次错题涉及第二主题时再次 `classify`，加 `--role related`。不要把一个长标题硬塞进所有争点。

历史批量迁移使用经人工复核的 JSON 计划：`cuoti.mjs classify-batch <计划.json> --stage`，先 `sync --dry` 看全量，再正式 `sync`。不要让相似度算法直接改旧账。

复检留证：

```powershell
node --env-file=.env.local scripts/cuoti.mjs review 12 pass `
  --event 81 --angle "变式案例：替换监护候选人的履职能力" `
  --anchor "考试分析L120-126" --note "能主动说出顺位与能力是两道门"
```

写操作都先入 `.local/cuoti-pending.jsonl`，随后立即自动同步；网络失败只保留失败项。只有显式 `--stage` 才延后。不要手改 outbox。

## 病根代码

| 代码 | 含义 |
|---|---|
| `unclassified` | 待云认领 |
| `knowledge_gap` | 规则或结论缺失 |
| `boundary_miss` | 限定语、例外或边界遗漏 |
| `concept_confusion` | 易混概念混淆 |
| `reasoning_order` | 前置关卡或推理顺序错误 |
| `question_layer` | 审题层级错位 |
| `fact_misread` | 题干事实误读 |
| `terminology_drift` | 法律术语被日常语言改写 |
| `expression_gap` | 主观题表达漏点 |
| `memory_decay` | 已掌握内容回落 |

显式 `--topic` 默认把主题分类记为 confirmed；确实拿不准主题时加 `--classification pending`。病根只能在云认领后写 `--diagnosis confirmed`。教练推断一律 `pending`，并写中立候选；不能把“粗心”当病根代码。

## 兼容纪律

- `absorb <事件id...>` 只销事件；成功同步后才能说“已销账”。
- `dismissed` 是云确认“不是错题”，统计闭环率时明确分母是否排除它，绝不能把 `absorbed_at` 非空直接等同销账。
- `recheck` / `pass` / `recheck-fail` 继续维护旧事件全覆盖轮换。若事件已有 T#，同时用 `review` 留主题级冷复检证据。
- `recheck-fail` 自动按复发重挂并继承主题；不再依靠长文本完全一致判断复发。
- 英语条目由 `yingyu-pc` 在新文章里验证干扰项套路，本 Skill 不复做原题、不销英语事件。
- 背诵栽点仍归带背账，不写 `study_error`；错题本只装真实做题、复盘和考核中的错误。
