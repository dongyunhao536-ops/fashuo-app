# 错题复盘命题与判题规范

## 目标与画像

云是在职、五战、目标北大 375+。主要损失不是不会偏难题，而是启动晚、不复盘、同类老错反复出现；高频病灶集中在原则的例外、限定语、审题层级和法律术语精度。

每道题都要有明确治疗目标。不要用定义默写消耗时间；基础题也要考边界、辨析或前置判断。总体维持约 80% 常规基础、20% 拔高；第 3 轮 A 起才调到约 70/30。

## 出题前

1. 先读错题事件原文和 T#主题，第一题正中原始栽点，不能只考邻近知识。
2. 对目标术语分别运行 `material`，至少取得教材或真题锚点；检索不到就降低信心，不凭印象补全。
3. 同一 T#或同病根事件优先按窝设计，一道对照题可覆盖多条，但每条事件的原始栽点都必须被实际触发。
4. 真题主观题优先原题和随卷参考答案；二次汇总只作索引，不作唯一判分锚点。
5. **画像与校准边界（[gpt] 2026-08-10）**：`profile` 的习惯性栽点可决定训练角度；已确认个案不得外推成全科特征；`pending` 只用于设计验证题。分科栽点预测 N<5 不调策略，N≥5 但兑现偏低时降低教练置信、增加互斥候选。画像和预测都不能写进题干给提示。
6. **读取下一探针（[gpt] 2026-08-10）**：以 `proof.nextProbe` 的 `variantKind + probeAxis + earliestDate` 为命题约束；未到最早冷却日不提前连考。处方与材料冲突时先说明原因并重算，不静默换轴。
7. **发送前过 Gate（[gpt] 2026-08-12）**：完成题干、附加要求、提示语和教练侧答案键或参考答案后，按《执行裁量契约》运行 `node scripts/question-integrity.mjs check ...`。只有 `QUESTION_INTEGRITY_PASS` 草稿能进入预测与展示；BLOCK 必须重写、复跑，不得先让云看。

## 不换壳的五种变形

1. 换问法：正问/反问、定性/依据、结论/前置关卡、客观题/简答/案例。
2. 换决定变量：改变自动性、通谋、控制、主体资格、时间节点等，观察结论是否随变量变化。
3. 设真实陷阱：把云原来的错误认知做成诱导项，或引入易混概念、绝对化表述和跳步骤结论。
4. 叠层：案例同时触发构成要件、正当化、形态、共犯、罪数或量刑中的 3–5 层。
5. 易混对决：要求说出一句话区分 test 与判断顺序，而非只报最终选项。

一次只抛 1–2 题。答对后换角度升档；答错后回原文补漏，再换情境重考。

## 结构化验证轴（[gpt] 2026-08-10）

- 每次命题先从《数据契约》的受控枚举中选一个 `probe_axis`，再写可读 `angle`。axis 是主动改变的变量，angle 是该题如何实现；改写 angle 不等于换轴。
- `counterfactual` 只主动改变处方轴，其他核心条件尽量保持，用来隔离病根；`novel_case` 更换人物、数字和叙事顺序，仍须重点覆盖处方轴；`integrated_case` 才允许多轴联动。
- 处方只用 confirmed 栽点定向；pending 可帮助设计验证题，但不能当作已确认病根，也不能自动改处方。
- 轴名、病根标签、规则名称和预期结论都留在教练侧。题面只呈现自然事实和设问，防止训练目标变成答案提示。

## 题面引用红线

答案污染的类型、拦截与 `void` 责任以《执行裁量契约》的前置 Gate 为单一事实源，本文件不再重复一套自然语言清单。另保留引用可读性要求：写 `#72（受贿与徇私枉法）`、`T#12（监护人顺位）`，不写裸 `#72`、`上一问`；选择题选项编号本身不受此限。

## 判题

1. 先让云给结论和依据；主观题保留原答，不替他润色后再评分。
2. 先过前置关卡：共犯成立→主从犯，着手/实行终了→停止形态，一罪/数罪标准→罪数，构成要件→此罪彼罪。
3. 按教材、真题随卷解析或可靠讲义逐项判；用户可见证据卡必须给必要原文或内容摘要。教材、讲义与考试分析写完整出处（科目+章节+页码+标题+行号），页码查不到就标“该书页码未知”、不许编，行号只是其中一项、不许只报行号；法条写条号，真题写年份、题号与随卷解析定位。`judgment-result.mjs` 不通过就不得展示或收口。<!-- [gpt] 2026-08-13 -->
4. 多选逐项写“依据→出处→结论”，定稿前检查不同选项是否使用了互相冲突的规则。
5. 有学理分歧、材料缺失或疑似与标答冲突时明确降信心，不能用笃定语气遮掩。
6. 纯生成题要说明依据哪个材料锚点，防止“我出题、我自证”的循环。

## 病根认领

答错后给 2–4 条互斥、中立的可能路径，让云本人认领；至少覆盖“规则不会、边界漏记、概念混淆、步骤错位、题干误读”等实际可能。云排除的路径也要记录，因为它决定是否与老主题合并。

**[gpt] 2026-08-26：通过题不进入病根认领。** `pass` 的判题 artifact 固定为 `diagnosis=pending` 且 `claim/candidates/rejectedCandidates/recognitionRef` 全空；这里的 pending 只表示“本轮不新增病根”，不得渲染成“待认领”，不得询问错因，不得运行 `classify`。直接用不带 `--pattern/--diagnosis` 的 `review` 做一次业务同步并收口。若结论虽然正确但依据有误，应判 `partial`，再进入候选认领，不能用 pass 掩盖真实错误。

认领前只能在当前 Run 的临时判题 artifact 记 `diagnosis=pending`，自然语言也不得说“这个错误暴露了/证明了/确认了某病根”；2–4 条互斥候选绝不写数据库。形成终态证据卡时，`candidates` 必须逐字保留原候选，`rejectedCandidates` 必须列全其余排除项，不能认领后改写候选历史。持久关系初始为 `unassessed`；云认领后同 Run 更新为 `confirmed`，全部排除写 `rejected`。只有云明确说忘了/不认领时才写 `untraceable_by=user`；“下一题”、断网、Stop 或 Run 中止只记遥测，不能生成这条学习事实。用户在原决定 Run 内改口并想起时，可把同一关系更正为 `confirmed/rejected`；跨 Run、`policy_migration` 历史封账和偷换关系仍禁止。untraceable 此后只正面考知识点，不针对猜测误解设计探针、不声称证明病根、不与老账并案。<!-- [gpt] 2026-08-25 -->

`partial/fail + pending` 不是一个可以直接收口的结果阶段：先以 `diagnosis_question` checkpoint 原样展示 Gate 证据卡；用户认领后由同 Run `classify/review` 落 `diagnosis_recorded`。用户明确忘了/不认领时由 `mark-untraceable` 落回执；如果只是断网或 Run 中止，丢弃临时候选并只留中止遥测，数据库保持 `unassessed`。<!-- [gpt] 2026-08-25 -->

## 销账与冷复检

- 当日新错只讲解、认领、入账并排下次冷考；当天不重考、不销账。讲解不单独记入 study_log 流水——错题 `add` 入账即记录，讲解只留在会话与错题事件里（2026-08-07 云定）。
- **[gpt] 2026-08-10：普通事件销账硬门槛**：最近一次 `partial/fail` 后至少两条带原答与依据的 `clean + application + L3+` 通过、覆盖两个不同结构化验证轴，且至少一条是跨会话冷检，才 `absorb`；第二条可以是同场无提示补充角度，因此事件销账仍与主题跨 7 天 stable 分离。蒙对、答偏、提示后通过、同轴只换措辞、依据不清均不销；当日新错直接禁止。
- **[gpt] 2026-08-10：每次复检必须显式标变式**。`original`=原题复现 L1、`rule_recall`=规则复述 L2、`counterfactual`=反事实 L3、`novel_case/integrated_case`=陌生/综合案例 L4、`teach_back`=讲给别人 L5；等级由类型派生，禁止教练自由打分。L5 是 recall，不能因为数字高就冒充应用迁移。
- 主题进入 stable 必须在最近一次 `partial/fail` 后出现至少两个不同北京日的 L3+ application 干净冷检通过，跨度至少 7 天、结构化验证轴至少两个，且至少一次 L4。两个不同自由文本 angle 若仍是同一 axis，不得凑 stable。第一次合格通过只进入 monitoring；任何新 `partial/fail` 立即回 open。
- 提示后通过、同场订正、原题复现、规则复述、teach-back 和旧版缺元数据 pass 都不能凑 stable。<!-- [gpt] 2026-08-12：一般文字瑕疵与答案污染分流。 --> 已展示的一般文字瑕疵按《执行裁量契约》的实质性标准处理；答案污染一经发现直接按教练责任 `void`，不适用“小瑕疵放行”，且不消耗有效题量、冷却或排期。
- 复发事件同样服从上述结构化迁移门槛；“跨两个会话”不是充分条件。
- 销账由教练依据证据自主判定，不反问云；但必须简短说明考过哪些结构化验证轴、为什么达到或没达到门槛。`absorb` 会自动重验，不能手改 outbox 绕过；误销账用 `reopen --reason` 恢复，不得伪造一次 `recheck-fail`。<!-- [gpt] 2026-08-10 -->

## 主观题

第 2 轮起每周安排 2–3 道成段作答。按原卷随卷参考答案/解析的采分点逐条标“命中、漏答、表述失分”；反复漏点以 `expression_gap` 入主题。案例深训和 15 分逐句批改转 `lunshu-pc`，客观题错因闭环留在本 Skill。
