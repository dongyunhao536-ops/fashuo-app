# 带背挂账数据契约

本文件只管“背诵栽点如何成为可审计事实”。带背方法、轮次深度和学科教案仍读 `beisong-blueprint.md` 与 `docs/背诵论/`。

## 唯一事实源与机器视图

- 唯一事实源：`.local/带背挂账.md`。不要另建 JSON、表格或聊天记忆当第二本账。
- 只读解析层：`scripts/lib/recite-ledger.mjs`。日报、周报和 `coach.mjs ledger` 都调用它，因此同一时点必须得到同一组数量。
- 人工使用：
  - `node scripts/daibei-ledger.mjs summary`：当前存量、分科、最久未碰、已撤池轮抽候选。
  - `node scripts/daibei-ledger.mjs audit`：逐条列格式问题。
  - `node scripts/daibei-ledger.mjs check`：存在结构错误时退出 1；每次写回后必跑。
  - `node scripts/daibei-ledger.mjs flow --from YYYY-MM-DD --to YYYY-MM-DD`：本期新挂/撤池/重挂/移交流量。
  - `node scripts/daibei-ledger.mjs transition <ID> --event new|withdraw|rehang|transfer|route-recognition --evidence "<教材/复检锚点>" [--note "<接收轨/说明>"]`：同时改当前状态并在本文件末尾追加不可改写的迁移流水。`route-anki` 只兼容读取旧流水，禁止继续写。<!-- [gpt] 2026-08-24 -->
  - `[gpt] node scripts/daibei-ledger.mjs evidence <ID> --result pass|partial|fail|void --anchor "<教材/题目锚点>" [--dimension understanding|recall] [--cold true|false] [--prompt clean|cued|invalid] [--pattern <code> --diagnosis pending|confirmed|rejected] [--note "<表现/病根>"]`：一次联动写入人读复检行、`最后碰`、同文件 `recite-evidence-v2` 流水与可靠 outbox 的同号 `learning_attempt`；随后运行 `cuoti.mjs sync`。只有给既有正文补结构化证据时才加 `--backfill`，该模式不得制造历史尝试。
  - 调历史日期或测试时可加 `--today YYYY-MM-DD`；日期口径始终是北京日。

## 条目最小结构

```markdown
### X34｜刑法｜一句话栽点
- 挂 08-05 ｜ 最后碰 **08-05** ｜ 状态：挂（简短现状）
- **点（教材行号）**：……
- **复检（08-05）**：✗/半✓/✓；逐项限定语；教材行号；下一次怎么问
```

- ID 全局唯一、旧号不复用；前缀按现有账本延续（L 法理、X 刑法、M 民法、S 法制史，宪法沿现有约定）。
- `最后碰` 是排序字段，每次实际复检都更新；同场纠正不是冷复检，但也属于“碰过”，应更新日期并在状态说明中写清“不算过关”。
- 状态只表达当前去向：`挂`、`撤 MM-DD`、`带背侧结案·移交…轨`。曾撤后复栽写成 `重挂 MM-DD`，当前状态回 `挂`。
- 挑错式再认轨保持 `状态：挂`，标题或状态说明明确 `转挑错式再认轨·周中轻滚`；机器视图记为 `route=recognition_light_roll`，从带背开场候选中排除。新措辞掉点先返回 `routingState=pending_confirmation`，确认轻滚轨接收后才运行 `route-recognition`；迁移前不自动撤出原账。
- 教材原文、关键限定语和复检证据留在条目正文；数量、最久未碰和科目分布不手填在总标题。

## 知识点 ID 与历史 Anki 溯源（v2）

- 带背条目仍用 `X19/L22…` 做账本主键；它与稳定知识点 ID 的关系写入 `knowledge_object_link`，不把标题相似当事实。先用 `node --env-file=.env.local scripts/knowledge.mjs search "<关键词>"` 查目录，再用 `knowledge.mjs link recite_ledger <条目ID> <KP-ID> --status pending|confirmed --method ... --anchor ...` 留可审计映射。
- 自动/模糊建议一律先 `pending`；只有教材锚点能证明是同一知识点时才 `confirmed`。<!-- [gpt] 2026-08-10 --> 每个条目必须至多有一个 `confirmed primary`；可另挂 `related/reference` 表达关系，但通用复检证据只向唯一 primary 传播。若一个条目实际混了多个独立知识点，应拆条目或分别检验，不得复制同一次表现给多个点。
- 既有 Anki 卡片字段只保留历史溯源：`exact` 表示曾有同点材料参考，`section` 只表示章节级参考。2026-08-24 停用后不得再把卡片星级、P1 或 `note_id` 用作选点、路由或掌握证据；历史字段暂不删除，避免量化口径无审计变化。
- 同一次带背复检的表现事实只在本账本写一条 `recite-evidence-v2`；系统以同一 operation_id 自动写 `learning_attempt(source=recite_ledger, role=recheck)` 作为完整尝试分母。知识点引擎通过已确认映射实时派生状态证据，不得再手工写相同 `knowledge_evidence`。<!-- [gpt] 2026-08-10 -->
- 零 confirmed primary、多个 primary 冲突或只有 related 时，证据仍完整留在本账本，但知识层暂停接入并记为接线债；用 `knowledge.mjs stats` / `suggest-recite` 审计，必须人工核验后再 `link`，绝不自动确认。

## 状态与抽查口径

- `active`：当前仍挂；其中 `route=daibei` 才是开场可复检池，`route=recognition_light_roll` 进入周中挑错轻滚，不占带背开场时间。`route=legacy_anki` 只表示尚未完成 2026-08-24 迁移的旧数据，必须尽快归零。
- `withdrawn`：当前已撤，但不是“永久会了”；每场固定从此池抽 1 条，最久未碰优先。
- `transferred`：已移交其他学科/轨道，不计带背可复检池；接收轨负责后续证据。
- 开场共抽 3–5 条：先取机器视图的最久未碰候选，再按当日章节相关性调整；固定保留 1 条已撤池候选。相关性可以调序，不能把老账永久饿死。
- 普通条目后续冷复检 1✓ 可撤；曾连败≥2 需连续 2✓；累计 3✗ 转专项。刚讲完、同场改对、题干喂答案、问法失真都不能充当冷复检 ✓。

## 复检证据与栽点画像（v2）

- `dimension=understanding` 只证明能解释规则/边界；`dimension=recall` 才证明能脱离材料复述。带背轨不写 `application` 通过；应用证据必须由错题复盘、案例或其他真实应用检验产生。
- `result=pass|partial|fail` 必须对应真实作答；问法失真、答案预输入或无法归责于用户时记 `result=void --prompt invalid --cold false`。有提示后答对记 `--prompt cued`，不得升级为干净通过。
- `--cold true` 只用于跨时点、无提示、题干干净的提取；同场订正与刚看过原文一律 `false`。
- 失败或半对必须同时给 `--pattern`。用 `node --env-file=.env.local scripts/knowledge.mjs patterns` 查看代码、中文标签与训练焦点。单次由教练推断时写 `--diagnosis pending`；用户明确认领/确认后才写 `confirmed`；用户否认或证据证明归因错误时追加 `rejected` 更正事件，禁止改写旧流水。
- `pending` 只用于下一次验证，不得写成“你经常怎样”；科目级“习惯性栽点”须至少 3 次**已确认**失败且跨至少 2 个知识点。已确认栽点只有在失败后出现 2 个不同日期的定向干净冷检通过、跨度至少 7 天时才退役。
- 知识点主阶段为 `未接触→已接触→理解→能复述→能应用→稳定`，每次由证据重算；“冲刺”是考前独立派单通道，不覆盖掌握阶段。稳定要求失败后兼具复述与应用两维冷检，至少两个日期且跨度不少于 7 天，因此带背一次通过不会直接变成“稳定”。

## 写回顺序

1. 判分前拉教材原文并列关键限定语；问法失真则该发作废，不记用户的错。
2. 实际检验统一用 `evidence` 命令写入结果、维度、冷检条件、题干完整性与栽点诊断；失败/半对不得只在自然语言里写“哪里错”。命令成功后立刻运行 `node --env-file=.env.local scripts/cuoti.mjs sync`，确认同号尝试入库。新栽点建唯一 ID 后再用 `transition --event new` 留流量证据。<!-- [gpt] 2026-08-10 -->
3. 凡撤池、重挂、移交或转挑错轻滚，禁止手改完状态就停：统一用 `transition` 命令完成状态与 append-only 流水双写。已有迁移事件不得删除或改写；更正用一条新事件。
4. 真正带完一节另写 `study_log activity="背诵"`，并在 `raw_input` 保留 `[背诵方式=带背]`；用户自背汇报同样写 `activity="背诵"`，但标 `[背诵方式=自背]`。自背汇报先启动 `daibei-pc kind=progress --target <规范章节>`，再运行 `coach.mjs log --run <SR-ID> --activity 自背 --chapter <同一章节>`；同步成功后由业务脚本自动签 `progress_recorded/writeback_verified`，以 `phase=progress` 收口，不调用全盘 `skill-context`。章节效果、撤梯级与病根放 `feeling`，不要拿挂账条目替代进度流水。<!-- [gpt] 2026-08-21 -->
   普通 `progress` 收口后照常按蓝本做当日抽查，但**它是 stateless probe、不建 Run**（见下方「新章节 KP 抽查」首条）；仅用户明确要求不抽查时使用 `progress-only`。**只有跨日冷复检才另起 `kind=recall` Run**，与进度流水分开，避免章节流水目标和稳定知识点结果互相污染。<!-- [gpt] 2026-08-21；[claude] 2026-08-25 当日抽查改无 Run -->
5. 有明确复检日期时用 `schedule.mjs add` 写 `.local/复盘排期.md`；它只管何时打，不管是否过关。<!-- [gpt] 2026-08-10 --> 需要同时结案排期并撤池/重挂时，必须一次给全：`schedule.mjs done <排期ID> --result "人读结论" --recite <条目ID> --event withdraw|rehang --outcome pass|partial|fail --cold true|false --prompt clean|cued --evidence "教材/题目锚点" [--pattern <code> --diagnosis pending|confirmed --note "说明"]`。该命令会把排期、带背事实和同号尝试联动提交；随后同样运行 `cuoti.mjs sync`。`withdraw` 只接受 `pass + cold=true + prompt=clean`；`rehang` 只接受 `partial|fail`，且失败/半对必须有 `--pattern`。
6. 运行 `node scripts/daibei-ledger.mjs check`。结构错误未清零前，不对外报数量，也不写“已完成回写”。

### 新章节 KP 抽查

<!-- [gpt] 2026-08-21：正确的章节抽查不能为了满足 Run 回执而新建栽点。 -->

- ⛔ **当天汇报进度后的顺手抽查完全不适用本节（2026-08-25 云拍板）**：它是 **stateless probe**——不建 Run、不 checkpoint、不 end、四个账本一个都不写（`study_log`／`learning_attempt`+`knowledge_evidence`／`.local/带背挂账.md`／`study_error`）。**因此下面关于 `knowledge.mjs attempt`、尝试分母、`cold` 取值的规定，一条都不适用于它。**热检量的是短期记忆不是保持率，进证据链会跟跨日冷检挤同一个分母。
  取证仍要做，只是不带 `--run`：答案来源已可靠（`.local/带背标准答案.md` 有母版，或本轮此前已核过同一材料）→ 直接跑一次不带 `--run` 的 `question-integrity` 出题；来源不可靠 → 先跑不带 `--run` 的 `material`／`material-batch`，再跑 Gate。`question-integrity` 只查题干泄题、**不核验答案键对错**，所以这一步不能省（08-25《法经》第三篇《网法》被写成《囚法》即由此漏出）。
- **以下各条只适用于跨日冷复检与已约定的专项复检**：
- 冻结目标是稳定 `KP-ID`、且不是既有带背挂账复检时，用 `node --env-file=.env.local scripts/knowledge.mjs attempt <KP-ID> recall <pass|partial|fail|void> ... --run <SR-ID>` 写 `learning_attempt`。
- 脚本必须在落 outbox 前核对 `daibei-pc/recall`、冻结 KP-ID、材料回执和题面 Gate；同步成功后才签 `result_recorded/writeback_verified`。
- 跨日冷检默认按真实条件填 `cold`，进入尝试分母，不因一个子问题答对就升级整个 KP 的掌握阶段；只有既有栽点复检才继续使用 `daibei-ledger.mjs evidence`。
- ⚠️ **兼容性注记**：`kind=recall-sameday` 与 `phase=probe` 是 2026-08-25 上午短暂存在过的中间方案，**已降为 legacy，仅供历史 Run 回放，不得新建**。这类 Run 上的两条写回路都会被 `DAIBEI_SAMEDAY_PROBE_NO_WRITEBACK` 拒绝，作为防御性兜底。

## 上游报告口径

- 日报/周报/评估报的是“当前存量快照”，不能把当前 active 数冒充本周新挂量，也不能从条目当前状态倒推出本周撤账数。
- “本周新挂/撤账”只认 `flow` 的本周 append-only 迁移事件；账本没有流水时明确报 0 条可审计迁移，绝不从当前状态倒推。
- 账本解析失败或存在结构 error 时报告中止；warning 可以继续，但须点名数据债。`未查到` 不等于 `0`。
- 日报/周报同时报告排期履约、理解/复述/应用证据与接线债；结案数、通过数和证据量都不得直接写成“已稳定掌握”。
- 背诵栽点不写 `study_error`；做题中真实答错才进入错题事件/主题轴。两边同时命中时双轨独立闭环。
