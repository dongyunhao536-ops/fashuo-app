# 答疑卡点数据契约

本契约只管“什么答疑事实值得跨会话追踪”。答题证据链、教材优先级和题型结构仍以 `SKILL.md` 为准。

## 四条事实轴不要混

| 事实 | 落点 | 关键边界 |
|---|---|---|
| 普通概念提问/一次答案 | 不落账 | 问过不等于不会；`ask_summary` 不是聊天流水 |
| 跨会话仍未收口的具体理解卡点 | `ask_summary` / `ask_point_v2` | 只记录已被用户反馈或追问证实的卡点 |
| 做题、案例、考核中真实答错 | `study_error` + `error_topic` | 走错题事件/主题闭环，不用答疑卡点替代 |
| 用户明确要保存的规则/拓展 | 心得 archive 链 | 不是 ask point，也不是错题 |

## PC 命令

<!-- [gpt] 2026-08-10：答疑卡点接入稳定 KP 与 understanding 证据，clarified 不再允许直接管理改写。 -->
- `node --env-file=.env.local scripts/ask.mjs list`：只列 TTL 内有效 open。
- `node --env-file=.env.local scripts/ask.mjs list --all`：审计全部状态。
- `node --env-file=.env.local scripts/ask.mjs add --subject 刑法 --confusion "具体卡点" [--type 案例 --step 3 --kp XF-0054 --evidence partial|fail --question "原问题" --anchor "教材行号"]`。带 `--kp` 时同步生成 confirmed 对象映射与一条 understanding 缺口证据；默认 `partial`，明确完全不懂才用 `fail`。
- `node --env-file=.env.local scripts/ask.mjs verify <id> <pass|partial|fail|void> [--kp XF-0054] --anchor "检验题/教材锚点" --note "作答表现与判定理由" [--cold --cued|--invalid-prompt --schedule <排期id>]`。`--kp` 可省略的前提是 A# 已有合法 `kp_id`。
- `node --env-file=.env.local scripts/ask.mjs resolve <id> --action dismissed|superseded [--note "理由"]` 只做管理移噪/换描述；`clarified` 必须由 `verify` 的无提示通过自动产生，CLI 会拒绝直接改写。
- 写操作与错题/日志共用可靠 outbox；默认立即同步，失败保留，`--stage` 才只暂存。`ask.mjs sync` 与 `cuoti.mjs sync` 都能重试。

## 对象映射审计（维护入口，不改变答题裁判）

<!-- [gpt] 2026-08-10：个人知识图谱二期统一核查错题、主题、答疑和带背的主点覆盖。 -->
- `node --env-file=.env.local scripts/knowledge.mjs mapping-audit [科目] [--limit 20 --json]` 统一核对 `error_topic / study_error / ask_point / recite_ledger` 是否已有唯一 `confirmed primary`，并把安全直连、冲突、pending 与未连接分开报告。
- `suggest-errors / suggest-topics / suggest-recite / suggest-asks` 都是零写入候选入口。即使显示“强候选”，仍只是检索结果；多概念对象、同分候选和上下位概念不能自动压成一个主点。
- `backfill-direct [科目]` 默认只预览；仅来源事实表已经保存合法稳定 `kp_id` 时，`--apply` 才能以 `legacy_direct` 回填 confirmed。文本、Anki 或模型相似度永远不进入这条自动确认通道。
- 人工确认仍须回到原材料核对对象含义，再用 `knowledge.mjs link ... --status confirmed --method manual --confidence 100 --anchor "..."` 留证据锚；审计数字本身不是映射证据。

## 个人知识上下文（只读派生，不是第五条事实轴）

<!-- [gpt] 2026-08-10：规定答疑近窗个人关联的输入、措辞门槛与裁判隔离。 -->
- `node --env-file=.env.local scripts/knowledge.mjs context <KP-ID...> --days 30 --depth 2 --limit 3 [--json]` 聚合近 30 个北京日内的强关联事实；窗口含参考日当天，默认最多沿 confirmed `prerequisite/supports/contrast` 走 2 跳。
- 上下文只读取既有事实：confirmed 对象映射、稳定 KP 直连、真实错题、已挂 A# 和有效 `knowledge_evidence partial/fail`。同一错题已经派生出的知识证据按 source 去重，不能一份表现计两次。
- 普通提问不在事实表，所以不会被召回；dismissed 错题、dismissed/superseded/expired 卡点、`void/invalid` 证据、rejected 诊断和 pending 映射必须过滤。clarified 卡点可以作为近窗历史，但不能表述成当前仍未收口。
- “同章”不是强关系，不能单独触发个人提醒；共享一个 `supports` 父点形成的纯结构两跳也不够强，不能借父节点召回旁系旧错。每条召回必须给出同一 KP、长期主题、直接 confirmed 关系，或至少含 prerequisite/contrast 的两跳路径；查询失败不能降级成“没有历史”。<!-- [gpt] 2026-08-10 -->
- `error_topic` 继续承担可复用长期问题主题；`failure_pattern_code` 是通用栽点类型；`root_cause_note + diagnosis_status` 才是具体个人诊断。两次只称疑似，跨至少 2 个 KP 的 3 次 confirmed 失败才称反复模式，具体病根仍须用户认领才能 confirmed。
- 上下文只决定讲解顺序与教学动作，不能改变本题法律裁判、知识阶段或任何持久化状态；其输出不得反向写入错题、A#、心得或证据表。

## 什么时候新增

- 不因用户“提出了一个问题”就新增。至少出现一种证据：用户明确说仍没懂/仍混淆；追问暴露同一错误模型；一次不带答案预输入的理解检查未过。
- confusion 写“他把 A 当成 B，缺哪把尺”，不要写“问了 X”、检索没命中、题干笔误、老师自我纠错或泛泛章节名。
- 同一追问链在收敛时，旧卡点显式 `superseded`，再写更准确的新卡点；不要一天按科目批量顶掉无关卡点。
- 做题中真实答错可同时暴露 ask point，但通常优先写错题事件/主题；只有“答案已讲清、理解链仍卡住且需下次续讲”才另挂 ask point。

## 状态与 TTL

- `open`：仍需跨会话续讲；只有 TTL 未过期的 open 才是 `ask_point_v2.active=true`。
- `clarified`：只在 `ask_verification` 已先写入 `understanding/pass + prompt_integrity=clean` 后产生。`cued pass` 只留证据、继续 open；无效题面写 `void + invalid`；刚读完答案、跟读复述和口头说“懂了”都不自动销疑。
- `dismissed`：确认不是用户卡点（系统噪音、题干问题、老师误判）。
- `superseded`：同一问题被更准确的新卡点替代，不等于已掌握。
- `expired` 是视图计算状态，只表示 90 天后停止自动注入，**绝不表示 clarified**；评估可报告数据过期，不能报“已解决”。

## 报告口径

- 周报报“本周新增答疑卡点”，绝不能叫“答疑次数”；普通提问不入表，所以这张表无法统计总答疑量。
- 学习性闭环只认 `clarified`；`dismissed` 是移噪，`superseded` 是换描述，三者分开报。
- 日报/教练/首页只展示有效 open；阶段评估另报 expired 数据债，但不能把过期条目塞回当前行动池。
- 查询失败时中止，不能把 null 输出成 0。

## 一致性红线

- `ask_verification` 是一个可重试复合 outbox 操作，固定按“核对 A#↔KP → confirmed link → knowledge evidence → clean pass 时 clarified”执行。证据写入失败时不运行 clarified；重试靠 operation_id 幂等。
- 带 `--schedule` 时先核对排期 `ref`、`route=ask-pc`、`dimension=understanding`（旧排期缺元数据可兼容，但声明了就必须匹配）；数据库证据同步成功后才回写排期。
- ask 卡点只负责“理解是否收口”；后续 recall 交 `daibei-pc`，application 交 `cuoti-fupan`。一个 understanding pass 不得写成知识点 stable。
