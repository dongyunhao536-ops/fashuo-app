# 答疑卡点数据契约

本契约只管“什么答疑事实值得跨会话追踪”。答题证据链、教材优先级和题型结构仍以 `SKILL.md` 为准。

## 四条事实轴不要混

| 事实 | 落点 | 关键边界 |
|---|---|---|
| 普通概念提问/一次答案 | 不落账 | 问过不等于不会；`ask_summary` 不是聊天流水 |
| 跨会话仍未收口的具体理解卡点 | `ask_summary` / `ask_point_v2` | 只记录已被用户反馈或追问证实的卡点 |
| 做题、案例、考核中真实答错 | `study_error` + `error_topic` | 走错题事件/主题闭环，不用答疑卡点替代 |
| 用户明确要保存的规则/拓展 | 心得 archive 链 | 不是 ask point，也不是错题 |

## PC 命令

- `node --env-file=.env.local scripts/ask.mjs list`：只列 TTL 内有效 open。
- `node --env-file=.env.local scripts/ask.mjs list --all`：审计全部状态。
- `node --env-file=.env.local scripts/ask.mjs add --subject 刑法 --confusion "具体卡点" [--type 案例 --step 3 --kp ... --question "原问题" --anchor "教材行号"]`。
- `node --env-file=.env.local scripts/ask.mjs resolve <id> --action clarified|dismissed|superseded [--note "证据"]`。
- 写操作与错题/日志共用可靠 outbox；默认立即同步，失败保留，`--stage` 才只暂存。`ask.mjs sync` 与 `cuoti.mjs sync` 都能重试。

## 什么时候新增

- 不因用户“提出了一个问题”就新增。至少出现一种证据：用户明确说仍没懂/仍混淆；追问暴露同一错误模型；一次不带答案预输入的理解检查未过。
- confusion 写“他把 A 当成 B，缺哪把尺”，不要写“问了 X”、检索没命中、题干笔误、老师自我纠错或泛泛章节名。
- 同一追问链在收敛时，旧卡点显式 `superseded`，再写更准确的新卡点；不要一天按科目批量顶掉无关卡点。
- 做题中真实答错可同时暴露 ask point，但通常优先写错题事件/主题；只有“答案已讲清、理解链仍卡住且需下次续讲”才另挂 ask point。

## 状态与 TTL

- `open`：仍需跨会话续讲；只有 TTL 未过期的 open 才是 `ask_point_v2.active=true`。
- `clarified`：用户后续能独立解释、辨析或应用，或明确确认已打通；刚读完答案、跟读复述不算证据。
- `dismissed`：确认不是用户卡点（系统噪音、题干问题、老师误判）。
- `superseded`：同一问题被更准确的新卡点替代，不等于已掌握。
- `expired` 是视图计算状态，只表示 90 天后停止自动注入，**绝不表示 clarified**；评估可报告数据过期，不能报“已解决”。

## 报告口径

- 周报报“本周新增答疑卡点”，绝不能叫“答疑次数”；普通提问不入表，所以这张表无法统计总答疑量。
- 学习性闭环只认 `clarified`；`dismissed` 是移噪，`superseded` 是换描述，三者分开报。
- 日报/教练/首页只展示有效 open；阶段评估另报 expired 数据债，但不能把过期条目塞回当前行动池。
- 查询失败时中止，不能把 null 输出成 0。
