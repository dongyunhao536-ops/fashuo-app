# PC 周报生产（升级版 · 火力全开 · 周报只在 PC 生产、APP 只展示）

生成前先读 `../_shared/学习事实层.md`、`../_shared/智能教练契约.md` 与 `../_shared/报告展示契约.md`。周报的错题段必须分开写事件销账数、主题冷复检证据和主题掌握状态。<!-- [gpt] 2026-08-10 -->

云 2026-07-06 定：**手机 APP = 应急 + 展示；周报只在 PC 生产、APP 端展示、PC 质量更高**（[[pc-primary-two-systems]]）。这里由当前 Codex 使用全账本和完整可用推理强度，写出比 APP 自动稿更狠更准的周报，落进共享 `weekly_report`（APP 页读它渲染，零 APP 改动就显示我的）。

## 工作流程
1. `node --env-file=.env.local scripts/weekly.mjs data [--week YYYY-MM-DD]` —— 算本周真实数据并存 `.local/weekly-data.json`。<!-- [gpt] 2026-08-10 --> 除学习流水/错题/答疑/待办/成本外，数据已含：结构化排期按 `route/dimension` 的应验收、截周完成、未完成、本周实际结案和旧欠账；带 `plan_*` 的 P0/P1/P2 严格兑现率与控制器模式；理解/复述/应用证据及 L4/限时/成套模考计数；带背唯一主 KP 接线率与接线债。默认本周（北京周一~周日）。
2. 再 `coach.mjs ledger` 补全上下文，并运行 `node --env-file=.env.local scripts/coach-engine.mjs snapshot` 读取七阶段分布、下周到期与科目风险排序；风险分只解释复检优先级，不当卷面预测。读取 `.local/日报台账.md` 本周 7 块核派单执行率。`weekly.mjs data` 已内置带背**当前存量快照 + 本周 append-only 迁移流水**；本周新挂/撤池只认 `flow`，没有流水就报 0 条可审计迁移，绝不倒推。复盘排期的 `route/dimension` 只说明由谁检验哪一维，结案只算履约；三维 evidence 只算观察事实，两者都不能单独写成“已掌握”。新排期用 `schedule.mjs add` 回写同一文件，完成用对应执行 skill 的证据命令再结案，旧散文只作历史证据。
3. **我据真实数据写决策型周报** → `.local/weekly-draft.md`（严格四层格式见下）。若 `controller=constrained/recovery`，不安排 P2 且 P1 最多 1 件；若为 rescue，只保留 P0。降的是并发，不是 P0 验收标准。<!-- [gpt] 2026-08-10：展示改为判定→变化→作战卡→证据 -->
4. **把“下周指导”逐件物化成验收单元**：每件用 `schedule.mjs add` 写稳定 `--id/--plan W<下周一>-<优先级>-<序号> --week <下周一> --source weekly --weight 1`，截止日必须在该周；知识检验同步写 `route/dimension`。重跑复用同一 ID，不能因重跑重复造计划。没有这一步，周报只是散文，控制器也没有分母。<!-- [gpt] 2026-08-10 -->
5. `node --env-file=.env.local scripts/weekly.mjs save --file .local/weekly-draft.md [--week ...]` —— upsert 到 `weekly_report`（week_start 覆盖），APP 叙事卡即刻展示。

## 叙事铁律（零编造 + 权威）
- **只据 `weekly.mjs data` 的真实数据复盘**：科目/考点/次数/事件销账数/主题复检数必须与数据一致；数据为空（0 复盘/0 销账/0 冷检/某科没动）就如实说“本周没有”。`absorbedErrors` 是事件闭环，不是弱项稳定；只有 `error_review` 能支撑 monitoring/stable。
- **执行、证据、状态三账分开**（[gpt] 2026-08-10）：排期完成率回答“该做的是否按时做”；三维证据回答“观察到了什么表现”；知识状态机才回答当前阶段。提示通过、作废题干、零/歧义 KP 接线必须单列，不得塞进干净通过分子；接线债只提出人工核验任务，周报不得自动确认映射。
- **稳定与考试就绪分开**（[gpt] 2026-08-10）：稳定只证明跨日复述+应用仍可依赖；考试就绪还要跨日 L4 陌生/综合题冷通过并至少一次限时/成套模考。周报只能报告本周证据计数，不能把 L4 次数换成胜率。
- **分清真进展 vs 真问题**，对照云病根（启动晚/从不复盘/重复犯老错）+ 方法论优先级（复盘 > 错题闭环 > 模考 > 进度铺开）给判断，该泼冷水就泼，别和稀泥。
- **下周指导可执行**：落到在职双轨具体时段（工作日早/通勤/晚、周末）+ 点名下周先攻哪几个弱项考点 + 背哪一轮哪些范围 + 何时模考/复盘；挑最关键 3-5 件、别列十条。学法/背诵法/题型打法建议参考 `docs/方法论/`（各科方法论详版·据真题高频与云病根定制）。
- **周报定位＝当周宏观指导标准（云 2026-07-13 定）**：「下周指导」不是建议清单，是接下来一周的作战标准——周中 coach/daibei/cuoti 做规划、排任务都对齐它，偏离要有理由。因此写它时要过三关：
  1. **兼顾全周期、不只看当下**：把本周放进全局——轮次表当前应在阶段与死线（基础结业 9-30、初试首日 **2026-12-19**）、**尚未铺开或推进过低的科目**（每次从 ledger、日报台账与用户最新确认现查，禁止沿用固定名单）、`config/coach.json` 目标分反推——推进快的科目别惯性加码，全局欠账要点名进指导。
  2. **优先级由我明确分档**：每件事标 P0/P1/P2——P0=本周必须完成的红线（不超过 2 件，完不成下周报点名）、P1=应做、P2=有余力再做。冲突时舍 P2 保 P0，别让云自己猜轻重。
  3. 分档理由一句话说清（为什么它是 P0），扣病根或死线，不空排序。
- **下周指导写完即成为日报的派单源（2026-07-28 起）**：日报每天 17:20 只从这份 P0/P1 里派单、不另立标准。所以①每件的**验收标准必须可判定**（"民法推进"日报没法判，"第一章听完+分章真题做完且栽题入账"能判）；②每件要**落到双轨的哪个时段**（工作日晚/早/通勤/周末上午），日报按时段派、时段冲突时不硬塞。写得含糊，日报就只能含糊地派、周报也就白写了。
- **投入趋势用"深度动作占比"说话（2026-07-17）**：时长不记（云拍板），但裸动作数会把"10 道水题"说得比"1 场两小时深复盘"更勤奋——叙述投入时配上 **深度动作（复盘+带背+成段输出）÷ 全部动作** 的占比讲质量，动作数只当量的参考。
- 扣**死线**（距基础结业死线/距初试）和**弱点模式**（[[yun-weakspot-exceptions]] 例外/边界）说话；纯法硕口径 [[fashuo-only-no-fakao]]。
- **「答疑卡点」段口径**：APP/PC 已统一写 `ask_summary`，`weekly.mjs data` 报的是**本周新增卡点**与当前有效 open，绝不是总答疑次数。学习性闭环只认 `clarified`；`dismissed` 是移噪、`superseded` 是被更准描述替代、TTL `expired` 只是停止注入，四者不能混成“解决”。
- **政治哨兵（9 月起）**：政治 Rule8 云自管，但 9 月起周报全局项每周带一句"政治启动/进度？"——只提醒不管辖（时长、模拟两条红线"没人盯就蒸发"的教训）。模拟分落 `config/coach.json`「模拟分记录」，9-26 之后的周报必读它对 320 红线。
- **用上"带背/学习效果"+上周周报**（`weekly.mjs data` 2026-07-07 起已含，见 [[daibei-skill]]）：复盘要读【带背/学习效果】段的**掌握轨迹**（云每节掌握到什么程度、盯哪些精度点），据此定"下周精度重点"；并对照【上一份周报】的"下周指导"看云本周**落实了没/欠了啥**，做到**周与周衔接**、别孤立地只讲本周。

## 输出格式（写进 weekly-draft.md，纯 markdown，学长口吻、大白话、无客套）
```
## 本周结论
> 🟢/🟡/🔴 <P0 严格兑现率 + controller 模式 + 一句话判断>

## 本周变化
### 做对了
- <最多 3 条真正改变趋势的进展>
### 偏航了
- <最多 3 条会改变下周安排的问题>

## 下周作战卡
### [P0] <动作名>
- 截止/时段：...
- 验收：...
- 理由：...
（P0≤2；总计 3~5 件；每件只出现一次）

## 证据附录
- <计划兑现、错题两轴、知识迁移、带背与数据异常的紧凑表/短句>
```
禁止再写“先对五件账→四个真进展→四个真问题→五件指导→全局项→一句话钉死”的重复长链；结论只在开头出现一次。<!-- [gpt] 2026-08-10 -->
