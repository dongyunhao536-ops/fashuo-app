## 1. 一句话定位

**一个给单一用户（"云"，在职、五战法硕、目标北大 375+）私人定制的、"越用越强"的法律硕士（非法学）备考系统——2026-07-06 起为「PC 主系统 + APP 应急展示」双体架构。**

- **PC 主系统**（Codex Desktop/CLI · 完整可用推理强度·零额外 API 成本）：九个 skill（教练/答疑/错题复盘/带背/主观题/日报/周报/评估/英语）覆盖全部学习动作，直读写共享账本，判题答疑强制"先检索教材原文、带行号佐证"。
- **APP**（ECS 自托管 PWA）：降级为**应急 + 只读展示**（今日页量化 v3、周报叙事卡）；其答疑/教练仍可用但自 07-08 起休眠。
- **同一本共享账本**（Supabase/PostgREST）：学习流水、错题本、长期记忆、周报，两套系统共读写，让每次做错、每次复盘、每次带背栽点都沉淀成可复利资产。

## 3. 系统形态

> **2026-07-06 架构大转向、2026-08-04 执行器迁移**（[[pc-primary-two-systems]]）：PC（Codex）＝主系统火力全开，APP＝应急+只读展示；两套共享同一 Supabase 账本。PC 规则升级以 `.agents/skills` + `AGENTS.md` + `scripts/` 为准，**绝不因 PC 教学规则变化顺手改 APP `src/`**。

                └──────────────────────────────────────────────────────────────┘
                     ▲ 实时直写（写完即 sync·不部署）              ▲ 只读展示
   ┌─────────────────┴────────────────────┐          ┌───────────┴──────────────┐
   │ PC 主系统（Codex · 完整可用推理强度）     │          │ APP（ECS PWA · 应急+展示）  │
   │ 九 skill：coach-pc 教练 / ask-pc 答疑    │          │ 今日页＝量化 v3 综合指数     │

- **九个动作（PC skill）**：宏观教练、证据链答疑、错题出题销账、带背+理解层检验、主观题、日报、周报、全周期评估、英语私教——分工与互转规则写在各 SKILL.md 的「分工」节，互不打架。<!-- [gpt] 2026-08-10 -->
- **一本共享账本**：PC 写、APP 读，实时同步不需部署；唯一例外是「心得/内容」走 fashuo-archive git 提交 + content_mirror 同步链。
- **分轴本地台账**：`.local/带背挂账.md` 管背诵事实，`.local/复盘排期.md` 管验收与计划归属，`.local/日报台账.md` 管日执行，`.local/概率预测台账.md` 管百分比预测及结果；每类事实只有一个主人，不合并成万能总表。<!-- [gpt] 2026-08-10 -->

- `events` 待办筐总线仍在（APP 答疑沉淀候选），随 APP 休眠已低频；PC 直写是主通道。

## 4. 飞轮模型

"越用越强"是**架构属性**，不是功能。账本 + 契约从 day-1 就在，模块增量上线。**现役闭环（2026-07 形态）**：

| 闭环 | 链路 | 防"假掌握"机制 |
|---|---|---|
| **错题闭环** | 栽题当场 `add` 入账 → cuoti-fupan 真题级出题考核（不换壳·先正中原始错因·按病根窝打包）→ 真掌握才 `absorb` 销账 → **已销账老题进 `recheck` 全覆盖轮换池（永不淘汰）**，抽查栽了带 🔁 复发重挂 | [gpt] `absorb` 双层重验：最近失败后至少两条带依据的 clean L3+ 应用通过、两个验证轴且至少一次冷检；一次答对/同轴换措辞/当日新错均拒绝。误销账用 `reopen --reason` 行政恢复，不伪造失败 |
| **带背挂账闭环** | 带背栽点入 `.local/带背挂账.md` 台账 → 每次带背开场抽 3~5 条复检（含 1 条已撤池轮换）→ 后续复检✓才撤账 | **改对当次不算过关**；连败≥2 需连续 2✓；3✗ 转专项 |
| **知识点证据闭环 v3** | 稳定 `kp_id` 关联错题/带背/答疑对象 → 理解、复述、应用表现证据 → 分开重算历史阶段、今日阶段与考试就绪 → confirmed 前置图谱排序 → 按考试日失分压力定向派单 | Anki 只作材料/重要度参考；稳定≠考试就绪；考试就绪另需跨日 L4 冷应用 + 限时/成套模考；风险指数不是概率，未观测点不是弱项 |
| **干预响应闭环 v2** | 定向派单固化上下文与具体 `protocol@version` → episode 即时执行 → 通过后串行 D3→D14→D30 → 按协议重算长期响应 → 保守探索/利用选下一种教法 | [gpt] 同一路由不同教法不混算；失败立即停止旧 episode；D14/D30 才能支持协议；观察性响应不冒充因果效果 |
| **周报对表闭环** | weekly-pc 周一自动产周报 →「下周指导」逐件写入带 `plan_*` 的结构化 P0/P1/P2 验收单元 → 日报派单 → 下周周报按截止时点对账 | 连续两周 P0<60% 自动冻结 P2/限 P1；连续三周进入 rescue；降负载不降 P0 标准 |
| **评估审计闭环** | pinggu-pc 月度体检（每月 1 号定时）→ 处方绑进当周周报分档 → **下次评估开篇审计上次处方执行率+里程碑** | 零编造、数字全可溯源；375 目标反推 |
| **模考红线闭环** | 首次模拟 2026-09-26（config 写死+ledger 倒计时）→ SOP 判分 → 分数落 config「模拟分记录」→ 周报/评估对 320 红线 | 分数不落账=红线蒸发（时长红线的教训） |
| **概率预测校准闭环** | 同口径完整模考 N<3 只报结构、N=3~5 只报趋势区间、N≥6 才报科目达标概率 → 按新证据版本幂等落概率台账 → 目标日 0/1 对账 → Brier/偏差/分桶回测 | 禁止从风险分编概率；禁止把分科概率拼上岸率；低样本明确拒答 <!-- [gpt] 2026-08-10 --> |

> **历史闸门（已冻结存档）**：背诵检测时代的 G1/G2/已强化/L1-L3 升降档（`kp-transition.ts` 已删）随 2026-06-29 模块下线；`detection_log` 与 `kp_state` 的旧 mastery 字段冻结。`kp_state` 中 933 个稳定 ID、名称和教材/Anki 元数据现仅作为 `knowledge_point_v2` 目录底座；新掌握结论全部由表现证据重算，v3 再按参考日派生当前可依赖阶段。<!-- [gpt] 2026-08-10 -->

## 6. 部署与运行架构

云在 2026-06-09 拍板**阿里云 ECS 自托管**（首年 ¥9/月），2026-06-11 上线。理由：最便宜、中国大陆访问最稳、七牛云 RPM 天花板不归部署平台管。代价：备案 0 天（纯 IP + 自签证书 + iPhone 信任根证书绕过）+ 自己运维。

```
INTERNET
  │ https://47.103.148.124:8443   （阿里云安全组只放行 22 + 8443；自签 TLS）
  ▼
ECS (Ubuntu 22.04, 2 核 2 G)
  ├─ nginx :8443  TLS 反代两路
  │     ├─ /rest/v1/*  → PostgREST :3001
  │     └─ /*          → Next.js   :3000
  ├─ Next.js production (pm2，进程名 fashuo)
  ├─ PostgREST (systemd，单二进制) ← Supabase API 100% 兼容
  ├─ PostgreSQL 15 (systemd，仅 localhost)
  └─ cron 运维四件套 + pg_dump 日备份 → /backups/

内存预算：PG 200-300M + PostgREST 40-80M + Node 400-700M + 系统 200-300M
        峰值 ≈ 1.0-1.4 GB / 2 GB（富裕）
```

## 8. 核心子系统详解

### 8.1 内容镜像与 grep 工具链

**`src/lib/search-tools.ts`** 是整个系统的"证据地基"。答疑/评分前必须先检索教材/心得/真题，回答带 grep 命中**真实行号**；无 grep 痕迹则信心度 -20% + 标★。

三个工具（Claude tool-use）：
- `search_textbook` — 检索《考试分析》教材原文
- `search_xinde` — 检索刑/民做题心得（**答疑第一优先级**）
- `search_zhenti` — 按年份(+题号)检索真题

实现要点：
- grep = **逐行子串匹配**。命中行连同 ±2 行上下文合并成块，`base+i` 行号用 `content_mirror.start_line` 校准回源文件真实行号。
- **[gpt] 世代同步**：`sync-content.mjs --dry|--dry-run` 先核验完整 scope、封存排除项、钉死资产与三类 SHA-256；正式同步只写 staging，数据库在一个事务中校验完整性、替换 active 并清空 staging。读端不会看到半个世代，移出白名单的旧路径不会继续幽灵命中。
- **[gpt] 来源层级**：每行带保守的 `source_level`（S1-S4/mixed/unclassified）和内容哈希，用于检索溯源与版本审计；层级只描述材料来源，不改变《考试分析》→讲义→真题的最终裁判顺序。
- **per-request `MirrorCache`**：一次答疑 12 条检索，每个 `kind` 只从 Supabase 拉一次（否则每个关键词全量下载五本教材，是延迟大头）。
- ⚠️ **七牛云/Bedrock 约束**：工具参数名（property key）必须 ASCII（`^[a-zA-Z0-9_.-]{1,64}$`），中文 key → 400。故 key 用 `keyword`/`year`/`question_no`，描述照样中文。
- ⚠️ **关键词硬规则**（贯穿出题/评分/答疑规划器）：关键词必须是**单个连续短词、不含空格**（2-6 字法律术语最佳）。"债务转移 担保" 这种带空格的词几乎零命中，必须拆成两条。这是 L2/L3 真实验收（2026-06-09）暴露的坑——用完整考点名当 keyword → grep 全空 → 评分无锚退化违反红线。

### 8.1A 知识点事实层 v3（现役·[gpt] 2026-08-10）

- **身份**：复用 `kp_state` 的 933 个稳定 ID 建 `knowledge_point_v2`；旧 L1/L2/L3/mastered 不参与任何现役判断。
- **材料映射**：Anki 抽取库有精确卡时标 `exact`，只有同章卡时标 `section`；用于别名、来源、重要度和覆盖提示，`masteryImpact=none`。自动建议不自动确认。
- **对象映射审计**：`mapping-audit` 以事实轴分别统计 `error_topic / study_error / ask_point / recite_ledger` 的 confirmed 主点、主题继承、pending、冲突与未连接；`suggest-*` 永远零写入。`backfill-direct --apply` 只接受来源表已有合法稳定 `kp_id` 的无推断迁移，文本/Anki/模型候选不得借此转 confirmed。<!-- [gpt] 2026-08-10 -->
- **表现证据**：`knowledge_evidence` 记录 `exposure/understanding/recall/application × pass/partial/fail/void`，并保留 cold、题干完整性、变式迁移等级、普通/限时/成套模考环境、时长、栽点代码、诊断状态及证据锚。带背事实仍唯一落 `.local/带背挂账.md`，经 confirmed 对象映射实时派生，不双写 DB。<!-- [gpt] 2026-08-10 -->
- **尝试分母**：`learning_attempt` 记录每次真实作答、复检或考核，不论通过还是失败；`result=void` 留审计但不进有效分母/得分率，`attempt_role` 分开首稿、重写、复检和跟进。非 manual 来源要求稳定 source ID，客观/主观作答还要求题号与 score/max；英语、主观题、带背从新事实开始接入，严禁从历史 accuracy/批语猜测回填。带 `kp_id` 的通用尝试可在同一事务投影 `knowledge_evidence`。<!-- [gpt] 2026-08-10 -->
- **摄取审计**：可靠 outbox 的每个操作先登记 `ingest_operation`；`operation_id` 相同而 payload 哈希不同会被数据库拒绝，已成功操作重放只返回原结果，失败状态与错误信息保留供恢复。<!-- [gpt] 2026-08-10 -->
- **历史与当前阶段**：`demonstratedStage` 保存历史最高可证明阶段；`stage` 表示参考日仍可依赖的阶段。四维按最近 clean pass、实际“通过→失利”间隔和跨日成功间隔派生 `fresh/due/decayed`；无个人样本时使用低置信默认半衰期。历史证据不删除，`retentionIndex` 只作调度，不是记忆概率。
- **稳定与考试就绪**：提示后通过不推进、作废题不计、新失败可降级；稳定须最近失败后 recall 与 application 两维干净冷检，至少两个日期且跨度 ≥7 天。考试就绪在稳定之上再要求至少两个日期的 L4 陌生/综合应用冷通过及一次限时/成套模考。时间经过后历史稳定仍保留，但当前稳定可以衰减回落。<!-- [gpt] 2026-08-10 -->
- **知识图谱**：`knowledge_relation` 保存 prerequisite/supports/contrast。只有 manual/curated/textbook 来源、带锚点的 confirmed prerequisite 会阻塞目标；pending/model/catalog 候选不参与派单。数据库和 CLI 双层禁止自环与 confirmed 前置环，目标受阻时自动派最深链上的根前置。刑法总论二期把正当化事由、停止形态、罪数形态和自首/立功的直接教材关系接入图谱；章节成员关系使用 `supports`，不冒充学习前置。<!-- [gpt] 2026-08-10 -->
- **个人知识上下文**：`knowledge.mjs context <KP-ID...>` 在当前教材结论已经独立确定后，沿 confirmed 关系最多 2 跳召回近 30 个北京日的错题、答疑卡点和有效失败表现；按 source 去重并给出每条关联理由。直接 supports 可用，但“成员 → supports 父点 → 旁系成员”的纯结构两跳不构成强关联，避免把同类目录误报成相似错误。两次只称疑似，跨至少 2 个 KP 的 3 次 confirmed 失败才称反复，具体病根仍以用户认领为准；该视图只改讲法、不改裁判或持久化事实。<!-- [gpt] 2026-08-10 -->
- **失分前瞻与预测**：用考试日前自然衰减、近 28 天结构化复检供给、考点重要度、前置缺口和活跃栽点给已激活 KP 排 `lossRiskIndex`，它永远不是概率。未激活高重要度点只列观测盲区；完整同口径模考 N<3 不报分，N=3~5 只报趋势区间，N≥6 才用 `ols-normal-v1` 报科目目标达成概率、区间和信心，并自动进入概率台账等待 Brier 回测。<!-- [gpt] 2026-08-10 -->
- **冲刺与画像**：“冲刺”是考前独立调度通道，不覆盖阶段。栽点 `pending → confirmed/monitoring → retired` 由证据重算；科目级习惯需 ≥3 次 confirmed 失败且跨 ≥2 个知识点，退役需失败后两次定向干净冷检、跨度 ≥7 天。
- **入口**：`npm run knowledge -- stats|search|show|graph|context|forecast|portrait|patterns|suggest-recite|suggest-topics|suggest-errors|suggest-asks|mapping-audit|backfill-direct|link|relate|attempt|evidence|sync`；`npm run forecast -- summary|due|resolve|check` 管概率回测；`coach-engine.mjs snapshot` 把当前阶段、考试就绪、图谱、画像、失分前瞻、控制器与既有错题/带背对象合成可审计派单。<!-- [gpt] 2026-08-10 -->

### 8.1B Learning Intelligence 干预响应层 v2（现役·[gpt] 2026-08-10）

- **受控协议**：`scripts/lib/intervention-protocols.mjs` 把具体教法登记为稳定 `protocol@version`，包含适用栽点、owner route、检验 dimension、执行说明与优先级。`route/dimension` 只说明“谁验哪一维”，不再代替方法本身；边界对照、单变量反事实、陌生案例迁移等可在同一路由下分开比较。
- **事前快照**：自动排期保存 `subject/kp/pattern/pattern_scope/intervention/episode/protocol/protocol_version/window/baseline_risk/expect`。粗 `intervention` 用于兼容策略审计，episode 中的 protocol、病根、对象和基线均不可事后改写。
- **串行观察**：immediate 真实结案后写 `episode_start`；只有干净通过才生成 D3，D3 干净冷通过才生成 D14，D14 通过才生成 D30。窗口表示最早可检日，禁止提前；partial/fail 停止旧 episode，避免提前铺满排期或低响应后机械重复。
- **带背兼容**：immediate 干净通过可照旧撤池；后续通过用 `schedule.mjs done --event observe` 只追加 `recite-evidence-v2`，失败才 `rehang`。因此长期观察不会反复制造撤池迁移。
- **两级重算**：`interventionResponse.items` 继续按“栽点 × route × dimension”给粗策略视图；`interventionResponse.protocols` 按“科目 × 栽点 × protocol@version”以 episode 为单位输出 immediate/D3/D14/D30 的成熟、可评估、通过、缺测与保守分。
- **长期门槛**：少于 3 个 episode 或未跨 2 个知识点保持 `collecting`；只有 D14/D30 至少 3 个可评估 episode、通过率 ≥67%、至少 2 次且跨 2 点通过才是 `supported`。即时或 D3 表现再好也不能提前宣称长期有效。
- **保守选策**：先让兼容协议各留个人样本；出现长期 supported 后按确定性 80% 利用、20% 确认性探索，防止旧优势永久固化。`needs-redesign` 在有替代时避开，但不等于病根被证伪、学生学不会或 owner 失效。
- **解释边界**：所有结果仍来自单人观察性数据；Wilson 下界只用于小样本排序，失分风险变化只报伴随信号。协议响应不替代知识点稳定、栽点退役、掌握概率或卷面分。

#### 升降档状态机 `src/lib/kp-transition.ts`（已删）

`difficulty` 是"忘性指数"（错/勉强累加、稳过递减），决定可达的最高间隔档（**难度门控 `rungCap`**：D≤6→30 天 / D7→15 天 / D8→7 天 / D≥9→3 天），防"半生不熟的卡漂到 30 天间隔"。

| 评分 | 难度 | 间隔 | 档级 | status |
|---|---|---|---|---|
| **干净通过** | −1 | 升一档（≤门控）；**重学档**(刚挂过)只"确认"不放长 | 当前 < 封顶则升档 | passed |
| **勉强** | +1 | 按通过推进一档（受更紧门控）；重学档不放长 | 不动，不计 mastered | untested |
| **未过（遗忘）** | +2 | 真题**高频**砸回 1 天档；中/低频退两档 | 不动，error_count+1 | failed |

间隔档 `[1, 3, 7, 15, 30]` 天。`mastered` = 按 `cap_level` 对应档全 passed；失手会复算掉 mastered → 回炉。**考前收敛**：距初试 ≤35 天起，有效间隔压到 ≤ 距考天数×0.5，确保高频/已掌握考点考前还能滚到（否则 30 天间隔排到考后）。

#### 调度器 `src/lib/scheduler.ts`（纯逻辑、零 LLM）

**今日清单 = 三段式 bucket**，按优先级裁剪：

1. **复验（G2）** — 最高优先，全部纳入
2. **到期复习** — 复习过且 `isDue`（距上次 ≥ 有效间隔，到期当天即纳入），按 P 降序
3. **新考点** — **科目轮转**引入（5 科按 `刑→民→法理→宪→法史` round-robin 交错，各科内按章节顺序），让法综 day-1 即进清单，不被刑民挤到数月后

**优先级公式**（外置 `config/scheduler.json`，调参不改代码）：
```
价值 V = w1·真题频率(3.0) + w2·弱项加权(2.0) + w3·科目权重(1.0)
紧迫度 U = max(0, 距上次复习天数 / 有效间隔 − 1)
排序分 P = V × (1 + U)        ← 加权和×门控，防纯乘法归零
```

**阶段开关**（全局模式，按日期切换）：知识体系铺开（当前）→ 高频+弱项优先（2026-09-01）→ 纯弱项+主观题模板（2026-12-07）。不同阶段科目权重不同。

所有日期计算走**北京日历日**（`bjDateStr`），消除"按 UTC 时刻算"导致的凌晨 0-8 点到期抖动。

#### 为什么是"两段式"

原始多轮 agentic loop 在七牛云 RPM（≈1 请求/分钟）下，一道案例题 4 轮工具循环要 **6.5 分钟**、¥1.40。改"两段式"后降到 ~2.55 分钟、¥0.74（−61% 时间、−47% 钱），且绕过七牛云"带 tools 时缓存失效"的坑：

```
① 规划器（小调用，Sonnet 4）：读题 → 判科目 + 列检索词 JSON，不作答
        ↓
② 本地一次性跑完所有 grep（共享 MirrorCache，封顶 12 条）
        ↓
③ 作答（大调用，Opus 4.8 不降级）：把全部 grep 结果喂回 → 按 v2.3 证据链作答 + META
封顶 2 次 LLM 调用（规划零产出重试一次，封顶 3 次）
```

健壮性双保险：规划模型渠道失效 → 退回作答模型规划；规划零产出 → 用作答模型重试。

#### v2.3 证据链作答规范（`buildAskSystemStable`）

核心信任机制：**绝不允许"我知道答案直接答"，凡结论必须可追溯到教材原文/真题题号/心得规则**。

- **答疑优先级**（禁止越级）：① 心得 → ② 真题 → ③ 教材《考试分析》→ ④ 法条 → ⑤ 司法解释
- **六步预检清单**（第一段固定输出，填真实检索结果）：问题归类 / 心得检索 / 易混检索 / 教材锚定 / 真题锚定 / 法律更新
- **按题型作答结构**：案例→四段式（结论/法理依据/涵摄/后果）；概念辨析→三段式；选项排除→逐项过；简答→关键词踩点版
- **必备机制**：触发词升级法律更新必查、多主体×范围矩阵、信心度 0-100%（<70% 提醒核对、<50% 标★⚠️）
- **末尾固定附「证据卡」** + **机器可读 META 块**

#### 沉淀（飞轮接线）

答案末尾的 `<<<ASK_META{...}>>>` 块被 `splitMeta` 抽出并从展示文本剥离，`sinkProposals` 据此沉淀：
- `weak_candidates`（从严，至多 2）→ `events(弱项候选)`

- `confusion` → `ask_summary`（90 天 TTL，下次同 subject 答疑检索式注入跨会话记忆）

**防灌筐二道闸**：`screenCandidates`（去太短/批内重复/封顶）+ `recentlyHandled`（30 天内已 confirmed/consumed/dismissed 的同候选不再投）。设计原则：**宁可漏投，不要灌筐**——待办筐是云手动复核的，噪音 = 负担。

#### 流式心跳

案例题 Opus 可达 2-3 分钟，手机蜂窝网会掐断静默长请求，故 `streamJson` 持续吐字节保活（`stream-response.ts`）。客户端断开（"停止思考"）→ `req.signal` 透传到 SDK，真正中止上游 Opus 调用、省下那次钱。

### 七牛云（Bedrock 转售）实测约束 —— 全部踩坑后定论

> 这些是反复真实付费探针得出的硬约束，改不动，写进代码注释和模型层备注，避免重复踩坑。

1. **`effort=high` 旋钮无真实效果**：`output_config.effort` / 顶层 `effort` 在七牛云从旧版 400 变成"200 但静默忽略"（无 thinking 块、token/延迟同 baseline）——比 400 更坑（造"已调高"假象），**一律不传**。答疑已在真实最强档，无更高旋钮可调。
2. **thinking 旋钮**：原生 `/v1/messages` 路径下 `thinking.effort` 全是死的；Opus 4.8（Bedrock）只能用 `adaptive`，且思考内容被七牛云抹空（redacted）、案例题 ROI 负（延迟/成本翻倍、质量改善微弱）→ **答疑作答默认不开**。
3. **带 tools 时 prompt caching 读取失效**：`cache_write($6.25/M) > input($5/M)`，缓存比不缓存还贵 ~8% = 净亏损。故答疑/评分这类**必带 grep 工具**的调用**一律不设缓存断点**，走纯 input 最省。两段式答疑两段都**不带 tools** → 重新启用缓存（无 tools 的 system 缓存烟测验证过 `cache_read` 正常）。
4. **RPM 限速狠**（≈1 请求/分钟）：调用包指数退避重试（`callWithRetry`：1/2/4/8/16s + 抖动）。**TPD（每日 token 上限）是硬顶**，重试无效 → `DailyCapError` 快速失败提示。
5. **工具参数名必须 ASCII**（见 §8.1）。
6. **降级模型必须用 Anthropic 官方带日期的原版 ID**（`claude-sonnet-4-20250514` / `claude-haiku-4-5-20251001`），七牛云自家 `anthropic/claude-X.Y-sonnet` 命名无渠道。

## 11. 安全与鉴权

**`src/proxy.ts`（Next 16 全站网关）+ `src/lib/auth-edge.ts`（Edge 兼容核心）。**

- 单用户密码鉴权，**不需要多用户/会话表**——"一个口令进门"。
- 口令 = `APP_PASSWORD`（环境变量）。登录成功写 httpOnly cookie，值 = `sha256("fashuo-app-auth-v1:口令")`，**明文不入 cookie**。
- 网关每请求重算期望 token 与 cookie 比对；同源 fetch 自动带 cookie → 客户端组件无需逐个加 header。
- **未登录**：页面 → 302 跳 `/login`（带 `?from=` 回跳）；`/api/*` → 401 JSON。
- **放行清单**：`/login`、`/api/login`、`/api/cron`（改由 `CRON_SECRET` 头鉴权）、PWA 资源（`/icon`、`/apple-icon`、`/manifest.webmanifest`）。
- **`authDisabled()`**：`APP_PASSWORD` 未设或 = `change-me` 时全放行（本地走查零摩擦）；上线改成真实口令即自动启用。
- 跑在 Edge runtime，只用 Web Crypto（`crypto.subtle`），node 路由也能 import。
- cookie 有效期 180 天（单人自用不必频繁重登）；换 `SALT` = 踢所有登录态。

**安全边界（别动）**：`.env.local` 不可 commit（含 `LLM_API_KEY` / service_role）；ECS 安全组只开 22 + 8443；装 iOS CA 时临时开 8888、装完立即删。

## 14. 红线与设计哲学

### 三条不可破红线（2026-07 双体版）

1. **判题/答疑不放水** —— APP 答疑 Opus 不降级；PC 判题守四纪律+双复核、**销账"改对当次不算过关"**。放水 = 假掌握，账本变自欺机器。
2. **出题/判题锚定真题与教材，防循环论证** —— 真题优先直取、改造必标年份、纯生成必给教材行号锚点让云可回原文核对（原"L2/L3 题源三层"红线的转世，现役实现在 cuoti-fupan《防循环论证》节）。
3. **手机永不直接改 markdown** —— 只写 Supabase + 待办筐，**PC `register-events.mjs` 是唯一登记员/唯一去重处**。

### 贯穿全局的设计原则

- **"越用越强"是架构属性**：账本 + 事件契约 day-1 就在，模块增量上线。
- **外置一切可调参数**：调度公式/间隔档/阶段开关/红线阈值/模型 ID 全在 `config/*.json` + `.env`，**调参不改代码、不重部署**。
- **纯逻辑可单测**：调度/升降档/解析/候选筛选全抽成纯函数 + vitest 锁定（飞轮命门不能靠肉眼）。
- **宁可漏投，不要灌筐**：待办筐是云手动复核的，噪音 = 负担。
- **零编造**：周报每个数字必须来自真实使用表；答疑每个结论必须有 grep 行号锚点。
- **LLM 结构化输出别用裸 JSON**：用 `===块===` / `<<<META>>>` 分隔符（中文 ASCII 引号会破坏 JSON）。
- **成本必有日熔断**：调用前后双栅栏 + 工具循环中再查，防多轮 grep 烧穿。
- **红线必须有传感器**（2026-07 教训）：写死的红线若没有数据源和盯它的机制就会蒸发（时长、模拟分两案）——要么接数据（模拟分记录），要么砍掉（时长），不留"僵尸红线"。
- **工具摩擦决定行为**：工具富集在哪科、行为就滑向哪科（刑法讲义齐全 vs 民法零启动的实证）——资料接入本身是行为纠偏手段（[[subject-materials-pipeline]]）。
- **PC 升级绝不进 APP `src/`**：skill/脚本层的进化与 APP 部署解耦（scripts/**、*.md 是 CD paths-ignore）。
