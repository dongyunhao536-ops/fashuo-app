## 1. 一句话定位

**一个给单一用户（"云"，在职、五战法硕、目标北大 375+）私人定制的、"越用越强"的法律硕士（非法学）备考飞轮系统。**

它不是题库 App，而是把"背诵 / 答疑 / 教练"三个学习动作接到**同一本共享账本**上，让每次背错、每次答疑澄清、每次复盘都沉淀成可复利的资产（弱项档、考点掌握档、做题心得），并据此动态调度"今天该背什么"。AI（Claude）只在**评分和答疑**这两个不可放水的环节上场，且强制"先检索教材原文、带行号佐证"才能下结论。

## 2. 业务背景

### 2.1 用户画像

| 维度 | 事实 |
|---|---|
| 人数 | **单用户**（自用 PWA，不做多租户/会话表） |
| 身份 | 在职考生，备考时间碎片化（工作日晚 + 通勤 + 周末） |
| 战绩 | 五战（前几次失败） |
| 目标 | 北大法硕（非法学），总分 375+ |
| 自述病根 | **启动晚 + 从不复盘 + 重复犯老错**（教练模块的优化优先级正是冲这三点设计的） |
| 考试日期 | 2026-12-21（初试），基础结业死线 2026-09-30 |

### 2.2 考试结构（系统覆盖范围）

法硕专业课 5 科，系统内部统一规范名：**刑法 / 民法 / 法理 / 宪法 / 法制史**。

- **刑民（150 分，最重）**：理解为本——系统侧偏"答疑理解主导 + 只背规则层"。
- **法综（法理 / 宪法 / 法制史）**：背诵检测主导。

> 两条飞轮"转速不同"，所以调度器的科目权重不能一套套两科（见 `config/scheduler.json` 科目权重分阶段表）。

政治、英语两门公共课**不在系统范围内**（云自管，教练只在总时长红线上提醒，不盯政英进度）。

### 2.3 内容资产（系统的"教材真相源"）

外部档案库在 PC 的 `D:\fashuo\`（另一个 git 仓 `fashuo-archive`），含：
- **教材**：《考试分析》官方教材文本（5 科）
- **真题分析**：高频考点 + 各年真题
- **做题心得**：`_刑法做题心得.md` / `_民法做题心得.md`（答疑第一优先级证据源）
- **易混概念库**：人工整理的区分手册（易混对决数据源）
- **薄弱知识点**：`当前弱项.md`（弱项登记落地处）
- **Anki 卡组**：863 张卡 / 5 科，带颜色/底色/加粗标注的**背诵优先级体系**（P1必背高精 / P2必背 / P3选背 / P4浏览 / 口诀 / 客观点 / 星级），是 L1 默写检测的内容底座。

markdown 内容**只读**进系统（镜像到 `content_mirror` 供后端 grep），系统永不回写 markdown（红线 #3）。

## 3. 系统形态

> 设计语言来自 `系统设计/14`（飞轮）。

```
                    ┌─────────────── 共享账本（复利资产） ───────────────┐
                    │  弱项  ·  kp_state 考点掌握档  ·  心得  ·  教练记忆   │
                    └───────────────────────────────────────────────────┘
                          ▲              ▲              ▲
        ┌─────────────────┘              │              └─────────────────┐
   ┌────┴─────┐                    ┌─────┴─────┐                   ┌───────┴────┐
   │ 背诵 T0  │                    │  答疑 T0  │                   │  教练 T1   │
   │ 检测引擎 │                    │ 两段式直答 │                   │ 个性化家教 │
   └────┬─────┘                    └─────┬─────┘                   └───────┬────┘
        │            写事件              │             写事件              │
        └──────────────────►  events 待办筐（模块间显式握手总线）◄────────┘
                                          │
                                    ┌─────┴─────┐
                                    │  仪表盘   │（账本只读视图：倒计时/双核/雷达/Top5/热力）
                                    └───────────┘
```

- **3 个动作**：背诵（T0）、答疑（T0）、教练（T1）。T0 = 高频日常动作；T1 = 低频策略动作。
- **1 个共享账本**：弱项 + `kp_state` 掌握档 + 心得 + 教练记忆。这是"越用越强"的复利资产。
- **1 条总线**：`events` 表（待办筐）。任何模块产出的"增量提案"（弱项候选/心得候选/复验请求/已强化）都往这里发，是模块间唯一的**显式握手**。
- **1 个仪表**：仪表盘 + 弱项页，纯账本只读视图，UI 层不写任何状态。

## 4. 飞轮模型

"越用越强"是**架构属性**，不是功能。账本 + 事件契约从 day-1 就在，模块增量上线。四道"闸门"（gate）把动作闭环：

| 闸门 | 含义 | 触发 | 实现 | 状态 |
|---|---|---|---|---|
| **G1** | 背诵失败 → 弱项 | 同档检测**连续失败 2 次** | `detection.maybeEmitWeakEvent` → `events(弱项候选, source=检测)` | ✅ |
| **G2** | 答疑澄清 → 背诵复验 | 答疑**确实纠正了**对某考点的误解（已用、用错、被纠正） | `/api/ask` 写 `events(复验请求)` → 调度器把该考点排进次日清单**最高优先桶**；检测完成后自动 `consumed` | ✅ |
| **G1 反向（已强化）** | 弱项考点首次三档全过 | `mastered && 曾弱` | `applyStateUpdate` 投 `events(已强化)` → PC 登记把弱项行移入"已强化"段 | ✅ |
| **G3** | 教练自动聚合 | — | 教练读账本（弱项/进度/投入/错题），复盘困惑点回投待办筐 | 部分（手动 + 复盘回投） |
| **G4** | 雷达融合 | — | 五科雷达融合答疑/教练覆盖 | 二期 |

**飞轮的命门是"升降档状态机"**（`kp-transition.ts`）：升降档错 = 假掌握 / 假未过，整个账本就变成自欺机器。所以它被单独抽成纯逻辑 + 单测锁定。

## 6. 部署与运行架构

云在 2026-06-09 拍板**阿里云 ECS 自托管**（首年 ¥9/月），2026-06-11 上线。理由：最便宜、中国大陆访问最稳、七牛云 RPM 天花板不归部署平台管。代价：备案 0 天（纯 IP + 自签证书 + iPhone 信任根证书绕过）+ 自己运维。

```
INTERNET
  │ https://47.103.148.124:8443   （阿里云安全组只放行 22 + 8443；自签 TLS）
  ▼
ECS (Ubuntu 22.04, 2 核 2 G)
  ├─ nginx :8443  TLS 反代两路
  │     ├─ /rest/v1/*  → PostgREST :3001
  │     └─ /*          → Next.js   :3000
  ├─ Next.js production (pm2，进程名 fashuo)
  ├─ PostgREST (systemd，单二进制) ← Supabase API 100% 兼容
  ├─ PostgreSQL 15 (systemd，仅 localhost)
  └─ cron 运维四件套 + pg_dump 日备份 → /backups/

内存预算：PG 200-300M + PostgREST 40-80M + Node 400-700M + 系统 200-300M
        峰值 ≈ 1.0-1.4 GB / 2 GB（富裕）
```

**部署资产**全在 `deploy/`，幂等可重跑，按 `01~12` 编号顺序执行：系统底座 → Postgres/PostgREST → mint JWT → 自签证书 → nginx → app 部署 → 备份/自动同步/巡检 cron。完整 SOP 见 `BUILD_PLAN.md` 的「部署 SOP」节。

### 关键运维约束

- **国内 ISP 出站封 5432 端口**，所有 DB 操作必须走 PostgREST（443/8443）；本地禁止 psql/pg 直连。
- **2G 内存 build 易 OOM**：必须后台 `nohup` + 限堆跑（`NODE_OPTIONS="--max-old-space-size=1536"`），否则 SSH 掉线 SIGHUP 杀 build 会被误判为 OOM。
- 日常更新流程：`git pull → npm ci → npm run build（后台限堆）→ pm2 restart fashuo`。
- **逃生通道**：`pg_dump` 全量导出 → 建 Supabase 项目 restore → 改 `.env` 的 `NEXT_PUBLIC_SUPABASE_URL` 回指公网 → 部署 Vercel/Railway，代码零改动，2-3 小时切换完。

## 7. 数据模型

数据按"三类各有唯一主人"切分（`db/schema.sql` 注释明示）：

- **A 内容** = markdown@档案库（镜像只读）
- **B 运行状态** = Supabase/Postgres 永久（不回 markdown）
- **C 增量提案** = 待办筐（append-only，PC 登记后 consumed）

| 表 | 类 | 作用 | 关键字段 |
|---|---|---|---|
| `content_mirror` | A | markdown 镜像，供后端 grep | `kind`(textbook/xinde/zhenti/yixiao…)、`path`、`start_line`（报命中行号）、`content` |
| `kp_state` | B | **考点掌握档**（核心复利资产，933 考点/5 科） | `cap_level`/`cur_level`、`l1/l2/l3_status`、`difficulty`(忘性指数)、`interval_idx`、`next_due`、`mastered`、`error_count`、`priority`、`ext`(jsonb：name/page/src_line/zhenti_freq/anki_note_ids/l1_cloze/l1_must…) |
| `detection_log` | B | 每道检测题的客观结果（审计 trail） | `level`、`ai_grade`、`passed`、`seconds`、`model`、`grep_lines`、`confidence`、`starred`(盲点警报) |
| `study_log` | B | 教练 tab 的学习活动流水 | `activity`(听课/做题/背诵/复盘)、`minutes`、`accuracy`、`plan_decision`(建议采纳率) |
| `study_error` | B | 教练**自报错题独立通道**（与 kp_state 隔离，绝不影响背诵排期） | `knowledge`、`kp_id`、`status`(open/absorbed)、`absorbed_via` |
| `coach_message` | B | 教练对话历史（连续性） | `role`、`content` |
| `coach_memory` | B | 教练**长期记忆**（关于云的耐久事实） | `fact`、`category`(画像/倾向/目标/偏好/约束) |
| `weekly_report` | B | 周报缓存（同周覆盖） | `content`(LLM 复盘)、`data_snapshot`(真实聚合溯源)、`cost_usd` |
| `ask_summary` | B | 跨会话答疑记忆（结构化 + 90 天 TTL） | `confusion`、`step_stuck`、`status`(open/clarified 云在 /ask/points 收口/dismissed 移噪/superseded 被顶掉)、`ttl_until` |
| `events` | C | **待办筐总线** | `type`(弱项候选/心得候选/复验请求/已强化)、`source`、`status`(pending→confirmed/dismissed→consumed)、`dedupBy` |
| `api_usage` | B | 每次 LLM 调用的 token + 估算成本（成本栅栏数据源） | `route`、`model`、四类 token、`est_cost_usd` |

### `events` 状态机（飞轮总线核心）

```
pending ──┬── confirmed（云在手机端"收下"）──► consumed（PC 登记进 markdown）
          └── dismissed（云"忽略"）
例外：复验请求不需云拍板，检测完成后在 APP 侧直接 pending → consumed
```

> **红线 #3 唯一去重处**：登记进 `当前弱项.md` 时按 `(subject, knowledge)` 去重、错误频率跨批次 +1，**只在 PC 登记脚本一处**。手机端只改 Supabase 状态，从不碰 markdown。

## 8. 核心子系统详解

### 8.1 内容镜像与 grep 工具链

**`src/lib/search-tools.ts`** 是整个系统的"证据地基"。答疑/评分前必须先检索教材/心得/真题，回答带 grep 命中**真实行号**；无 grep 痕迹则信心度 -20% + 标★。

三个工具（Claude tool-use）：
- `search_textbook` — 检索《考试分析》教材原文
- `search_xinde` — 检索刑/民做题心得（**答疑第一优先级**）
- `search_zhenti` — 按年份(+题号)检索真题

实现要点：
- grep = **逐行子串匹配**。命中行连同 ±2 行上下文合并成块，`base+i` 行号用 `content_mirror.start_line` 校准回源文件真实行号。
- **per-request `MirrorCache`**：一次答疑 12 条检索，每个 `kind` 只从 Supabase 拉一次（否则每个关键词全量下载五本教材，是延迟大头）。
- ⚠️ **七牛云/Bedrock 约束**：工具参数名（property key）必须 ASCII（`^[a-zA-Z0-9_.-]{1,64}$`），中文 key → 400。故 key 用 `keyword`/`year`/`question_no`，描述照样中文。
- ⚠️ **关键词硬规则**（贯穿出题/评分/答疑规划器）：关键词必须是**单个连续短词、不含空格**（2-6 字法律术语最佳）。"债务转移 担保" 这种带空格的词几乎零命中，必须拆成两条。这是 L2/L3 真实验收（2026-06-09）暴露的坑——用完整考点名当 keyword → grep 全空 → 评分无锚退化违反红线。

### 8.2 背诵检测引擎（L1/L2/L3）

**`src/lib/detection.ts`** —— 统一三档接口 `generateQuestion()` + `gradeAnswer()`。

| 档 | 形态 | 出题 | 评分 | 成本 |
|---|---|---|---|---|
| **L1** | 记忆默写 / 关键词填空 | 读 Anki 卡的 P1必背高精 + 口诀，挖空（Haiku 现造、缓存到 `ext.l1_cloze`） | **规则秒判**（关键词命中率），勉强/边界叫一次 **Haiku 语义复判**（治"换句话说被逐字门槛误杀"） | 0 ~ 极低 |
| **L2** | 简答（4-6 要点） | Opus 两段式：规划检索词 → grep 教材 → 出题 | **Opus 不降级**，grep 教材锚定 | ¥0.3-0.5/题 |
| **L3** | 迷你案例（定性 + 法律关系 + 后果） | 同 L2 | 同 L2 | ¥0.3-0.5/题 |

**L1 内容底座 = Anki 标注体系**：`scripts/anki-extract.py` 保留 HTML 颜色/底色/加粗，还原"哪些背、背到何种程度"——题型（主观/客观）、P1必背高精/P2必背/P3选背/P4浏览、口诀、客观点、星级。L1 关键词集 = 本段 **P1必背高精 + 口诀**（不混 P2，P2 是要点级展开属 L2 理解检测）。

**L2/L3 题源三层**（取可得最高层，防"出题=评分循环论证"）：
1. **真题直取**（有关联真题且主观题 → 原题当检测题，零循环）
2. **真题改造**（客观题 → Opus 改造 + 强制标真题年份 + 进抽查）
3. **教材生成**（冷点无真题 → Opus 基于考点教材行号锚生成，标 `source=ai` 进抽查面板）

**防循环三保险**：①生成 ≠ 评分（两次独立调用）②评分锚定教材 grep 客观比对，不对出题者隐藏答案打分 ③来源全程标注 `detection_log`，抽查面板挑 AI 生成给云核对。

**评分输出**：`grade`(干净通过/勉强/未过) + `passed` + `hits`/`missing`(可解释) + `confidence`(0-100) + `starred`(盲点警报，缺锚必标) + `grepLines`。L2/L3 用严格 JSON 块输出，`parseGradeJson` 容错抽取。

**grade 后必做三件事**（红线③）：写 `detection_log` → `applyStateUpdate`（升降档写 `kp_state`）→ G1 检查（连续失败投弱项候选）+ G2 兑现（消费复验请求）+ 已强化检查。

### 8.3 升降档状态机 + 调度器

#### 升降档状态机 `src/lib/kp-transition.ts`（纯逻辑、单测锁定）

`difficulty` 是"忘性指数"（错/勉强累加、稳过递减），决定可达的最高间隔档（**难度门控 `rungCap`**：D≤6→30 天 / D7→15 天 / D8→7 天 / D≥9→3 天），防"半生不熟的卡漂到 30 天间隔"。

| 评分 | 难度 | 间隔 | 档级 | status |
|---|---|---|---|---|
| **干净通过** | −1 | 升一档（≤门控）；**重学档**(刚挂过)只"确认"不放长 | 当前 < 封顶则升档 | passed |
| **勉强** | +1 | 按通过推进一档（受更紧门控）；重学档不放长 | 不动，不计 mastered | untested |
| **未过（遗忘）** | +2 | 真题**高频**砸回 1 天档；中/低频退两档 | 不动，error_count+1 | failed |

间隔档 `[1, 3, 7, 15, 30]` 天。`mastered` = 按 `cap_level` 对应档全 passed；失手会复算掉 mastered → 回炉。**考前收敛**：距初试 ≤35 天起，有效间隔压到 ≤ 距考天数×0.5，确保高频/已掌握考点考前还能滚到（否则 30 天间隔排到考后）。

#### 调度器 `src/lib/scheduler.ts`（纯逻辑、零 LLM）

**今日清单 = 三段式 bucket**，按优先级裁剪：

1. **复验（G2）** — 最高优先，全部纳入
2. **到期复习** — 复习过且 `isDue`（距上次 ≥ 有效间隔，到期当天即纳入），按 P 降序
3. **新考点** — **科目轮转**引入（5 科按 `刑→民→法理→宪→法史` round-robin 交错，各科内按章节顺序），让法综 day-1 即进清单，不被刑民挤到数月后

**优先级公式**（外置 `config/scheduler.json`，调参不改代码）：
```
价值 V = w1·真题频率(3.0) + w2·弱项加权(2.0) + w3·科目权重(1.0)
紧迫度 U = max(0, 距上次复习天数 / 有效间隔 − 1)
排序分 P = V × (1 + U)        ← 加权和×门控，防纯乘法归零
```

**阶段开关**（全局模式，按日期切换）：知识体系铺开（当前）→ 高频+弱项优先（2026-09-01）→ 纯弱项+主观题模板（2026-12-07）。不同阶段科目权重不同。

所有日期计算走**北京日历日**（`bjDateStr`），消除"按 UTC 时刻算"导致的凌晨 0-8 点到期抖动。

### 8.4 答疑（两段式 + 流式 + 沉淀）

**`POST /api/ask`** + `src/lib/ask-prompt.ts` + `runPlanThenAnswer`（`anthropic.ts`）。

#### 为什么是"两段式"

原始多轮 agentic loop 在七牛云 RPM（≈1 请求/分钟）下，一道案例题 4 轮工具循环要 **6.5 分钟**、¥1.40。改"两段式"后降到 ~2.55 分钟、¥0.74（−61% 时间、−47% 钱），且绕过七牛云"带 tools 时缓存失效"的坑：

```
① 规划器（小调用，Sonnet 4）：读题 → 判科目 + 列检索词 JSON，不作答
        ↓
② 本地一次性跑完所有 grep（共享 MirrorCache，封顶 12 条）
        ↓
③ 作答（大调用，Opus 4.8 不降级）：把全部 grep 结果喂回 → 按 v2.3 证据链作答 + META
封顶 2 次 LLM 调用（规划零产出重试一次，封顶 3 次）
```

健壮性双保险：规划模型渠道失效 → 退回作答模型规划；规划零产出 → 用作答模型重试。

#### v2.3 证据链作答规范（`buildAskSystemStable`）

核心信任机制：**绝不允许"我知道答案直接答"，凡结论必须可追溯到教材原文/真题题号/心得规则**。

- **答疑优先级**（禁止越级）：① 心得 → ② 真题 → ③ 教材《考试分析》→ ④ 法条 → ⑤ 司法解释
- **六步预检清单**（第一段固定输出，填真实检索结果）：问题归类 / 心得检索 / 易混检索 / 教材锚定 / 真题锚定 / 法律更新
- **按题型作答结构**：案例→四段式（结论/法理依据/涵摄/后果）；概念辨析→三段式；选项排除→逐项过；简答→关键词踩点版
- **必备机制**：触发词升级法律更新必查、多主体×范围矩阵、信心度 0-100%（<70% 提醒核对、<50% 标★⚠️）
- **末尾固定附「证据卡」** + **机器可读 META 块**

#### 沉淀（飞轮接线）

答案末尾的 `<<<ASK_META{...}>>>` 块被 `splitMeta` 抽出并从展示文本剥离，`sinkProposals` 据此沉淀：
- `weak_candidates`（从严，至多 2）→ `events(弱项候选)`
- `xinde_candidates`（从严，至多 1）→ `events(心得候选)`
- `review_kp_candidates`（G2，需有 kp_id 锚点）→ `events(复验请求)`
- `confusion` → `ask_summary`（90 天 TTL，下次同 subject 答疑检索式注入跨会话记忆）

**防灌筐二道闸**：`screenCandidates`（去太短/批内重复/封顶）+ `recentlyHandled`（30 天内已 confirmed/consumed/dismissed 的同候选不再投）。设计原则：**宁可漏投，不要灌筐**——待办筐是云手动复核的，噪音 = 负担。

#### 流式心跳

案例题 Opus 可达 2-3 分钟，手机蜂窝网会掐断静默长请求，故 `streamJson` 持续吐字节保活（`stream-response.ts`）。客户端断开（"停止思考"）→ `req.signal` 透传到 SDK，真正中止上游 Opus 调用、省下那次钱。

### 8.5 教练 T1（个性化家教）

**`src/lib/coach.ts`** + `POST /api/coach` + `config/coach.json`。2026-06-21 从"填四段表"重做为**个性化对话式法硕家教**。

- **人设**：云的私人法硕家教，掌握他的全部学习数据 + 长期记忆，建议必须个性化、扣真实进度和老毛病说，该泼冷水就直说。
- **方法论地基**（`METHODOLOGY` 常量）：浓缩自 10+ 篇高分/在职/多战经验帖（刑民理解为本、前期理解后期全面背、复盘是高分隐性共性、真题 2-3 遍、模考不可缺…）。针对云的最大风险定优先级：**复盘 > 错题闭环 > 模考节奏 > 进度铺开**。
- **账本每轮重查**（`loadLedger`）：阶段/死线/Top5 弱项/近 N 周投入/已学章节/未吸收自报错题 + 答疑暴露弱项 + 近 8 轮对话 + 长期记忆。

- **周日固定动作**：本周积压复盘——主动把未吸收错题逐条用理解层考一遍、收口销账（专治"错题不闭环"）。

> 教训：LLM 中文里偶用 ASCII 引号破坏裸 JSON → 改用 `===块===` / `<<<META>>>` 分隔符块，段内随便用引号都不坏。

### 8.7 待办筐（events 总线）

### 七牛云（Bedrock 转售）实测约束 —— 全部踩坑后定论

> 这些是反复真实付费探针得出的硬约束，改不动，写进代码注释和模型层备注，避免重复踩坑。

1. **`effort=high` 旋钮无真实效果**：`output_config.effort` / 顶层 `effort` 在七牛云从旧版 400 变成"200 但静默忽略"（无 thinking 块、token/延迟同 baseline）——比 400 更坑（造"已调高"假象），**一律不传**。答疑已在真实最强档，无更高旋钮可调。
2. **thinking 旋钮**：原生 `/v1/messages` 路径下 `thinking.effort` 全是死的；Opus 4.8（Bedrock）只能用 `adaptive`，且思考内容被七牛云抹空（redacted）、案例题 ROI 负（延迟/成本翻倍、质量改善微弱）→ **答疑作答默认不开**。
3. **带 tools 时 prompt caching 读取失效**：`cache_write($6.25/M) > input($5/M)`，缓存比不缓存还贵 ~8% = 净亏损。故答疑/评分这类**必带 grep 工具**的调用**一律不设缓存断点**，走纯 input 最省。两段式答疑两段都**不带 tools** → 重新启用缓存（无 tools 的 system 缓存烟测验证过 `cache_read` 正常）。
4. **RPM 限速狠**（≈1 请求/分钟）：调用包指数退避重试（`callWithRetry`：1/2/4/8/16s + 抖动）。**TPD（每日 token 上限）是硬顶**，重试无效 → `DailyCapError` 快速失败提示。
5. **工具参数名必须 ASCII**（见 §8.1）。
6. **降级模型必须用 Anthropic 官方带日期的原版 ID**（`claude-sonnet-4-20250514` / `claude-haiku-4-5-20251001`），七牛云自家 `anthropic/claude-X.Y-sonnet` 命名无渠道。

### 三种调用封装（`anthropic.ts`）

- `runWithSearchTools` — 手动 agentic loop（注入 grep 工具链，收集命中行号）。保留给背诵复用。
- `runPlanThenAnswer` — 两段式（答疑/L2 L3 评分/L2 L3 出题主力）。
- `runSingleTurn` — 单次无工具调用（教练 / L1 语义兜底 / cloze 现造 / 易混对决）。

## 11. 安全与鉴权

**`src/proxy.ts`（Next 16 全站网关）+ `src/lib/auth-edge.ts`（Edge 兼容核心）。**

- 单用户密码鉴权，**不需要多用户/会话表**——"一个口令进门"。
- 口令 = `APP_PASSWORD`（环境变量）。登录成功写 httpOnly cookie，值 = `sha256("fashuo-app-auth-v1:口令")`，**明文不入 cookie**。
- 网关每请求重算期望 token 与 cookie 比对；同源 fetch 自动带 cookie → 客户端组件无需逐个加 header。
- **未登录**：页面 → 302 跳 `/login`（带 `?from=` 回跳）；`/api/*` → 401 JSON。
- **放行清单**：`/login`、`/api/login`、`/api/cron`（改由 `CRON_SECRET` 头鉴权）、PWA 资源（`/icon`、`/apple-icon`、`/manifest.webmanifest`）。
- **`authDisabled()`**：`APP_PASSWORD` 未设或 = `change-me` 时全放行（本地走查零摩擦）；上线改成真实口令即自动启用。
- 跑在 Edge runtime，只用 Web Crypto（`crypto.subtle`），node 路由也能 import。
- cookie 有效期 180 天（单人自用不必频繁重登）；换 `SALT` = 踢所有登录态。

**安全边界（别动）**：`.env.local` 不可 commit（含 `LLM_API_KEY` / service_role）；ECS 安全组只开 22 + 8443；装 iOS CA 时临时开 8888、装完立即删。

## 14. 红线与设计哲学

### 三条不可破红线

1. **评分/答疑 Opus 不降级** —— 放水 = 假掌握，飞轮变自欺机器。
2. **L2/L3 题源真题锚定**，AI 现生成仅补充 + 标注 + 抽查 —— 防"出题 = 评分循环论证"。
3. **手机永不直接改 markdown** —— 只写 Supabase + 待办筐，**PC `register-events.mjs` 是唯一登记员/唯一去重处**。

### 贯穿全局的设计原则

- **"越用越强"是架构属性**：账本 + 事件契约 day-1 就在，模块增量上线。
- **外置一切可调参数**：调度公式/间隔档/阶段开关/红线阈值/模型 ID 全在 `config/*.json` + `.env`，**调参不改代码、不重部署**。
- **纯逻辑可单测**：调度/升降档/解析/候选筛选全抽成纯函数 + vitest 锁定（飞轮命门不能靠肉眼）。
- **宁可漏投，不要灌筐**：待办筐是云手动复核的，噪音 = 负担。
- **零编造**：周报每个数字必须来自真实使用表；答疑每个结论必须有 grep 行号锚点。
- **LLM 结构化输出别用裸 JSON**：用 `===块===` / `<<<META>>>` 分隔符（中文 ASCII 引号会破坏 JSON）。
- **成本必有日熔断**：调用前后双栅栏 + 工具循环中再查，防多轮 grep 烧穿。
